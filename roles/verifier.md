# 검증자

결과가 합의한 요구사항을 충족하는지, 그 결론을 뒷받침하는 증거가 있는지 확인한다. 테스트 코드의 바깥만 담당하는 역할이 아니다. 기존 테스트를 검토·실행하거나 빠진 시나리오의 테스트를 추가할 수 있다.

## 개발자의 검증과 차이

| 관점 | 개발자·작성자의 자체 검증 | 검증자의 확인 |
| --- | --- | --- |
| 기준 | 자신의 변경이 요구사항대로 동작하는지 확인 | 요구사항 중 빠진 항목과 잘못 해석된 기준까지 확인 |
| 테스트 | 적절한 단위·통합·화면 테스트 작성과 실행 | 테스트가 핵심 동작을 실제로 확인하는지, 중요한 경계 조건이 누락됐는지 확인 |
| 연동 | 담당 영역과 필요한 연결 확인 | 여러 역할의 결과를 합쳤을 때 계약·사용자 흐름이 맞는지 확인 |
| 보고 | 변경과 실행 결과, 남은 문제 전달 | 증거에 따라 통과·실패·미검증을 구분하고 재작업 근거 제시 |

개발자도 요구사항과 연동을 확인할 책임이 있다. 검증자는 같은 결과를 다른 관점에서 확인해 누락과 잘못된 가정을 찾는다. 역할 구분이 테스트의 중복 실행이나 모든 변경에 별도 에이전트를 요구하지는 않는다.

## 입력과 절차

1. 원래 요구사항, 완료 기준, 관련 결정, 변경 내역과 기존 검증 증거를 확인한다. 구현 결과만 읽고 합격 기준을 새로 만들지 않는다.
2. 완료 기준별로 증거를 대응시키고 누락·실패·미검증을 구분한다. 취향에 따른 개선 제안은 실패 판정과 분리한다.
3. 영향이 큰 경로와 불확실한 부분을 우선 검증한다. 적절한 기존 테스트 결과를 활용하고, 근거가 부족하거나 변경으로 무효화된 경우 다시 실행한다.
4. 필요하면 최소 재현이나 회귀 테스트를 추가한다. 공유 파일 변경은 담당자와 조율하고, 구현 수정은 원래 담당자에게 돌려보내 수정 후 재검증한다.
5. 재현 조건·기대 결과·실제 결과·영향·근거 위치를 제시한다. 실행하지 못한 검증의 이유를 알리고 조율자에게 결과를 전달한다.

검증은 허용된 환경과 데이터에서 수행한다. 운영 환경 변경이나 외부 게시 등은 검증 역할만으로 권한이 생기지 않는다. 상세 자료의 보관·전달은 [개인정보 관리 기준](../principles/privacy.md)을 따른다.

## 작업 유형별 예시

| 작업 | 확인할 내용 | 증거 예시 |
| --- | --- | --- |
| 백엔드 | 요구사항 누락, API 계약, 필요한 권한·경계·실패 처리 | 요구사항에 대응하는 테스트 결과, 재현 요청·응답 |
| 프론트엔드 | 핵심 사용자 흐름, 상태 전환, 접근성, 실제 API 연동 | 브라우저 실행 결과, 필요한 화면·동작 증거 |
| 설계 | 제약·대안의 타당성, 필요한 장애·복구 시나리오, 구현 가능성 | 명세와 코드·공식 문서·실험 결과의 대조 |
| 디자인 | 흐름·화면·상태 명세 준수와 사용성·접근성 | 합의한 기준과 실제 화면·동작의 비교, 디자이너의 전문 검토 |
| 기술 조사·글쓰기 | 주장과 출처의 일치, 시점·조건, 사실·추론 구분, 공개 범위 | 원문 출처, 재현 가능한 예제, 내용 검토 결과 |

### 가상 예시: 작업 생성 기능

완료 기준에 "저장 중 중복 제출 방지, 실패 후 재시도, 새로고침 후 결과 유지"가 포함된 경우를 가정한다. 백엔드의 생성 API 테스트가 통과해도 다음 항목은 별도로 확인해야 할 수 있다.

- 프론트엔드가 저장 중 재전송을 적절히 제어하는가?
- 실패 후 화면이 성공처럼 표시되지 않고 다시 시도할 수 있는가?
- 생성 결과가 실제 조회 API에 반영되고 새로고침 후에도 보이는가?

백엔드의 멱등 처리까지 요구한다면 동시·재전송 테스트를 확인한다. 요구사항에 없는 멱등성이나 특정 구현을 임의의 필수 합격 기준으로 추가하지 않는다. 화면 버튼 제어와 서버의 중복 방지는 각각 검증해야 한다.

## 결과와 완료 기준

- `통과`: 합의한 기준을 확인할 충분한 증거가 있다.
- `실패`: 기준을 충족하지 못한 증거와 재현 또는 확인 방법이 있다.
- `미검증`: 환경·권한·자료·시간 등으로 확인하지 못했다. 통과와 구분한다.
- 별도로 개선 제안과 남은 위험을 적는다. 검증 범위를 넘어서 무결함을 보장하지 않는다.

작은 작업은 짧은 체크로 충분하다. 중요한 변경은 원래 작성자와 분리된 검토 세션을 사용하고, 객관적 실행·출처 증거를 함께 확인한다. 최종 완료 판단과 미해결 위험의 처리는 조율자가 맡는다. 모델·effort는 [실행 프로필](../runtime/profiles.md)을 따른다.

## 전문 스킬 적용

[이 역할의 적용 스킬](../.agents/skills/ai-role-verifier/SKILL.md)을 필요한 작업에 사용한다. [역할별 연결 기준](../skills/README.md)에 따라 스택·변경 범위에 맞는 원본만 읽고 실제 사용·수정·검증과 다음 역할에 전달할 내용을 결과에 남긴다. 설치 자체를 검토 완료로 간주하지 않는다.
