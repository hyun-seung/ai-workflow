# 역할 스킬의 운영 준비 완료 기준

역할별 스킬의 초기 구축과 이후 정기 관리를 구분한다. 이 문서는 스킬 연결·관리·화면 검증의 마감 기준이며, ai-workflow 전체 하네스의 [다른 개발 과제](../runtime/harness-roadmap.md)까지 완료했다는 뜻은 아니다. 설치별 진행 상태와 실제 증거는 `local/role-skills/`의 비공개 기록에 둔다.

## 초기 구축의 세 가지 마감 작업

| 작업 | 확인할 결과 | 완료 판단 |
| --- | --- | --- |
| 1. 출처·운영 상태 정리 | 현재 설치 무결성, 역할별 선택, 기존 시험과 남은 미확인, 필요한 출처 재확인 | 각 항목의 유지·보류 이유와 미검증 범위가 명시됨. 조회 실패를 활동 없음으로 바꾸지 않음 |
| 2. 변경·복구 통합 확인 | 격리 라이브러리에서 추가·업데이트·증거 부족 보류·오류·복구·비활성·보관·복원과 조회 화면의 일치 | 현재 관리 도구와 API/화면으로 실제 상태·버전·판정이 일치함. 기존 설치와 사용자 자료가 보존됨 |
| 3. 운영 인계와 공개 마감 | 역할별 사용법, 새 설치의 연결·예약 준비, 실패 시 확인·복구, 공개 변경의 문서·개인정보 검사 | 다른 작업에서 재사용할 수 있는 절차와 제한이 정리되고 승인된 변경의 커밋·푸시가 확인됨 |

기존의 유효한 시험은 재사용하고 새로 확인한 항목만 추가한다. 실제 설치를 일부러 고장 내거나 영구 삭제해서 시험하지 않는다. 통합 시험의 가상 스킬·DB와 실제 업무 기록을 구분한다. 시험용 서버·탭은 작업이 끝나면 정리한다.

출처 재확인만 한 후속 점검은 전체 신규·인기 탐색을 수행한 정기 검토로 표현하지 않는다. 전체 검토와 후속 검토의 범위·시각·남은 제한을 각각 보존한다. 요약이 대시보드의 최신 검토로 표시되면 그 범위가 요약 문구에도 드러나야 한다.

## 초기 마감 이후

세 작업의 완료는 역할별 선택·실제 사용 기록·자동 관리와 복구를 운영할 준비가 됐다는 뜻이다. 모든 외부 스킬을 `active`로 바꾸거나 모든 플랫폼·SDK를 검증할 필요는 없다. 시험 근거가 제한된 버전은 `pilot`, 관련 방법만 사용하는 원본은 `reference-only`를 유지할 수 있다.

신규·인기·업데이트 후보와 기존 스킬의 유지·대체·은퇴 판단은 [주간 관리](../runtime/skill-maintenance.md)로 이어간다. 실제 native·운영 검증, 새 언어·DB별 스킬은 해당 프로젝트의 스택과 요구가 정해졌을 때 별도 작업으로 진행한다. 새 후보가 생겼다는 이유로 초기 구축을 계속 미완료 상태로 두지 않는다.

다른 설치에서는 [설치·역할 선택](README.md), [프로젝트 지침 연결](../projects/README.md), [선택한 실행 환경](../runtime/environments/README.md), [화면의 사용·관리 기록](../runtime/trace-skills.md)을 연결하고 실제 적용 여부를 확인한다. 이 저장소를 복제하는 것만으로 외부 원본·로컬 활성 목록·예약이 자동 배포되지는 않는다.

실무 인계는 [운영·인계 가이드](operations.md)에서 작업별 명령·새 설치·화면 확인·실패 복구 순서로 시작한다.
