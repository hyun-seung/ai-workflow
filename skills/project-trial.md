# 실제 프로젝트에서 역할 스킬 시험하기

가상 시험 다음에는 대상 프로젝트의 좁은 사용자 흐름 하나로 확인한다. 제품 전체 감사나 외부 스킬의 품질 인증으로 확대하지 않는다. 이 절차는 [프로젝트 연결](../projects/README.md)과 대상 저장소의 지침을 대신하지 않는다.

## 시작 조건

- 조율자는 원래 요구사항, 대상 커밋, 역할별 완료 조건과 이번 변경 범위를 정한다. 스킬 관리 작업이라는 이유로 무관한 제품 로드맵을 구현하지 않는다.
- 작업공간·기존 변경·프로젝트 지침을 먼저 확인한다. 등록된 대상이 없으면 개인 폴더 전체를 탐색하지 않고, 승인된 저장소의 고정 커밋을 격리해 재현할 수 있다. 복제본과 실제 개발 작업공간을 구분한다.
- 대상 프로젝트의 cwd를 유지하고 공통 저장소의 절대 경로로 역할 문서와 스킬 선택기를 연결한다. 현재 제공된 도구와 프로젝트의 기본 브라우저를 확인한다. 연결 실패로 전환하면 오류와 실제 사용 환경을 기록한다.
- API 모드의 이름만 믿지 않고 설정 우선순위와 클라이언트 분기를 확인한다. mock 흐름에는 가상 데이터만 쓰고 운영 계정·실제 API를 연결하지 않는다. 의존성·전역 설정·설치 스크립트의 실행 범위도 구분한다.

## 역할별 최소 결과

| 역할 | 이번 시험의 책임 | 전달할 근거 |
| --- | --- | --- |
| 디자이너 | 기존 선택 원본·상태·조작 위계를 확인. 의미 있는 새 구조가 아니면 새 시안을 강제하지 않음 | 정확한 원본, 유지 요소와 시안/실제 화면의 차이 |
| 프론트엔드 | 관련 규칙만 읽고 실제 입력·상호작용으로 재현. 같은 범위의 결함 수정 | 변경 파일, 수정 전 재현, 같은 조건의 수정 후 결과 |
| 검증자 | 원래 AC에서 정상·경계·복구와 증거의 범위를 확인 | 통과/실패/미검증, 재현 방법과 다음 담당자 |

작은 작업은 한 에이전트가 역할 관점을 나누어 수행할 수 있다. 이 경우 독립 검토라고 기록하지 않는다. 검증자가 수정을 맡지 않았다면 개발자에게 재현 근거를 돌려준다.

## 실제로 확인할 것

1. 코드의 입력 제한·계약을 찾아 긴 값의 길이를 정한다. 최대 길이, 혼합 문자와 긴 본문을 실제 데이터 경계나 입력으로 넣는다. 문서의 예시 길이를 제품 제한으로 추정하지 않는다.
2. 빈 상태에서 작성·저장·목록 또는 상세 반영까지 한 흐름을 확인한다. 오류가 발생하면 첫 오류 입력으로 초점이 이동하고, 수정 설명이 보이며, 원문이 유지되는지 본다. 관련 입력 수정과 무관한 입력 수정도 구분한다.
3. Web에서는 키보드 조작·초점·오류 상태와 설명 연결, 좁은 폭의 줄바꿈·가로 넘침, 표시된 조작 영역을 확인한다. 화면 크기만 바꾼 결과를 실제 터치·실기기 검증으로 쓰지 않는다. 확대·native·서버 실패·재시도·중복 제출 중 실제로 시험하지 않은 항목은 미검증이다.
4. 도구가 명령을 수락한 것과 앱의 결과를 구분한다. 클릭·키 입력 후 실제 값·화면·저장 결과를 확인한다. 다른 조작 방식으로 복구했으면 원래 방식의 성공을 주장하지 않는다.
5. 수정 후 동일한 데이터·크기·상태로 새 캡처와 측정값을 수집한다. 대상의 필수 검사도 실행한다. DOM 표식이 없어 0행이거나 누락된 측정은 통과가 아니다. 필요하면 실제 요소에 읽기 전용 측정 표식을 보완하고 다시 수집한다. 검사 허용치를 늘리거나 가짜 행을 넣지 않는다.
6. 캡처를 직접 열어 읽기·잘림·광학 정렬을 확인한다. 기하 검사의 적용 대상과 표식 없는 요소를 밝힌다. 자동 검사 통과를 전체 접근성·성능·디자인 인증으로 확대하지 않는다.

## 보관과 판정

실행 기록은 [짧은 확인 양식](../templates/role-skill-review.md)을 따른다. 대상 버전·수정 패치, 스킬의 출처/고정 버전·실제 읽은 부분, 환경·데이터·검사 결과·캡처를 연결한다. 프로젝트의 필수 기준이 실패하면 완료로 표시하지 않는다.

개인 경로·실행 ID·프로젝트별 보고서와 화면은 기본적으로 `local/role-skills/trials/`에 보관한다. 실제 대상이 비공개이면 원본과 패치의 공개 범위도 따른다. 공개 저장소에는 재사용 가능한 절차와 가상 예시만 남긴다. 로컬 서버·탭은 작업에서 만든 것만 정리한다.

제품 패치의 공개·커밋·푸시 권한은 스킬 라이브러리의 관리 권한과 별개로 확인한다. 격리 복제본의 수정은 사용자 프로젝트에 반영된 변경이 아니다. 필요하면 대상 커밋과 적용 가능한 패치를 인계한다.

한 흐름이 통과해도 다른 플랫폼·역할·버전은 미검증으로 남는다. 스킬의 `pilot`에서 `active` 승격은 [유지관리](../runtime/skill-maintenance.md)의 버전·역할·태그에 결합된 근거로 별도 판단한다. 단일 에이전트의 시험 결과를 스킬 도입 전후의 인과적 효과 측정으로 쓰지 않는다.
