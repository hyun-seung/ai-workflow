# 같은 AI의 후속·취소·목표 변경 점검

2026-11-15, 현재 저장소의 `scripts/routing_flow.py`를 **매번 새 CLI 프로세스로 실행**해 가상 입력 24건을 확인했다. 테스트에서 내부 함수를 직접 호출하거나 native 응답 mock을 사용하지 않고 실제 상태 파일·역할 문서·종료 코드를 대조했다. 모두 기대한 결과와 일치했으며 이 범위에서 코드 수정이 필요한 문제는 발견하지 못했다.

작성자가 만든 입력에 대한 로컬 운영 점검이다. 실제 사용자 대화의 의미 해석 정확도, Orca 입력 연결, 실제 worker 중지, 학습 효과·토큰 절감을 검증한 결과는 아니다. 추가 모델·worker·플러그인·네트워크 호출은 하지 않았다.

## 확인한 흐름

| 흐름 | 확인 결과 |
| --- | --- |
| 단순 설명 | `direct`, 새 상태 파일 없음 |
| 같은 AI의 tutor 제안·수용 | 첫 수용에 선택 역할 지침을 반환하고 worker 시작은 요구하지 않음 |
| 대기 제안·수용의 재전달 | 제안 반복을 억제하고 중복 수용에는 지침 본문을 다시 반환하지 않음 |
| 프로세스 재시작 뒤 같은 작업의 후속 | 저장한 선택을 재사용하고 지침 본문 재반환 없이 상태 파일 내용·수정 시각 유지 |
| 명시적인 문맥 복구 | 수용한 역할만 다시 준비하고 선택 상태는 수정하지 않음 |
| 역할 선택 취소 | 현재 선택을 해제하고 지침 복구·후속 재사용을 차단 |
| 거절·취소한 같은 대상 | 재추천을 억제. 명시적인 재검토에만 새 제안을 만들며 이전 동의는 거절 |
| 목표·제어 변경 | 새 revision에서 이전 선택 만료. revision 없는 제어 변경은 오류이며 기존 상태 보존 |
| 최신 직접 처리 지시 | 역할 선택을 만료시킨 뒤 후속에서도 `direct` 유지 |
| 다른 요청 | 같은 상태 파일 재사용은 오류, 새 상태 경로의 직접 처리는 상태 파일 없이 완료 |
| 현재 대화 프로필 변경 후보 | `manual`, `executable: false`. 실행 가능한 선택이나 worker로 바꾸지 않음 |

파일 권한 0600·상태 폴더 0700과 요청 이유·역할 본문을 선택 상태에 저장하지 않는 것도 확인했다. 중복 수용·후속 재사용·문맥 복구에서는 파일 해시와 수정 시각을 전후 비교했다. 모든 성공 출력은 `runtime_applied: false`를 유지했다. 지침 반환을 실제 주입·준수의 증거로 바꾸지 않는다.

개별 입력·출력과 상태 경로는 저장소 밖의 소유자 전용 임시 조사 기록에 보관했다. 공개 문서에는 실제 프로젝트 경로·세션 식별자·역할 응답 원문을 포함하지 않는다. 임시 기록은 장기 보관이나 백업을 보장하지 않는다.

## 현재 AI가 적용할 운영 기준

1. 같은 작업의 후속인지 먼저 판단한다. 단순히 직전 선택이 있다는 이유로 재사용하지 않는다.
2. 목표·제어·현재 설정이 바뀌면 revision을 올리고, 다른 요청이면 새 상태 파일을 쓴다. 사용자가 ID나 파일을 관리하게 하지 않는다.
3. 취소 이후에는 이전 역할을 새 답변에 계속 적용하지 않는다. 이미 읽은 문맥을 삭제했다고 설명하지 않는다.
4. 역할 수용을 모델 변경·위임 동의로 확대하지 않는다. 현재 대화의 프로필 변경은 공식 연결 전까지 수동 설정으로 구분한다.
5. 이 점검을 매 입력마다 실행하지 않는다. 일반 요청은 짧은 진입 지침을 사용하고 필요한 선택 사건만 기록한다.

상세 계약은 [공통 진입 흐름](routing-flow.md), 일상적인 사용 예시는 [짧은 운영 안내](routing-quickstart.md)를 따른다. 이번 결과 때문에 일반 입력용 지침을 늘리거나 새 테스트 도구를 추가하지 않았다.

## 실제 운영 검증으로 남은 부분

- **실제 worker 취소·복구:** 새 요청의 명시한 모델·effort·동시/누적 한도와 실제 권한이 필요하다. 정확한 dispatch의 중지 요청·종료 관측·슬롯 해제를 따로 확인한다. 과거 1회 허용을 재사용하지 않는다.
- **앱 자동 연결:** 같은 런타임의 공식 입력/상태 전달·신뢰된 hook 근거가 필요하다. CLI 성공을 앱 연결 성공으로 표시하지 않는다.
- **비용·품질 비교:** [공식 원본 연결](native-source-access.md)을 확보한 뒤 동일 완료 기준으로 수행한다. 로컬 상태 처리의 성공이나 분류 호출 없음은 전체 요청 비용 절감의 증거가 아니다.
- **사용성:** 사용자가 실제로 느끼는 설명 난이도·분량·추천 빈도는 사용 피드백으로 확인한다. 위 24건으로 만족도나 오분류율을 계산하지 않는다.

남은 통합 순서는 [개발 현황](../learning/development.md#남은-작업)에 유지한다. 현재 차단 조건이 바뀌기 전에는 같은 native 시험을 반복하거나 가정한 API용 어댑터를 추가하지 않는다.
