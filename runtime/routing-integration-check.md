# 입력·역할·위임의 제한 실제 검증

2026-11-14, Orca 1.4.257·Codex 0.167.0에서 실시했다. 사용자가 선택한 `gpt-6.1-sol / medium`으로 현재 worktree의 읽기 전용 worker 한 건만 실행했다. 동시 1·누적 1·자동 재시도 없음으로 제한했고 새 worktree·전역 설정·권한 변경은 하지 않았다. 실제 식별자·경로·snapshot·선택 기록·audit는 비공개 임시 기록에 보관한다.

결과는 **일부 연결 확인**이다. 역할 전달과 명시 위임의 시작·재조회·종료, 요청/실행환경 적용 프로필은 확인했다. 실제 사용자 입력 hook·같은 AI에 역할 자동 주입·공급자 턴의 모델/effort·토큰 수집까지 연결된 것은 아니다.

## 확인한 결과

| 항목 | 결과 | 근거와 한계 |
| --- | --- | --- |
| 현재 작업 공간 | 확인 | 공식 `worktree current`의 경로와 대상 프로젝트 일치 |
| 사용자 선택 연결 | 확인 | 같은 프로젝트·Orca 조율자·요청·추천 버전의 수용 기록을 관리 계획에 고정 |

| 공급자 실제 관측 | 미확인 | native `turn_context`의 원본 경로를 확보하지 못함. worker도 값을 추측하지 않고 unknown으로 보고 |
| 중복 재조회 | 확인 | 같은 operation·같은 입력의 실제 재조회가 `replay: true`, 관리 배정 수 1을 유지 |

| 입력/완료 hook | 미확인 | 시험용 프로젝트 정의를 등록했으나 실제 사용자 선택 입력과 worker 완료에서 probe/Stop 영수증이 생성되지 않음 |
| 토큰·비용 | 미측정 | 측정 이벤트를 만들거나 누락을 0으로 채우지 않음. 직접 처리 대비 절감 주장 없음 |

전체 프로필 판정은 `unverified`다. 요청·실행환경 적용의 네 필드는 pass, 공급자 실제 모델·effort 두 필드는 unverified다. 역할 지침을 전달한 대상은 새 worker이며 **같은 AI의 자동 역할 적용 성공으로 대신 보고하지 않는다.**

## 입력 연결에서 확인한 경계

- 현재 런타임 환경에 Codex 세션/스레드 식별자가 있었고 두 값이 일치했다. Orca 조율자 ID와는 별개이며 이름으로 변환하지 않았다. 실제 hook payload와의 일치는 미확인이다.
- 상위 Codex hook 설정에 `UserPromptSubmit` 정의가 있었지만 터미널용 환경 키를 참조하므로 이를 현재 structured chat의 이벤트 수신 근거로 쓰지 않았다. 기존 전역 정의는 수정하지 않았다.
- 설치 버전의 Orca 공식 플러그인 `agent.prompt.before`는 터미널에 제출하는 프롬프트 대상이며 사람이 직접 보낸 입력은 제외한다. [공식 host API](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-host-api.md#hooks)
- 공식 세션 검색의 활성 여부만 조회했으며 꺼져 있어 검색을 진행하지 않았다. 검색 설정을 켜거나 다른 대화·전체 세션 폴더를 탐색하지 않았다.
- 해당 worker의 공식 `worker-read --source auto --limit 1`은 정규화된 transcript와 불투명한 source identity를 반환했으며 native JSONL 원본 경로·프로필·토큰은 제공하지 않았다. 이 transcript를 native 원본으로 재해석하지 않았다.
- 새 hook의 정확한 정의·프로젝트 계층 신뢰 검토가 필요하다. [OpenAI hook 신뢰 계약](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks)을 확인했으나, 현재 Orca UI의 해당 검토 경로는 확보하지 못했다. UI 조회는 macOS 접근성 오류로 실패했고 사용자는 대화창 외의 hook 검토 안내를 확인하지 못했다. OS 권한·신뢰 우회 설정은 바꾸지 않았다.

영수증 부재만으로 Orca 전체가 hook을 지원하지 않는다고 단정하지 않는다. 로딩·프로젝트 신뢰·정의 신뢰·이벤트 제공 중 어느 단계가 원인인지 확인하지 못한 상태다. 다른 앱이나 단독 Codex로 실행 환경을 바꿔 성공으로 표시하지 않는다.

후속 공식 문서 재검색에서는 일반 프로젝트 hook 지원을 확인했다. 현재 CLI의 관리 상태 hook도 활성·Codex 설치 상태였으므로 “관리 hook이 꺼져 있음”을 원인으로 삼지 않는다. 이 설정/설치 조회와 사용자 프로젝트의 실제 이벤트 실행은 다르다. [재확인한 공식 지원 범위](orca-routing-input.md#2026-11-14-공식-웹-문서-재확인)를 기준으로 후속 진단을 제한한다.

설정 진단에서는 프로젝트 폴더의 신뢰와 사용자 hook의 저장된 활성/신뢰 항목은 확인했지만, 이번 프로젝트 hook의 개별 승인 기록은 없었다. 이는 실행을 막을 수 있는 별도 단계이며 실제 정의 해시·로딩·이벤트 상태의 조회와 구분한다. 동일 native 런타임의 `hooks/list`를 Orca CLI로 조회하는 경로는 확보하지 못했고 새 서버·직접 신뢰 해시 작성으로 대체하지 않았다. [진단의 근거와 한계](orca-routing-input.md#설치-버전-확인과-실제-시험)를 유지한다.

## 시험용 probe와 정리

`scripts/routing_probe.py`는 정확히 지정한 프로젝트·native 세션에서 `UserPromptSubmit`의 session/turn/cwd/transcript 경로 메타데이터만 한 번 기록한다. prompt·transcript 내용은 읽거나 저장하지 않으며 다른 세션·subagent는 제외한다. 최초 수신 확인 문맥은 한 번만 반환하고 후속 입력에는 빈 출력이다. 잘못된 입력·기록 오류는 원래 요청을 차단하지 않는다.

8개 로컬 검사에서 대상 일치/불일치·subagent 제외, 0600 보관·원문 비저장, 재주입/재저장 방지, 변경/손상된 기록 거부, 네트워크/실행 미호출·원본 미읽기, 후보 정의의 비설치와 비차단 오류를 확인했다. 이는 실제 이벤트 발생의 증명이 아니다.

실제 검증 종료 후 소유한 정의의 SHA-256을 대조해 **이번 시험에서 만든 프로젝트 hook 파일만 제거**했다. 따라서 이후 모든 입력에 시험용 프로세스가 남지 않는다. 전역 hook과 다른 프로젝트 파일은 보존했다. 비공개 후보·선택 바인딩·공식 snapshot·부분 audit는 남겼고 실제 worker 종료·관리 활성 배정 0을 확인했다.

## 기본 경로와 선택적 연결의 구분

이 검증에서는 기본 인입을 native hook 중심으로 좁혀 보았으나, hook을 모든 기능의 필수 선행 조건으로 두지 않도록 수정했다. `AGENTS.md`와 짧은 라우팅 지침이 연결된 현재 AI가 사용자 입력을 읽고 같은 응답에서 판단·제안하며, 대화에서 받은 선택을 필요한 로컬 도구에 연결하는 것이 기본 경로다. 별도 분류 AI·native probe·선택 UI가 매 입력에 필요한 것은 아니다.

같은 AI의 역할 적용도 필요한 지침을 현재 AI가 읽는 방식으로 운영할 수 있다. 이 가능 경로와 앱이 역할/상태를 자동 주입했다는 검증은 구분한다. 현재 대화의 모델/effort 전환은 별도 공식 적용 경로가 필요하며, 역할 적용을 이유로 worker로 바꾸지 않는다. native hook은 상태 자동 전달·원본 경로/측정 수집의 선택적 고도화로 둔다.

## 이후 진행 조건

1. 기본 경로는 연결된 짧은 지침·대화 선택·필요한 로컬 도구로 운영한다. native hook 로딩/검토 경로는 앱 측 선택적 지원 항목으로 분리하며 같은 UI 탐색·추가 시험 worker를 반복하지 않는다.
2. 경로가 확보되면 명시한 프로젝트 정의만 검토하고 실제 사용자 입력 한 건에서 수신·짧은 상태 전달·선택/취소·같은 AI에 상태/지침을 자동 주입하는 추가 연결을 확인한다. 신뢰·권한을 우회하지 않는다.
3. 승인된 다음 실제 업무에서 native 원본 경로·종료 이벤트를 받아 기존 수집기로 공급자 실제 프로필·토큰을 보완한다. 이번 한도 1을 새 operation/요청으로 초기화해 추가 시험하지 않는다.
4. 그 뒤에 [직접 처리 비교](routing-comparison.md)에 실제 짝지은 기록과 사용자/독립 품질 평가를 넣는다. 시간·금액과 자동화 확대는 별도 실제 근거가 필요하다.
