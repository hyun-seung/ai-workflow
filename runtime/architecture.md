# 공통 규칙·실행 환경·프로젝트 지침의 분리

상태: 채택. 환경 가이드와 시작 선택의 최소 구성만 구현했다. 모든 도구의 오케스트레이션 엔진을 이 저장소에서 새로 만드는 계획은 보류한다.

## 책임 경계

| 부분 | 소유하는 책임 | 기존 자료 재사용 |
| --- | --- | --- |
| 공통 작업 규칙 | 작업 분리·역할·완료 기준·검증·인계 자료·결과 보고 | AGENTS.md, roles/, templates/, 개인정보 원칙 |
| 실행 환경별 연결 | 에이전트·작업 공간 생성, 작업 전달, 상태·질문·결과 수신, 종료 | runtime/environments/의 환경별 가이드와 도구의 설치 버전 기능 |
| 프로젝트별 지침 | 저장소 구조·파일 범위·개발 규칙·테스트·저장소 간 계약 | 대상 프로젝트의 상위/개별 저장소 지침을 명시적으로 연결 |

환경은 Orca/Paseo 같은 작업 관리 체계다. agent provider는 Codex/Claude 등이며 model은 그 공급자 안의 실행 선택이다. 예를 들어 환경이 Orca 또는 Paseo이면서 공급자는 둘 다 Codex일 수 있다. 설치된 공급자나 모델 이름으로 환경을 추론하지 않는다.

공통 계약이 요구하는 것은 목표·원래 AC·변경 결과·버전·검증 근거·실행 연결이다. 각 도구의 작업 ID·dispatch ID·agent ID·host ID를 동일한 전역 ID라고 가정하지 않는다. 연결 자료에 출처를 보존하며 환경이 제공하지 않는 사용량은 미측정으로 표시한다. 공급자 전용 sandbox·effort·사용량 이벤트 형식을 공통 필수값으로 강제하지 않는다.

## 시작 선택

[시작 가이드](environments/README.md)에 따라 scripts/startup.py가 세션 근거와 선택한 환경의 읽기 전용 연결 조회로 가이드를 선택한다. 명시적 환경 설정은 세션 자동 추정보다 우선한다. 불명확·충돌·접속 실패·지원 응답 형식 미확인은 오류로 알리고 중단한다. 다른 앱이나 단독 Codex CLI로 조용히 대체하지 않는다.

선택 결과는 guide_selected이며 에이전트 실행 준비가 끝났다는 뜻이 아니다. 프로젝트·원격 host·작업 공간·사용할 공급자/모델·권한·필요 lifecycle 기능은 환경 가이드에 따라 추가 확인한다. 현재 스크립트는 세션 전체의 진위나 실행 권한을 증명하는 보안 경계가 아니다.

## 기존 개발에 미치는 영향

- 공통 원칙·역할·Markdown 작업 양식과 검증 기준은 유지한다.
- workflow.py의 단일 Codex 실행·기록·집계 기능과 기존 JSON 형식은 호환성을 유지한다. workflow.json의 adapter=codex는 기존 공급자 직접 실행 어댑터다. Orca/Paseo 선택값이 아니다.
- workflow.py run은 명시적으로 선택하는 단독 Codex 실험·검증 경로다. 환경 연결 실패의 대체 경로로 자동 호출하지 않는다. Orca/Paseo가 관리하는 세션의 실행을 이 CLI가 자동 계측한다고 가정하지 않는다.
- 직전의 [고정 자체 실행기 계약](orchestration-contract.md), 입력/결과 스키마와 가상 예제는 단독 Codex 프로토타입 설계 참고 자료로 보존한다. 공통 필수 프로토콜이나 다음 기본 구현 과제로 강제하지 않는다.
- 자체 잠금·재시도·질문 전달·알림·작업 그래프는 먼저 환경이 제공하는 기능을 확인한다. 공통 코드에는 필요한 연결과 결과 검증만 추가한다.
- 기존 컨텍스트 전달 실험은 단독 Codex 경로의 관측 기록이다. 그 측정치를 Orca/Paseo 환경의 실측으로 간주하지 않는다.

## 첫 적용과 미구현 범위

실제 적용과 검증은 Orca부터 진행한다. 프로젝트 지침 연결 → Orca 네이티브 인계 최소 실험 → 필요한 연결·결과 검증 보완 → 복수 저장소 개발·통합 검증 → 운영 안정화 순서다. Paseo의 실제 에이전트 실행·완료 수신 검증과 추가 개발은 그 이후로 보류한다. 기존 Paseo 가이드·시작 선택은 유지하며, 공통 규칙·프로젝트 지침에 Orca 전용 명령을 섞지 않는다.

첫 적용 형태는 상위 프로젝트 폴더 아래 백엔드·모바일 저장소를 함께 조율하는 구성이다. [프로젝트 연결 가이드](../projects/README.md)에 따라 상위 계약과 각 저장소의 지침·테스트를 구분한다. 실제 대상 프로젝트 이름·경로·등록 상태·미확인 사항은 비공개 진행 자료에 남긴다.

현재 구현은 가이드 선택과 연결 조회, 프로젝트 지침 경로 확인이다. 환경 네이티브 API 호출을 공통 함수로 감싼 dispatch/receive, 양쪽 환경의 실제 에이전트 실행·완료 수신 실험, 복수 저장소 변경 통합, 공통 사용량 수집, 예산 제어·자동 재개는 미구현 또는 미검증이다.

다음은 선택한 가이드와 프로젝트 지침을 실제 역할에 전달하는 작은 네이티브 작업으로 검증한다. 환경별 생성·접수·시작·완료·질문·권한 요청을 구분해 증거를 남기며, 필요한 기능이 없으면 제한을 보고하고 중단한다. 전체 자동 엔진보다 이 최소 인계부터 확장한다.

## 요청별 기록의 추가

실사용에서 요청별 명시 판단 요약·배정·지시·행동·결과를 함께 조회할 필요에 따라 [비공개 DB와 로컬 화면](trace-viewer.md)을 별도 도구로 추가한다. 공통 JSON bundle/JSONL 교환 계약과 저장 구현 경계를 유지하며 현재 SQLite만 구현한다. 명시 snapshot 수입 단계이고 native 실시간 추적·자체 orchestration 엔진을 의미하지 않는다. 기존 단독 실행·기록 형식의 호환성과 Orca 우선/Paseo 실제 실행 보류 결정은 유지한다.
