# 대화에서 적용 상태 표시

공통 지침을 적용하는 AI는 답변 끝에 실제 적용과 확인 결과를 한 줄로 표시한다. 사용자가 매번 적용 여부를 묻지 않아도 처리 방식을 알 수 있게 한다. 별도 사전 승인 질문이나 상태 확인용 에이전트를 만들지 않는다. 작업을 시작할 때 안내가 필요하면 예정 사항으로 표현하고, 완료 표시는 결과를 확인한 뒤에만 쓴다.

형식은 `ai-workflow · <적용 역할/직접 처리> · <실제 확인 결과>`다. 이번 요청에 중요한 결과만 고르고 불필요한 항목은 늘이지 않는다. 다음은 가상 예시이며 실행 증거가 아니다.

- 학습 설명: `ai-workflow · 튜터 적용 · 도식 제공 · 연관 Q&A 3개`
- 짧은 후속: `ai-workflow · 튜터 적용 · 짧은 후속으로 도식·Q&A 생략`
- 문서 수정: `ai-workflow · 직접 처리 · 링크 자체 확인 · 독립 검토 미수행`
- 개발: `ai-workflow · 역할별 에이전트 실행 · 자동화 시험 통과 · 독립 검토 통과`
- 대기 중: `ai-workflow · 조율 · 개발자 결과 수신 · 독립 검토 대기`
- 연결 확인 불가: `ai-workflow · 적용 미확인: 공통 지침 접근 불가`

## 표시 전 확인

- 역할·스킬은 실제로 읽어 적용했거나 같은 작업에서 유효하게 재사용한 경우만 표시한다. 연결 파일의 존재나 역할 이름만으로 적용을 주장하지 않는다.
- 자체 확인, 자동화 시험, 실제 별도 실행과 독립 검토를 구분한다. 별도 검토가 완료 조건인데 미실시·미검증이면 이를 반드시 표시하고 전체 완료로 표현하지 않는다. 복합 개발은 기존 `development_workflow.py report`의 결과와 일치해야 한다.
- 튜터는 응답에 실제 도식과 연관 질문·답변이 있는지 대조한다. 텍스트 화살표는 `텍스트 도식`, 실제 렌더된 도식은 `도식 제공`으로 구분한다. 제공하지 않았거나 지원을 확인하지 못했다면 사실대로 표시한다. 생략은 짧은 후속 등 기존 튜터 지침의 조건을 따르며 표시를 맞추려고 불필요한 내용을 추가하지 않는다.
- 사용자가 한 줄 답변·결과물만·표시 생략을 요청하거나 상위 출력 형식과 충돌하면 상태 줄을 생략한다. 역할 선택을 위한 긴 설명이나 매번 전체 문서 재로딩은 필요 없다.

## 확인 수준과 한계

이 줄은 AI가 작성하는 수행 요약이며 앱의 자동 감사·보안 승인·별도 프로그램 실행 증명이 아니다. 문서 연결만 확인된 경우와 실제 응답에서 적용된 경우를 구분한다. 공통 지침 자체를 받지 못한 대화에 이 표시를 강제로 추가할 수는 없다.

새 대화에서 일반 개념 질문과 짧은 후속 질문을 각각 시험해 실제 응답 내용과 상태 줄이 일치하는지 확인한다. 개발은 자체 시험만 있는 경우와 실제 독립 검토가 있는 경우를 구분해 확인한다. 문서·양식 검사를 통과한 것만으로 다른 앱의 실제 표시까지 검증됐다고 보고하지 않는다. 기존 대화를 초기화하지 않으며 사용자 승인 없이 검증 메시지를 대신 전송하지 않는다.

## 확인한 범위

한 로컬 Codex 앱의 기본 home 연결문을 보완한 뒤, 프로젝트 밖 새 대화에서 가상의 메시지 큐 개념 질문을 보냈다. 질문에서 튜터·도식·Q&A·상태 표시를 직접 요구하지 않았으며, 실제 응답에서 렌더된 Mermaid 흐름도, 비교표, 연관 질문과 답변 2개, 수행 내용과 일치하는 상태 줄을 확인했다. 도식은 접근성 트리와 화면으로 대조했다.

같은 대화의 후속에 한 문장 답변을 명시하자 실제로 한 문장만 반환했고 도식·Q&A·상태 줄을 추가하지 않았다. 긴 첫 설명과 짧은 후속의 예외를 각각 확인했으며 모든 짧은 질문에서 상태 표시를 생략하라는 뜻은 아니다.

이는 해당 환경의 실제 응답 관측이며 작성자의 자체 확인이다. 모든 주제·계정·앱·기존 대화의 자동 적용, 독립 평가, 개발 컨트롤러·사용량 수집 연결까지 검증한 결과는 아니다. 표시 누락을 앱이 강제로 차단하는 기능도 추가하지 않았다. 실제 대화·개인 경로·설정 백업은 공개 문서에 포함하지 않는다.
