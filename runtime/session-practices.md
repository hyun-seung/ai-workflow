# 세션·계획·검증 운용

공통 원칙을 실제 요청에 적용하는 판단 기준이다. 매 작업마다 전부 읽는 체크리스트가 아니며, 아래 CLI 명령은 해당 제품에서만 사용한다. Orca/Paseo의 대화·실행 기능을 제품 CLI 명령과 같다고 가정하지 않는다.

## 한 대화에 하나의 일관된 결과

- 같은 문제의 수정·검증·후속 질문은 현재 대화에서 이어간다. 무관한 목표는 새 대화로 분리한다. 이전 결정이 필요하면 목표·결정·파일 위치·남은 검증만 인계한다.
- Claude Code의 `/clear`, Codex CLI의 `/new` 또는 환경의 새 대화 기능을 사용한다. 긴 대화라는 이유만으로 필요한 맥락을 버리지 않는다.
- 같은 교정이 반복 실패하면 실패 원인과 재현 조건부터 정리한다. 잘못된 가정이 쌓였다면 수정된 요청으로 새 대화를 시작한다. 두 번 실패했다는 숫자만으로 자동 초기화하거나 이미 만든 산출물을 되돌리지 않는다.

## 계획은 불확실성을 줄이는 데 사용

작은 수정은 직접 처리한다. 여러 단계, 요구사항 충돌, 되돌리기 어려운 변경은 관련 자료를 조사하고 목표·참고 자료·제약·완료 기준을 짧게 정리한 뒤 구현한다. 모호한 핵심만 사용자에게 질문하고, 이미 확정한 내용을 반복 확인하지 않는다. [작업 양식](../templates/README.md)의 네 줄 요청이나 위임용 계약을 작업 규모에 맞게 쓴다.

필요하면 제품의 계획 모드(Claude Code의 Shift+Tab 전환, Codex CLI의 `/plan`)를 사용한다. 탐색 대화가 길어졌다면 계획과 완료 기준을 파일에 남겨 새 구현 대화로 전달할 수 있다. 짧고 유효한 맥락까지 항상 새 대화로 옮길 필요는 없다. 계획 모드 자체를 파일 접근·운영 권한의 강제 경계로 간주하지 않는다.

## 모델·캐시는 비용 판단의 한 요소

시작 시 모델·effort와 필요한 권한을 정하고, 안정된 지침·자료를 불필요하게 다시 쓰지 않는다. 모델 변경이나 prefix 변화는 캐시 적중에 영향을 줄 수 있다. 그러나 품질·보안상 필요한 변경을 캐시 때문에 금지하지 않는다. 특히 Codex는 일부 권한 변경을 새 메시지로 덧붙여 prefix를 보존하도록 처리한다. [Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/)는 2026-01-23의 구조 설명이며 모든 버전에 동일한 캐시 동작을 보장하지 않는다.

Claude Code의 기본 TTL은 구독 포함 사용량의 본 대화에서 1시간, API 키·크레딧 등과 대부분의 서브에이전트에서 5분이다. 설정으로 달라질 수 있고, 캐시 적중은 TTL을 갱신한다. 이는 Codex의 TTL이나 구독 한도 할인율이 아니다. 오래 쉬어도 이전 판단이 필요하면 이어가며, 과거 내용이 불필요하면 새 대화를 선택한다. 캐시를 유지하려고 불필요한 메시지를 보내지 않는다. [Claude 캐시 문서](https://code.claude.com/docs/en/prompt-caching).

캐시 읽기·쓰기·비캐시 입력, 구독 사용량과 API 비용을 구분한다. 비용 절감은 추정으로 단정하지 않고 실제 기록과 완료 품질로 비교한다. 자동 압축이 있으므로 “과거 원문 전체가 영구히 매번 전달된다”거나 “모든 모델이 100만 토큰이다”라고 가정하지 않는다.

기존 `scripts/workflow.py`는 매번 `codex exec --ephemeral`로 새 단일 역할 실행을 만든다. 같은 `task_id`나 기록 ID를 붙여도 대화가 재개되지 않는다. 연속 대화가 필요한 작업은 선택한 환경의 실제 재개 기능을 사용하며, 이 가이드가 실행기에 세션 재개를 추가한 것은 아니다.

## 짧은 규칙과 실행 가능한 검사

- 상시 지침에는 프로젝트 고유의 함정·필수 제약·검증 명령을 둔다. 반복 실수의 원인을 확인해 필요한 규칙을 추가하거나 기존 문구를 고친다. 새로 확인된 중요한 위험은 반복될 때까지 기다리지 않는다.
- 상세 절차는 필요할 때 읽을 문서로 연결한다. 폴더 구조·도구 기본 행동을 장황하게 복제하지 않는다. 파일 줄 수뿐 아니라 실제 자동 로드되는 문서의 합계와 중복도 본다.
- 완료 기준을 확인할 테스트·빌드·재현·화면 비교 수단을 제공한다. 이미 통과한 검사를 새 변경이나 불확실성 없이 반복하지 않는다. 모델이 스스로 테스트한다는 이유로 필요한 검증과 프로젝트 명령을 삭제하지 않는다.
- 예외 없이 지켜야 하는 제약은 실행 환경의 권한·sandbox, 지원되는 hook, CI 검사 등으로 강제하고 실제 실패 경로도 확인한다. 문서에 적힌 규칙, 로컬 검사, 필수 CI/병합 조건은 서로 다르다. 이 저장소의 `dispatch_guard.py`도 관리 경로 밖의 실행을 통제하지 않는다.
- 대문자 강조나 막연한 “깊게 생각해 / 끝까지 해” 대신 결과와 종료 조건을 적는다. reasoning 설정은 지원 범위를 확인하고, 모델별 조언을 모든 모델에 일괄 적용하지 않는다.
