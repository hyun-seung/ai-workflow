# 요청·실행환경·실제 관측 프로필

모델·effort는 세 종류의 근거를 구분한다. 요청값이나 도구 기본값으로 실제 관측값을 채우지 않는다.

| 구분 | 사용하는 근거 | 의미 |
| --- | --- | --- |
| 요청 | 명시 native snapshot의 `startOptions.launch.requested` | 해당 배정을 시작할 때 요청한 값 |
| 실행환경 적용 | 같은 snapshot의 `startOptions.launch.effective` | Orca가 실행 준비에서 적용했다고 기록한 값 |
| 실제 관측 | 해당 native 턴 내부 `turn_context`의 model·effort | Codex 실행 기록에 관측된 값 |

실제 관측은 공급자의 턴 컨텍스트에 기록된 값이다. 공급자 내부 라우팅이나 물리 서버의 모델을 별도 계측했다는 뜻은 아니다. snapshot·값이 없으면 미확인이다. native 요청이 관측됐지만 모델을 명시하지 않은 null은 `native 기본값 요청`으로 표시하며 실제 모델을 추측하지 않는다. 적용 단계의 관측된 null은 `적용값 미제공`이다.

[라우팅 선택을 명시 연결한 배정](routing-dispatch.md)은 `finish_worker.py`의 관리 operation 연결에서 선택한 모델·effort를 기대값으로 가져온다. 완료 metadata의 세 단계를 대조해 하나라도 누락되면 `routing_profile=unverified`, 불일치면 fail로 반환하며 요청값으로 실제 관측을 채우지 않는다. 이는 가상 native 응답으로 검사한 신규 연결이며 아래 기존 수집 경로의 실제 관측 검증과 구분한다.

## 추가 관측과 수입

[native 검사기](native-record.md)는 optional worker snapshot을 정확한 task/dispatch/Orca process incarnation과 대조한다. `requested`는 기존 계약을 유지하고 `launch_effective`를 추가한다. 오래된 snapshot에 effective 단계가 없으면 unavailable이다. CLI 기대값은 프로필을 바꾸거나 실행 사실로 승격되지 않는다.

[사용량 수입](trace-usage.md)은 `observed_contexts`가 있는 Orca·Codex worker 메타데이터에 한해 `kind=profile`, `source=trace.native-profile.v1` 이벤트와 입력 경로·SHA256 collection을 같은 트랜잭션으로 추가한다. 새 명령이나 웹 조회 중 파일 읽기는 없다. 기존 [완료 hook](completion-hook.md)의 `import_usage` 호출도 이 연결을 사용한다. profile 항목이 없는 오래된 입력과 조율자 수집 형식은 그대로 수입하며 실제 관측은 미확인으로 남는다.

프로필은 같은 요청·논리 actor의 `usage_event_id`·물리 measurement_key·정확한 측정 interval에 연결한다. provider context는 턴 시작과 종료 사이의 행만 선택한다. 배정 머리말·세션·Orca 출처를 대조하고 그 바깥의 다른 턴 설정을 가져오지 않는다. profile 단독 수입도 Store의 동일 요청/소유자/구간·source/version·유한수·불변 해시 검사를 거친다. 잘못된 프로필이나 입력 근거는 함께 수입하던 usage도 롤백한다.

초기 actor의 requested/observed·기존 토큰 이벤트를 덮어쓰지 않는다. 프로필 사실과 근거가 같으면 같은 ID로 replay하고, 나중에 native 요청/적용 근거가 추가되면 별도 관측을 남긴다. 모델 관측 이벤트는 토큰 측정이 아니므로 요청·역할 토큰 합계에 더하지 않는다. 프로필 원천 JSON의 구조·참조 검사는 입력 작성자의 신원이나 조작되지 않았음을 암호학적으로 증명하지 않는다. 수집기가 확인한 실제 원본 및 명시된 입력을 사용한다.

## 화면의 요약과 세부 근거

담당자 카드에 요청과 실제 관측의 모델·effort를 표시한다. 펼치면 요청·실행환경 적용·실제 관측, 각 프로필 원문과 입력 경로·해시를 확인한다. 작업별 토큰 행은 해당 usage 구간에 연결된 프로필만 표시한다.

- native 요청 근거가 없을 때 담당자 카드의 명시 요청값은 `등록값`으로 표시할 수 있다. 이를 그 담당자의 모든 후속 배정 요청으로 복제하지 않는다. 작업별 요청은 별도 native 근거가 없으면 미확인이다.
- 이전 actor.observed 값은 원래 수입 기록으로 보존하고 펼쳐 읽는다. 근거가 연결된 새 실제 관측처럼 표시하지 않는다.
- 관측 없는 값은 미확인, 일부 작업/필드가 빠지면 일부 미확인이다. 다른 context 행·다른 구간에 설정이 달랐다면 구간별 상이로 표시한다. 같은 구간·동일 행에 서로 다른 관측 근거가 있으면 근거 상충으로 표시한다. 임의로 마지막 값 하나를 고르지 않는다.
- 요청 또는 적용값과 실제 관측의 명확한 단일 값이 다르면 차이를 표시한다. 여러 값·부분 관측·native 기본값을 자동 실패나 단일 일치로 판정하지 않는다.
- 같은 구간의 보완 관측은 값별로 합쳐 읽되, 명시된 native 기본값과 나중의 명시 값이 같은 요청 근거에서 충돌하면 그 차이를 숨기지 않는다.

## 보존·개인정보·마감

새 프로필 추가로 기존 [마감](trace-closeout.md)이 stale이 될 수 있다. 원래 이벤트/보고서를 보존한 뒤 근거를 확인하고 새 마감 ID를 사용한다. SQLite 테이블은 그대로이며 profile을 모르는 예전 도구는 새 이벤트를 거부할 수 있으므로 복원에도 지원 버전을 사용한다.

원본·입력 경로에는 사용자명이 포함될 수 있다. 프로필 근거와 실제 입력은 비공개로 보관하고 공개 문서는 범용 계약과 가상 예시만 사용한다. 이 기능은 세션 폴더 탐색·외부 전송·모델 설정 변경·자동 승인·새 서버 실행을 하지 않는다. 실제 프로필이 없는 과거 자료를 역할명·요청 모델·세션의 다른 턴 값으로 소급 추정하지 않는다.

## 확인한 범위

가상 입력의 구간·소유자·버전·JSONL·롤백·replay와 UI의 누락·상충·기본값·보완을 독립 검토했다. 로컬에 등록된 Orca·Codex worker 한 건에서 기존 Stop hook의 usage와 profile 동시 자동 수입도 확인했다. 같은 worker의 종료 snapshot으로 요청·적용 근거를 보완해 세 단계의 일치와 토큰 한 구간 유지를 실제 화면에서 확인했다. 과거 자료의 선택 재관측, 다른 공급자·원격·조율자 턴의 profile 지원은 해당 근거를 별도로 확인해야 한다.
