# 프로젝트 전체 연결

이 문서는 README의 시작 메시지를 받은 AI가 사용하는 연결 절차다. 사용자가 만든 기능을 필요한 순간에 함께 사용할 수 있도록 프로젝트를 준비한다. 지침을 읽은 것, 설정한 것, 실제 실행을 검증한 것을 구분한다. 이 문서는 새 설치 프로그램이나 앱의 자동 입력 hook이 아니다.

## 사용자가 결정할 것

필요한 정보만 묻고 이미 확인한 답은 재사용한다.

1. **대상:** 현재 앱이 열린 기존 프로젝트가 맞는지 확인한다. 경로·host가 불명확할 때만 묻는다.
2. **저장소 위치:** 읽을 수 있는 ai-workflow 복사본이 있으면 재사용한다. 없으면 설치할 위치와 받을 버전을 제안한다. 폴더 생성·다운로드는 실제 허용 범위와 도구의 정식 권한 절차를 따른다. 새 제품 프로젝트·worktree로 대신하지 않는다.
3. **기록:** 비공개 기록·SQLite를 둘 위치와 보관·수집 범위를 선택받는다. 지침 연결을 수집 동의로 간주하지 않는다.

모델·effort·에이전트별 JSON을 사용자가 먼저 작성하게 하지 않는다. 실제 환경을 확인한 뒤 합리적인 후보와 적용할 변경을 제시한다. 결정이 필요한 항목은 한 번에 정리하되, 읽기 전용 확인과 설정안 준비는 먼저 진행한다.

## 1. 읽기 전용 확인과 연결안 준비

- 현재 cwd·Git 브랜치·미커밋 변경·앱/daemon host를 확인한다. 인증정보나 원본 세션을 탐색하지 않는다.
- 공통 `AGENTS.md`, 대상 프로젝트의 지침, [프로젝트 가이드](../projects/README.md)를 읽는다. 현재 판단에는 [짧은 진입 지침](routing-brief.md)을 사용한다. 전체 역할 문서를 한꺼번에 로드하지 않는다.
- Orca/Paseo 연결은 [환경 가이드](environments/README.md)를 따른다. Codex 앱에 미지원 `startup.py --environment codex` 값을 만들지 않는다. 설치된 CLI가 해당 앱의 실제 세션임을 뜻하지 않는다.
- 사용할 저장소 커밋, 필요한 도구·역할 스킬의 존재와 지원 기능을 확인한다. 외부 스킬은 설치·버전·실제 읽기를 확인하고, 미설치 후보를 사용한 것으로 적지 않는다.
- 기능별 연결안을 만든다. 수정할 파일·추가 문구·비공개 출력 위치·필요 권한·되돌릴 방법을 보여 준다. 기존 지침·설정·DB는 보존한다. 공유 파일에는 사용자 절대 경로를 무심코 커밋하지 않는다.

기존 자료가 없다면 설치·버전 확인과 최소 지침 연결을 먼저 준비한다. 도구 접근이 없는 일반 채팅에서는 필요한 파일 전달 방법을 안내하고, 로컬 연결을 수행했다고 주장하지 않는다.

## 기능별 연결 확인

전체 연결의 점검 목록이다. 모든 항목을 켜거나 모든 문서를 매 요청마다 읽으라는 지시가 아니다. 대상 앱·업무에 맞는 항목을 준비하고, 나머지는 이유와 함께 남긴다.

| 기능 | 연결할 내용 | 현재 경계와 근거 |
| --- | --- | --- |
| 요청의 앞단 판단 | 현재 AI가 목적·후속·자료 부족·직접 처리 여부를 먼저 판단. 필요한 경우만 추천·선택 기록 | [짧은 판단](routing-brief.md), [대화 선택과 상태 연결](routing-flow.md). 별도 분류 모델과 매 입력 도구 호출은 기본이 아님. 앱의 자동 입력 수신·선택 UI는 미연결 |
| 역할·학습 방식 | 필요한 역할 문서와 로컬 역할 스킬만 읽고 적용 | [역할](../roles/README.md), [튜터](../learning/README.md), [스킬 연결](../skills/README.md). 같은 AI의 역할 적용과 새 에이전트 실행을 구분 |
| 모델·effort | 요청·실행환경 적용·실제 관측을 분리. 변경이 필요하면 지원 경로와 해당 작업의 선택 확인 | [프로필](profiles.md), [실행 관측](execution-profiles.md). `workflow.json`이 모든 앱의 설정을 자동 대체하지 않음. 현재 대화의 자동 모델 전환은 미연결 |
| 위임·동시 실행 한도 | 환경의 공식 관리 경로, 등록된 요청·담당자, 동시/누적 한도·정확한 종료 확인 | [위임 한도](delegation.md), [선택한 worker 실행](routing-dispatch.md). 연결 동의를 무제한·지속 위임 동의로 확대하지 않음. 다른 앱에 Orca ID를 위조하지 않음 |
| 권한·신뢰 | 프로젝트·경로·명령에 필요한 최소 권한과 정식 예외 절차 | [실행 권한](permission-policy.md). 부모 성공을 자식 권한으로 추정하지 않음. hook은 정확한 정의에 대한 별도 보안 신뢰 필요 |
| 개발·검증 | 프로젝트의 실제 테스트와 완료 기준, 영향에 맞는 자체 검사·필요한 독립 검토 | [역할 책임](../roles/README.md), [작업 양식](../templates/README.md). 작은 작업에 불필요한 에이전트·전체 검사·화면 검증을 강제하지 않음 |
| 실행 기록·조회 | 비공개 trace DB와 요청·담당자·검증 근거 연결, 필요 시 로컬 화면 | [기록과 대시보드](trace-viewer.md). 데이터 수입과 UI 사용 준비를 따로 확인. 다른 앱의 원문을 자동 변환한다고 가정하지 않음 |
| 사용량·실행 프로필 | 지원되는 실제 측정 출처와 구간을 연결하고 중복·부분 측정을 표시 | [사용량 수입](trace-usage.md), [조율자 명시 수집](coordinator-collection-flow.md), [완료 hook](completion-hook.md). 전체 세션 원본 탐색·한도 우회·quota의 작업 토큰 승격 금지. Paseo/Codex 앱 자동 수집 adapter는 미구현 |
| 완료·복구·정리 | 수용한 결과·정확한 종료·보관본·재처리·임시 자원 소유권을 연결 | [요청 마감](request-completion.md), [수집 복구](completion-recovery.md), [작업 공간 관리](workspace-lifecycle.md). 기존 프로젝트·원본·이력을 임시 자원으로 삭제하지 않음 |
| 승인 대기 | 필요한 승인과 수입 가능한 이벤트의 상태를 구분 | [승인 대기](approval-waits.md). 실제 live 승인 ID 대조·자동 알림 전송·버튼 연결은 확인된 지원 경로가 없어 활성화했다고 보고하지 않음 |
| 여러 PC의 개선 자료 | 최소 요약 내보내기·수동 전달·별도 feedback DB 수입·중복 확인 | [서버 없는 파일 교환](feedback-exchange.md). 중앙 업로드는 미구현. 교환 키·원문·개인 경로는 공개하지 않음 |
| 비교·스킬 유지관리 | 같은 완료 기준의 측정 비교와 실제 사용 후 개선 검토 | [비교](routing-comparison.md), [스킬 운영](../skills/operations.md). 규칙·모델·권한을 자동 변경하지 않음. 예약·외부 설치는 별도 선택이며 복제만으로 배포되지 않음 |

## 2. 검토한 연결안 적용

사용자가 수용한 파일·설정 범위만 적용한다. 실제 권한이 부족하면 정식 승인 경로를 사용한다. 설정을 받았다는 대화 응답을 도구의 보안 신뢰 영수증으로 대신하지 않는다.

프로젝트 진입 지침은 짧게 유지한다. 다음을 찾을 수 있도록 대상 앱이 지원하는 지침 파일에 연결한다.

- 실제 공통 저장소의 `AGENTS.md`와 프로젝트 고유 지침.
- 일반 요청에는 `runtime/routing-brief.md`를 따르고, 단순 요청은 직접 처리한다는 기준.
- 역할 변경이 필요할 때만 해당 역할·스킬을 읽는 경로.
- 수용한 선택·위임·기록 연결이 필요한 작업에서만 상세 운영 문서를 참조하는 경로.

역할 본문·전체 설정·전체 기능 표를 매 턴 주입하지 않는다. “모든 기능 사용”이라는 목표를 매 요청 전체 도구 실행으로 해석하지 않는다. 초깃값과 변경이 필요한 지점은 비공개 설치 기록에 남긴다.

## 3. 기능별 실제 검증

먼저 [읽기 전용 지침 시험](app-guidance-check.md)을 수행한다. 이어서 활성화하려는 기능에 필요한 최소 검증만 한다.

- **판단·역할:** 작은 질문을 직접 처리하고, 역할·검토가 필요한 대표 요청에서는 그 이유와 다음 단계를 설명하는지 확인한다. 선언만으로 독립적인 품질 검증을 주장하지 않는다.
- **위임:** 실제 worker 시험이 명시적으로 허용된 경우에만 한 건을 등록된 경로로 수행한다. 프로필·동시/누적 한도·종료 조건을 먼저 고정한다. 위임이 불필요한 지침 시험에 worker를 증설하지 않는다.
- **기록·수집:** 먼저 합성 자료로 형식·중복·충돌을 확인한다. 실제 자료 수집은 사용자가 정한 비공개 위치와 명시 출처만 사용한다. hook은 실제 이벤트 수신·DB 반영·재처리까지 확인한 범위만 통과로 표시한다. 원본이 없거나 구간을 확정할 수 없으면 부분/미측정으로 남긴다.
- **마감·교환:** 준비한 보관·정리와 교환 기능을 각각 확인한다. 한 PC의 합성 파일 복사를 실제 두 PC 전송으로 확대하지 않는다.

설정 중 발견한 앱의 지원 공백을 새 제품 개발·전역 설정 우회로 해결하지 않는다. 현재 가능한 경로를 먼저 마무리하고, 필요한 adapter나 앱 기능은 별도 후속으로 구분한다.

## 4. 사용자에게 보여 줄 완료표

상세 영수증·경로·로그는 비공개로 보관하고 다음처럼 짧게 보고한다. 아래는 양식이며 미리 통과로 채우지 않는다.

| 기능 | 연결 상태 | 검증 상태·다음 행동 |
| --- | --- | --- |
| 요청 판단·역할 | 미설정 / 연결 / 비활성 / 미지원 | 통과 / 실패 / 미검증, 실제 근거 |
| 위임·한도·권한 | 동일 | 지원 환경과 허용 범위 |
| 검증·마감 | 동일 | 수행한 검사와 미확인 |
| 기록·사용량·조회 | 동일 | 실제 수입 범위, 부분·미측정 |
| 파일 교환·개선 자료 | 동일 | 합성/실제 PC 검증 구분 |
| 승인 알림·앱 자동 연결 | 동일 | 지원 공백과 재개 조건 |

기능 전체가 활성화되지 않아도 연결된 판단·역할·검증 경로는 사용할 수 있다. 다만 일부 설정만 한 상태를 “전체 자동화 완료”로 표시하지 않는다. 사용자는 이후 자연어로 요청하고, 현재 AI는 연결된 지침과 수용한 실행 범위에서 필요한 기능을 선택한다.
