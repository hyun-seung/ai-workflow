# 작업 공간 생성·보관·정리

새 프로젝트를 만드는 일, 도구에 폴더를 등록하는 일, 임시 작업 파일을 만드는 일을 구분한다. 작업이 길거나 역할이 여러 개라는 이유만으로 프로젝트·Git 저장소·worktree를 새로 만들지 않는다. 명시한 로컬 임시 폴더는 [완료 처리 도구](completion.md)로 보관본 검증·등록 해제·삭제를 연결할 수 있다. 자동 생성·보관본 생성·전역 프로젝트 탐색은 구현하지 않았다.

## 언제 만드는가

| 요청과 현재 상태 | 기본 선택 |
| --- | --- |
| 기존 프로젝트의 기능 수정·검증 | 기존 프로젝트와 지침 재사용. 새 프로젝트 생성 불필요 |
| 문서 조사·작은 분석·일회성 보조 스크립트 | 합의된 비공개 임시 폴더. 앱 프로젝트 등록은 실행 환경에 필요할 때만 |
| 독립적으로 실행할 재현 실험·테스트 프로젝트 | 별도 작업 폴더. 소스·실행 방법·결과는 최종 산출물로 보관하고 캐시·임시 실행 파일과 구분 |
| 사용자가 지속적으로 개발할 새 제품·저장소를 요청 | 유지할 프로젝트로 생성. 위치·이름·저장소 범위를 명확히 함 |
| 같은 저장소의 격리된 변경본이 실제로 필요 | 한 담당자에게 묶을 수 있는지 먼저 판단하고, 필요한 경우 선택한 환경의 worktree 기능 사용 |

기존 폴더가 비어 있다고 가정하거나 같은 이름의 폴더를 재사용하지 않는다. 새 폴더는 충돌 없는 경로로 만든다. 새 Git 초기화·remote 연결·앱 등록은 각각 필요한 목적이 있을 때 수행하며, 임시 폴더 생성에 자동으로 따라붙지 않는다.

## 생성 전에 정할 내용

조율자가 작업 입력 또는 비공개 실행 기록에 다음 내용을 짧게 남긴다. 기존 프로젝트를 그대로 쓰는 작은 작업에 새 문서·절차를 만들 필요는 없다.

- 생성 이유, 기존 프로젝트로 처리하지 않는 이유.
- 기존 프로젝트 / 유지할 새 프로젝트 / 임시 작업 공간의 구분.
- 정확한 host·경로·담당자, 이번 작업이 생성한 범위와 앱 등록 식별자.
- 최종 소스·보고서·로그의 보관 위치와 임시 캐시·빌드 출력의 구분.
- 완료 뒤 유지·등록 해제·임시 폴더 삭제 중 적용할 조치와 권한 근거.

정리 권한이 이미 사용자 요청이나 합의한 운영 규칙에 포함돼 있으면 반복해서 묻지 않는다. 불분명하면 임의 삭제하지 않고 보관 이유와 필요한 결정을 알린다. 기존 사용자 프로젝트·외부 입력·최종 산출물을 임시 자료로 분류하지 않는다. 과거에 만든 폴더에 새 정책을 소급해 자동 삭제하지 않는다.

## 작업 중 관리

작업별 프로세스와 입력·출력 위치를 기록하고, 다른 역할의 scratch를 자신의 폴더로 가정하지 않는다. 최종 산출물의 기준 위치를 하나 정하고 복사본의 목적을 명시한다. 로그·보고서에 작업용 원본 경로가 있으면 보관본에서 대응 파일을 찾을 수 있도록 경로 목록을 남긴다.

같은 파일·설정의 수정은 한 담당자에게 모은다. 병렬 작업이 필요하면 수정 범위·포트·로그·빌드 출력이 분리돼야 한다. 세부 기준은 [병렬 위임 정책](parallelism.md)을 따른다.

## 완료 시 정리 순서

1. 결과 쓰기 작업을 마무리하고 이번 작업이 시작한 서버·worker·백그라운드 프로세스의 종료를 확인한다. 사용자가 유지하도록 요청한 서비스는 목적·종료 방법을 남긴다.
2. 합의한 보관 위치에 소스·실행 방법·필요한 결과와 검증 근거를 보관한다. 남길 파일과 제외할 캐시를 명시한다. 폴더나 ZIP이 존재한다는 사실만으로 보관 완료로 판정하지 않는다.
3. 필요한 파일 목록과 내용·해시를 대조한다. 복사 이후 새 사용자 변경이나 실행 기록이 생기지 않았는지 확인하고, 원본 작업 폴더가 없어도 보관본의 문서·자료를 찾아 사용할 수 있는지 확인한다. 검증 범위를 넘는 재실행은 별도로 표시한다.
4. 정리 대상과 권한이 확정된 임시 공간만 처리한다. 앱 등록 해제와 디스크 삭제는 별도 조치이며, 삭제 명령이 두 가지를 함께 수행하는지 설치 버전에서 확인한다. 삭제 권한이 없는 경우 허용된 정리만 수행한다.
5. 결과 전달과 함께 종료된 프로세스, 제거한 등록·폴더, 보관 위치와 남은 항목을 알린다. 정리가 실패·보류됐다면 원인과 다음 조치를 기록한다.

요청 결과가 준비됐지만 네이티브 worker의 자동 회수만 예약 상태라면 결과를 먼저 전달하고 그 자원 상태를 별도로 기록한다. `worker_done`을 실제 프로세스 종료로 바꾸어 쓰거나, 회수를 기다리며 반복 조회하지 않는다. 테스트 서버는 네이티브 worker 회수와 별개로 이번 실행의 프로세스를 종료해야 한다.

원본과 보관 위치가 같거나 중첩되면 삭제하지 않는다. 이번 작업이 만든 정확한 경로만 대상으로 삼으며 scratch 상위 폴더 전체·공유 캐시·다른 프로젝트를 일괄 삭제하지 않는다. 심볼릭 링크나 실행 상태 때문에 대상이 불분명하면 정리를 멈춘다. 자동 TTL만으로 사용자 산출물을 지우는 정책은 기본으로 사용하지 않는다.

## 정리 도구 적용과 남은 범위

`scripts/workspace_cleanup.py prepare`로 정확한 대상·명시 권한·수용 근거·배정 목록·보관본·파일 해시를 비공개 계획에 저장한다. `apply` 또는 `finish_worker.py --cleanup-plan`은 계획과 실제 상태를 다시 확인한다. 유지할 프로젝트나 아직 기록되지 않은 과거 프로젝트를 자동 삭제 대상으로 추정하지 않는다.

현재 지원하는 앱 등록 해제는 로컬 Orca folder setup이다. Git worktree·원격 host·프로세스 강제 종료는 제외한다. 단계별 재시작과 부분 실패·중단 시 보존 조건은 [완료 처리 사용법](completion.md)에 따른다.
