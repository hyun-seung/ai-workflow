# 작업 공간 생성·보관·정리

새 프로젝트를 만드는 일, 도구에 폴더를 등록하는 일, 임시 작업 파일을 만드는 일을 구분한다. 작업이 길거나 역할이 여러 개라는 이유만으로 프로젝트·Git 저장소·worktree를 새로 만들지 않는다. 새 로컬 임시 폴더는 아래 도구로 생성 기록과 보관·정리를 연결한다. 기존 폴더는 [완료 처리 도구](completion.md)의 별도 승인·보관 검사를 적용한다. 전역 프로젝트 탐색은 하지 않는다.

## 언제 만드는가

| 요청과 현재 상태 | 기본 선택 |
| --- | --- |
| 기존 프로젝트의 기능 수정·검증 | 기존 프로젝트와 지침 재사용. 새 프로젝트 생성 불필요 |
| 문서 조사·작은 분석·일회성 보조 스크립트 | 합의된 비공개 임시 폴더. 앱 프로젝트 등록은 실행 환경에 필요할 때만 |
| 독립적으로 실행할 재현 실험·테스트 프로젝트 | 별도 작업 폴더. 소스·실행 방법·결과는 최종 산출물로 보관하고 캐시·임시 실행 파일과 구분 |
| 사용자가 지속적으로 개발할 새 제품·저장소를 요청 | 유지할 프로젝트로 생성. 위치·이름·저장소 범위를 명확히 함 |
| 같은 저장소의 격리된 변경본이 실제로 필요 | 한 담당자에게 묶을 수 있는지 먼저 판단하고, 필요한 경우 선택한 환경의 worktree 기능 사용 |

기존 폴더가 비어 있다고 가정하거나 같은 이름의 폴더를 재사용하지 않는다. 새 폴더는 충돌 없는 경로로 만든다. 새 Git 초기화·remote 연결·앱 등록은 각각 필요한 목적이 있을 때 수행하며, 임시 폴더 생성에 자동으로 따라붙지 않는다.

## 생성 전에 정할 내용

조율자가 작업 입력 또는 비공개 실행 기록에 다음 내용을 짧게 남긴다. 기존 프로젝트를 그대로 쓰는 작은 작업에 새 문서·절차를 만들 필요는 없다.

- 생성 이유, 기존 프로젝트로 처리하지 않는 이유.
- 기존 프로젝트 / 유지할 새 프로젝트 / 임시 작업 공간의 구분.
- 정확한 host·경로·담당자, 이번 작업이 생성한 범위와 앱 등록 식별자.
- 최종 소스·보고서·로그의 보관 위치와 임시 캐시·빌드 출력의 구분.
- 완료 뒤 유지·등록 해제·임시 폴더 삭제 중 적용할 조치와 권한 근거.

정리 권한이 이미 사용자 요청이나 합의한 운영 규칙에 포함돼 있으면 반복해서 묻지 않는다. 불분명하면 임의 삭제하지 않고 보관 이유와 필요한 결정을 알린다. 기존 사용자 프로젝트·외부 입력·최종 산출물을 임시 자료로 분류하지 않는다. 과거에 만든 폴더에 새 정책을 소급해 자동 삭제하지 않는다.

## 작업 중 관리

작업별 프로세스와 입력·출력 위치를 기록하고, 다른 역할의 scratch를 자신의 폴더로 가정하지 않는다. 최종 산출물의 기준 위치를 하나 정하고 복사본의 목적을 명시한다. 로그·보고서에 작업용 원본 경로가 있으면 보관본에서 대응 파일을 찾을 수 있도록 경로 목록을 남긴다.

같은 파일·설정의 수정은 한 담당자에게 모은다. 병렬 작업이 필요하면 수정 범위·포트·로그·빌드 출력이 분리돼야 한다. 세부 기준은 [병렬 위임 정책](parallelism.md)을 따른다.

## 완료 시 정리 순서

1. 결과 쓰기 작업을 마무리하고 이번 작업이 시작한 서버·worker·백그라운드 프로세스의 종료를 확인한다. 사용자가 유지하도록 요청한 서비스는 목적·종료 방법을 남긴다.
2. 합의한 보관 위치에 소스·실행 방법·필요한 결과와 검증 근거를 보관한다. 남길 파일과 제외할 캐시를 명시한다. 폴더나 ZIP이 존재한다는 사실만으로 보관 완료로 판정하지 않는다.
3. 필요한 파일 목록과 내용·해시를 대조한다. 복사 이후 새 사용자 변경이나 실행 기록이 생기지 않았는지 확인하고, 원본 작업 폴더가 없어도 보관본의 문서·자료를 찾아 사용할 수 있는지 확인한다. 검증 범위를 넘는 재실행은 별도로 표시한다.
4. 정리 대상과 권한이 확정된 임시 공간만 처리한다. 앱 등록 해제와 디스크 삭제는 별도 조치이며, 삭제 명령이 두 가지를 함께 수행하는지 설치 버전에서 확인한다. 삭제 권한이 없는 경우 허용된 정리만 수행한다.
5. 결과 전달과 함께 종료된 프로세스, 제거한 등록·폴더, 보관 위치와 남은 항목을 알린다. 정리가 실패·보류됐다면 원인과 다음 조치를 기록한다.

요청 결과가 준비됐지만 네이티브 worker의 자동 회수만 예약 상태라면 결과를 먼저 전달하고 그 자원 상태를 별도로 기록한다. `worker_done`을 실제 프로세스 종료로 바꾸어 쓰거나, 회수를 기다리며 반복 조회하지 않는다. 테스트 서버는 네이티브 worker 회수와 별개로 이번 실행의 프로세스를 종료해야 한다.

원본과 보관 위치가 같거나 중첩되면 삭제하지 않는다. 이번 작업이 만든 정확한 경로만 대상으로 삼으며 scratch 상위 폴더 전체·공유 캐시·다른 프로젝트를 일괄 삭제하지 않는다. 심볼릭 링크나 실행 상태 때문에 대상이 불분명하면 정리를 멈춘다. 자동 TTL만으로 사용자 산출물을 지우는 정책은 기본으로 사용하지 않는다.

## 새 임시 폴더의 등록·보관 연결

`scripts/workspace_resources.py`는 명시한 새 폴더 하나를 생성하면서 요청·담당자·목적·정리 권한·정확한 경로와 inode를 비공개 기록에 고정한다. 유지할 조율 프로젝트를 `--project`로 지정한다. 기존 경로나 보관 폴더는 채택하지 않으며 Git 초기화·앱 등록·에이전트 생성은 하지 않는다. 같은 resource ID의 입력 변경을 거부하고, 완료 뒤 replay로 원본을 다시 생성하지 않는다.

다음은 가상 경로·ID다. 허용 루트는 이미 존재해야 하며 소스는 그 바로 아래 새 폴더여야 한다. 기록 디렉터리와 보관 위치는 프로젝트·소스 밖에 둔다.

```sh
python3 scripts/workspace_resources.py \
  --project /path/to/coordinator-project --directory /path/to/private/resources \
  create --resource-id resource_example --request-id request_example --owner backend_example \
  --source /path/to/private-scratch/experiment --allowed-root /path/to/private-scratch \
  --archive /path/to/private-delivery/experiment \
  --purpose '이번 요청의 재현 실험' --authorization '승인된 임시 실험의 보관 후 정리'
```

모든 쓰기 작업이 끝나고 수용 근거를 확정하면 다음 명령을 한 번 호출한다. `--worker`에는 이 폴더를 사용한 모든 배정을 반복 지정한다. 정확한 종료와 열린 파일을 확인한 뒤 빈 디렉터리·바이너리를 포함해 복사하고 목록·크기·해시를 대조한다. 기본 보관 상한은 64 MiB이며 생성 시 `--max-bytes`로 명시 변경한다. Git·심볼릭 링크·하드링크·특수 파일은 보관하지 않고 보존·중단한다.

```sh
python3 scripts/workspace_resources.py \
  --project /path/to/coordinator-project --directory /path/to/private/resources \
  finalize --resource-id resource_example --acceptance /path/to/private/accepted.json \
  --worker task_example/ctx_example
```

보관 뒤 기존 `workspace_cleanup.py prepare/apply`에 같은 수용 근거와 배정을 전달한다. 보관본의 전체 목록·내용·파일 메타데이터와 루트 inode를 고정해 추가 파일·링크와 폴더 교체도 거부한다. 기본 Y는 보관본·경로·등록·종료 검사를 모두 통과해야 원본을 지운다. 정책이 N이거나 `--auto-cleanup N`이면 보관까지만 하고 정리 계획 생성·삭제를 건너뛴다. 이후 명시 Y 재호출은 원본·보관본·수용 근거·배정이 그대로일 때만 가능하다. 프로세스나 앱 프로젝트를 자동으로 종료하지 않는다.

`status --resource-id resource_example`은 해당 비공개 기록만 읽는다. 완료 재호출은 기존 영수증을 대조하며, 원래 경로에 새 폴더가 생겼으면 지우지 않는다. 생성/복사 도중 중단된 기록은 원본과 불완전 보관본을 남기고 명시 점검을 요구한다. 자동 재복사·덮어쓰기·TTL 삭제는 하지 않는다. 등록한 경로와 배정 목록은 조율자의 선언이며 다른 프로세스의 쓰기를 OS에서 차단하는 기능은 아니다.

## 기존 정리 도구와 남은 범위

### 푸시·병합이 끝난 Git worktree

사용자가 완료 worktree 정리를 허용한 범위에서는 조율자가 다음 조건을 확인하고 정리한다. 푸시 또는 PR 병합 표시 하나만으로 삭제하지 않는다.

- 정확한 저장소·host·worktree를 식별한다. 현재 작업 중인 checkout, main worktree, 다른 프로젝트는 제외한다.
- 해당 HEAD가 최신 원격 main에 포함됐는지 확인한다. squash/rebase로 ancestry가 다르면 PR의 정확한 head·병합 결과와 변경 대응을 별도로 확인하며 추정하지 않는다.
- staged/unstaged 변경, untracked 파일, ignored 로컬 설정·보고서까지 확인한다. 보존할 자료는 worktree 밖의 비공개 위치에 복사해 목록·내용 해시를 검증한다. 미커밋 사용자 작업을 자동 폐기하지 않는다.
- worker·대화·터미널·서버와 예약 작업·다른 worktree의 의존성이 남아 있는지 확인한다. done 알림만으로 실행 종료를 가정하지 않는다. 예약 작업의 대상 변경은 별도로 검토한다.
- 설치 버전의 공식 명령과 실제 제거 범위를 확인하고, 제거 직전 HEAD·파일·실행 상태를 다시 대조한다. 기본은 강제 삭제 없이 checkout/앱 등록만 정리하며 브랜치와 대화 기록은 보존한다. 보존 동작을 확인할 수 없으면 유지한다.
- 제거 후 정확한 worktree가 목록·디스크에서 정리됐는지, 브랜치·기록과 보관 자료가 유지되는지 확인하고 결과와 보류 이유를 남긴다.

Orca에서는 정확한 `worktree list` 식별자로 `worktree rm`을 사용한다. 이 명령은 Git checkout을 실제로 제거하므로 단순 탭 숨김으로 설명하지 않는다. `--force`, `--delete-branch`, archive-hook 실패 무시는 기본으로 사용하지 않으며, 전역 cleanup 규칙을 대신 실행하지 않는다. 이 절차는 조율자의 확인 절차이고 자동 Git 병합 감시기가 아니다.

`scripts/workspace_cleanup.py prepare`로 정확한 대상·명시 권한·수용 근거·배정 목록·보관본·파일 해시를 비공개 계획에 저장한다. `apply` 또는 `finish_worker.py --cleanup-plan`은 계획과 실제 상태를 다시 확인한다. 유지할 프로젝트나 아직 기록되지 않은 과거 프로젝트를 자동 삭제 대상으로 추정하지 않는다.

현재 지원하는 앱 등록 해제는 로컬 Orca folder setup이다. Git worktree·원격 host·프로세스 강제 종료는 제외한다. 단계별 재시작과 부분 실패·중단 시 보존 조건은 [완료 처리 사용법](completion.md)에 따른다.
