# 실행 설정


역할별 실행값은 [workflow.json](../workflow.json)에서 관리한다. [실행기](../scripts/workflow.py)는 공통 설정, 대상 프로젝트의 `.ai-workflow.json`, `--local-config`로 지정한 설정 순서로 읽는다. 역할의 책임은 [역할 문서](../roles/README.md)에 둔다.

이 Markdown 파일은 설정 형식과 선택 기준을 설명한다. 값을 바꾸려면 JSON 설정을 수정한다. 실행기는 모델·effort를 Codex CLI 옵션으로 전달하며, 사용할 수 없는 모델을 다른 모델로 자동 변경하지 않는다. 계정·자격 증명·개인 경로는 공개 설정에 넣지 않는다.

## 설정 형식 v1

| 필드 | 값과 적용 방식 |
| --- | --- |
| `version` | 필수 정수 `1` |
| `adapter` | 현재 `codex`만 지원, 생략 시 `codex` |
| `instructions` | 공통으로 전달할 Markdown 경로 배열. 각 설정 계층의 배열을 순서대로 추가 |
| `roles.<ID>.model` | 모델 ID. 예: `gpt-6.1-sol` |
| `roles.<ID>.effort` | `low`, `medium`, `high`, `xhigh`, `max` 중 단일 값 |
| `roles.<ID>.sandbox` | `read-only` 또는 `workspace-write` |
| `roles.<ID>.instructions` | 해당 역할의 Markdown 경로 배열. 상위 설정에 있던 배열을 교체 |

공통 설정은 최소 한 역할을 정의하고, 합쳐진 역할에는 model·effort·sandbox·instructions가 모두 있어야 한다. 프로젝트·개인 설정은 바꿀 필드만 지정한다. 알 수 없는 필드나 역할 ID는 오타로 보고 실패한다. 지원하지 않는 `token_budget` 같은 필드를 넣으면 동작하는 척하지 않고 거부한다.

경로는 해당 JSON 파일의 디렉터리 기준 상대 경로이며 그 디렉터리 안의 Markdown 파일만 허용한다. `../`로 바깥을 참조하거나 바깥을 가리키는 심볼릭 링크는 거부한다. 개인 문서는 별도 디렉터리에 둔 로컬 설정에서 명시적으로 지정할 수 있다. `.ai-workflow.json` 자체의 심볼릭 링크는 허용하지 않는다.

예를 들어 프로젝트의 `project-rules.md`를 추가로 전달하고 백엔드의 effort를 올리려면 대상 프로젝트의 `.ai-workflow.json`을 다음과 같이 작성한다. 먼저 `project-rules.md` 파일이 실제로 존재해야 한다.

```json
{
  "version": 1,
  "instructions": ["project-rules.md"],
  "roles": {
    "backend": {"effort": "high"}
  }
}
```

[JSON Schema](../schema/workflow.schema.json)는 편집기에서 사용할 수 있다. 실행기는 외부 패키지 없이 필드·값·병합 결과·실제 파일 존재 여부를 검사한다. 형식 검증은 선택한 모델의 계정 접근 권한이나 개별 effort 지원 여부를 보장하지 않는다.

## 제공하는 시작 구성

2026-11-09 기준의 설정 예시다. JSON에는 범위 대신 한 실행값을 저장하고, 작업에 따라 프로젝트·개인 설정으로 변경한다.

| 역할 | 기본 모델 | 기본 effort | 조정 조건 |
| --- | --- | --- | --- |
| 조율자 | GPT-6.1 Sol | Low | 작업 분리·예산 재계획·최종 통합 판단은 Medium. 복잡한 충돌은 High 검토 |
| 설계자 | GPT-6 Astra | High | 작은 변경은 Medium, 중요한 신규 설계·복잡한 대안 비교는 Extra High |
| 디자이너 | GPT-6.1 Terra | Medium | 시안·화면 검토를 중심으로 사용하고, 복잡한 흐름·대안 비교는 High |
| 백엔드 개발자 | GPT-6.1 Sol | Medium | 복잡한 동시성·트랜잭션·장애 분석은 High. 범위가 명확한 작은 수정은 Terra와 비교 |
| 프론트엔드 개발자 | GPT-6.1 Sol | Medium | 기능·상태·API 연동을 중심으로 사용하고, 단순 화면 수정은 Terra와 비교 |
| 검증자 | GPT-6.1 Sol | Medium | 복잡한 코드·요구사항·연동 검토는 High. 화면 중심 확인은 Terra, 중요한 설계·보안·동시성 검토는 Astra를 선택적으로 사용 |

모델 식별자는 Sol이 `gpt-6.1-sol`, Terra가 `gpt-6.1-terra`, Astra가 `gpt-6-astra`다. Low/Medium/High/Extra High는 설정에서 각각 `low`/`medium`/`high`/`xhigh`로 지정한다. 도구별 지원 범위와 실제 적용값을 확인한다.

이 표는 공급자의 역할별 성능 보장이나 검증된 최적 설정이 아니다. 개발은 Sol을 시작점으로 사용하고 대표 작업에서 Terra와 필요시 Astra를 비교한다. 디자이너에는 참고 화면·디자인 규칙·실제 구현 화면을 제공하며, 높은 effort만으로 시각 검토를 대신하지 않는다.

## 상향과 하향

- 단순·명확한 작업은 기본값보다 낮출 수 있다. 중요한 요구사항 충돌, 동시성·장애·데이터 위험, 원인 미상의 반복 실패는 더 높은 effort나 다른 모델을 검토한다.
- 실패 원인이 자료 부족·환경·권한 문제인지 먼저 확인한다. 같은 요청을 계속 재시도하거나 모델을 상향하는 것만으로 해결하려 하지 않는다.
- 변경 시 이유와 새 설정을 기록하고, 남은 예산과 예상 사용량을 다시 확인한다. 허용된 전체 한도를 자동으로 늘리지 않는다.
- 높은 effort가 재작업을 줄일 수 있지만 사용량 절감을 보장하지 않는다. 완료까지의 전체 사용량·시간·검증 결과로 판단한다.
- 현재 실행기는 한 역할만 실행하고 지침으로 재위임을 제한하며, `ultra` 설정은 지원하지 않는다. 자동 업무 분배는 후속 범위다. 이 지침을 런타임 수준의 하위 에이전트 차단 기능으로 해석하지 않는다.

## 측정과 예산

- effort, 한 번의 출력 제한, 경과 시간 제한, 작업 전체 토큰 예산은 서로 다르다. 실행기는 [실행별 토큰 수집·선택적 로컬 기록·시간 제한·기록 집계](execution-records.md)를 제공한다. 집계는 지정한 폴더의 기록만 포함하며, 전체 업무의 누락된 사용량 자동 수집과 토큰 예산 강제는 아직 없다. 다음 기준은 기록 해석과 후속 예산 기능에 적용한다.
- 예상 사용량은 작업 유형·범위·모델·effort·유사 실적을 근거로 범위와 불확실성을 함께 제시한다. 허용 예산은 예상치와 별도로 정한다.
- 실제 사용량은 실행 도구가 제공하는 task/attempt/session 등 식별 가능한 기록에서 수집한다. 담당 역할이 추측한 수치를 실측으로 쓰지 않는다.
- 입력·출력·캐시·추론 항목은 공급자의 집계 의미를 확인한다. 이미 입력 또는 출력에 포함된 세부 항목을 다시 더하지 않는다. 누적 이벤트와 상위·하위 에이전트 집계를 중복 합산하지 않는다.
- 실패·재시도·조율·검증·보고·개선도 기록한다. 누락은 0이 아니라 미측정 또는 부분 측정으로 표시한다. 역할별 분리가 안 되면 세션 합계만 보고한다.
- 사용량이 호출 종료 후 제공되는 실행기는 정확한 상한을 보장하기 어렵다. 진행 중 배정량을 고려하고, 한도 도달 시 후속 실행을 중단할 수 있는 실행기 연결이 필요하다.
- 토큰 수, API 비용 추정, 구독 한도 사용량을 구분한다. 품질 기준을 낮추거나 필요한 검증을 생략해 예산을 맞추지 않는다.

실행 기록은 [보고 양식](../templates/task-report.md)을 활용한다. 실제 입력·코드·로그·스크린샷과 개인 설정은 기본 비공개이며, 저장 위치가 정해지지 않았다면 [개인정보 관리 기준](../principles/privacy.md)에 따라 먼저 확인한다.
