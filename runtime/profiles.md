# 모델과 effort 초기 운영안

이 문서는 2026-11-09 기준의 잠정 운영안이다. 역할 책임은 [역할 문서](../roles/README.md)에서, 모델·effort 선택은 여기서 관리한다. 실제 작업으로 품질·사용량·재작업을 비교해 수정한다.

이 파일은 실행 가능한 설정이 아니다. 사용하는 도구에서 지원 모델과 effort를 확인하고 실제 설정에 연결해야 한다. 요청한 설정과 실제 적용된 설정을 구분하며, 사용할 수 없는 모델을 조용히 다른 모델로 바꾸지 않는다. 계정·자격 증명·개인 경로는 공개 문서에 넣지 않는다.

## 역할별 시작점

| 역할 | 기본 모델 | 기본 effort | 조정 조건 |
| --- | --- | --- | --- |
| 조율자 | GPT-6.1 Sol | Low~Medium | 상태 취합·전달은 Low, 작업 분리·예산 재계획·최종 통합 판단은 Medium. 복잡한 충돌은 High 검토 |
| 설계자 | GPT-6 Astra | High | 작은 변경은 Medium, 중요한 신규 설계·복잡한 대안 비교는 Extra High |
| 디자이너 | GPT-6.1 Terra | Medium~High | 시안·화면 검토를 중심으로 사용하고, 복잡한 흐름·대안 비교는 High |
| 백엔드 개발자 | GPT-6.1 Sol | Medium | 복잡한 동시성·트랜잭션·장애 분석은 High. 범위가 명확한 작은 수정은 Terra와 비교 |
| 프론트엔드 개발자 | GPT-6.1 Sol | Medium | 기능·상태·API 연동을 중심으로 사용하고, 단순 화면 수정은 Terra와 비교 |
| 검증자 | GPT-6.1 Sol | Medium~High | 코드·요구사항·연동 검토에 사용. 화면 중심 확인은 Terra, 중요한 설계·보안·동시성 검토는 Astra를 선택적으로 사용 |

모델 식별자는 Sol이 `gpt-6.1-sol`, Terra가 `gpt-6.1-terra`, Astra가 `gpt-6-astra`다. API·CLI에서 지원하는 경우 Low/Medium/High/Extra High를 각각 `low`/`medium`/`high`/`xhigh`로 지정한다. 범위로 표시한 항목은 작업에 맞는 단일 값을 선택한다. 도구별 지원 범위와 실제 적용값을 확인한다.

이 표는 공급자의 역할별 성능 보장이나 검증된 최적 설정이 아니다. 개발은 Sol을 시작점으로 사용하고 대표 작업에서 Terra와 필요시 Astra를 비교한다. 디자이너에는 참고 화면·디자인 규칙·실제 구현 화면을 제공하며, 높은 effort만으로 시각 검토를 대신하지 않는다.

## 상향과 하향

- 단순·명확한 작업은 기본값보다 낮출 수 있다. 중요한 요구사항 충돌, 동시성·장애·데이터 위험, 원인 미상의 반복 실패는 더 높은 effort나 다른 모델을 검토한다.
- 실패 원인이 자료 부족·환경·권한 문제인지 먼저 확인한다. 같은 요청을 계속 재시도하거나 모델을 상향하는 것만으로 해결하려 하지 않는다.
- 변경 시 이유와 새 설정을 기록하고, 남은 예산과 예상 사용량을 다시 확인한다. 허용된 전체 한도를 자동으로 늘리지 않는다.
- 높은 effort가 재작업을 줄일 수 있지만 사용량 절감을 보장하지 않는다. 완료까지의 전체 사용량·시간·검증 결과로 판단한다.
- 초기에는 Ultra를 기본값으로 쓰지 않는다. ChatGPT Work의 Ultra는 최대 추론과 하위 에이전트 위임을 포함하므로, 필요한 병렬 검토인지 확인하고 하위 작업 사용량도 합산한다. 다른 도구에 같은 동작이 있다고 가정하지 않는다.

## 측정과 예산

- effort, 한 번의 출력 제한, 작업 전체 예산은 서로 다르다. 이 문서만으로 토큰 한도를 강제할 수 없다.
- 예상 사용량은 작업 유형·범위·모델·effort·유사 실적을 근거로 범위와 불확실성을 함께 제시한다. 허용 예산은 예상치와 별도로 정한다.
- 실제 사용량은 실행 도구가 제공하는 task/attempt/session 등 식별 가능한 기록에서 수집한다. 담당 역할이 추측한 수치를 실측으로 쓰지 않는다.
- 입력·출력·캐시·추론 항목은 공급자의 집계 의미를 확인한다. 이미 입력 또는 출력에 포함된 세부 항목을 다시 더하지 않는다. 누적 이벤트와 상위·하위 에이전트 집계를 중복 합산하지 않는다.
- 실패·재시도·조율·검증·보고·개선도 기록한다. 누락은 0이 아니라 미측정 또는 부분 측정으로 표시한다. 역할별 분리가 안 되면 세션 합계만 보고한다.
- 사용량이 호출 종료 후 제공되는 실행기는 정확한 상한을 보장하기 어렵다. 진행 중 배정량을 고려하고, 한도 도달 시 후속 실행을 중단할 수 있는 실행기 연결이 필요하다.
- 토큰 수, API 비용 추정, 구독 한도 사용량을 구분한다. 품질 기준을 낮추거나 필요한 검증을 생략해 예산을 맞추지 않는다.

실행 기록은 [보고 양식](../templates/task-report.md)을 활용한다. 실제 입력·코드·로그·스크린샷과 개인 설정은 기본 비공개이며, 저장 위치가 정해지지 않았다면 [개인정보 관리 기준](../principles/privacy.md)에 따라 먼저 확인한다.
