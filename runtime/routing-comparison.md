# 직접 처리와 라우팅의 측정 비교

상태: 기존 native 측정 파일을 읽는 단일 비교 쌍 도구와 가상 자료 검사 구현. v1의 토큰 비교를 유지하고 v2에 [명시 시간·단가 추정](routing-metrics.md)을 선택적으로 연결했다. 실제 직접 처리/라우팅의 짝지은 기록·사용자 또는 독립 품질 평가·절감 효과는 아직 없다. 이 단계가 새 모델·worker 실행이나 자동화 확대를 허용하지 않는다.

`scripts/compare_routing.py`는 두 실행의 **같은 완료 기준·명시한 수집 범위·품질 판정·중복 없는 측정 토큰**을 대조한다. 기존 [worker 기록](native-record.md), [조율자 턴 기록](coordinator-usage.md), [측정 검증과 물리 구간 검사](trace-usage.md)를 재사용한다. DB·원본·설정에 쓰거나 모델·네트워크·worker를 호출하지 않는다. 비교 도구를 매 요청의 라우팅 경로에 넣지 않는다.

## 실제 비교를 준비하는 순서

[비교 준비 묶음](../experiments/routing-pilot/README.md)에 짧은 설명·후속·작은 수정·복합 검토의 실제 사용할 가상 입력과 공통 완료 기준을 준비했다. [평가 양식](../templates/routing-evaluation.md)은 완료 후 작성한 파일을 `quality.evidence`에 연결하며, 빈 양식이나 준비된 기준만으로 품질 pass를 선언하지 않는다. 이 준비 묶음 자체는 비교 실행·모델 선택·추가 worker를 허용하지 않는다.

1. 같은 목표·완료 기준·출처 요구·검증 수준을 한 파일에 확정한다. 직접 처리와 라우팅 처리 모두 이 파일을 사용하고 SHA-256을 고정한다. 결과가 나온 뒤 기준을 낮추지 않는다.
2. 직접 처리와 라우팅 처리의 별도 실제 실행을 연결한다. 모델·effort·캐시 상태·입력 자료·지침 버전·실행 순서 차이를 평가 근거에 기록한다. 새 모델/worker는 구체적인 사용자 선택·한도·권한 준비 후에만 실행한다. 비교를 위해 같은 물리 실행을 두 방식의 결과로 재사용하지 않는다.
3. 추천·선택·본작업·인계·통합·검증·재작업·보고에 사용된 지원 native 턴을 기존 수집기로 기록한다. 현재 모델의 추천 판단이 본응답에 섞여 있으면 턴 전체로 수집하고 임의 비율로 나누지 않는다. 사용자 선택 이후의 조율·보고 누락도 포함한다.
4. 원래 완료 기준으로 결과를 검토하고 근거 파일을 작성한다. 작성 AI의 자체 점검(`self`)과 별도 검토(`independent`)·사용자 평가(`user`)를 구분한다. 사실·공식 출처·분량·이해 가능성·불필요한 추천·오분류·재작업을 평가한다. 평가자의 모델 호출도 비교 범위에 넣었는지 밝힌다.
5. [비공개 비교 양식](../templates/routing-comparison.json)을 채워 명시 호출한다. 지침·예상 절감률·테스트용 숫자를 실제 측정으로 넣지 않는다.

대표 사례는 작은 설명, 같은 주제의 후속 질문, 짧은 수정, 복합 설계 검토부터 고른다. 그림/병렬 준비나 모델 전환의 이점을 볼 때는 별도 승인된 실행 쌍을 추가한다. 쉬운 요청에서 추천·위임을 생략한 경우도 비교 대상이며 worker 생성 자체를 성공 기준으로 삼지 않는다. 한 쌍으로 일반화하지 말고 실행 순서·캐시 차이를 기록하며 유형별 반복 평가로 이어 간다.

## 입력과 보관

```sh
python3 scripts/compare_routing.py \
  --project /private/example/project \
  --manifest /private/example/comparison.json
```

경로는 가상 예시다. 양식의 0으로 된 해시는 자리표시자이며 실제 파일의 SHA-256으로 바꿔야 한다. 기준·품질 근거·측정 파일·manifest는 모두 Git·대상 프로젝트 밖의 소유자 전용 폴더 0700, 파일 0600에 둔다. symlink·비정상 파일·변경 중 파일은 거부하며 파일당 최대 8MiB다. stdout도 비공개 결과로 취급한다. 원본 세션 폴더를 탐색하거나 metadata에 들어 있는 source 경로를 따라 읽지 않는다.

각 `measurements` 항목은 다음과 같은 **기존 수집 파일** 참조다. source 원본의 해시 대신 이 입력 파일 자체의 해시를 사용한다.

```json
{"path":"/private/example/completion/worker.metadata.json","sha256":"실제 파일의 소문자 64자리 SHA-256"}
```

- worker: `kind=orca_codex_metadata`, `dispatch_usage`
- 조율자: `kind=orca_codex_coordinator_turn`, `turn_usage`(기존 version 2/3 포함)

요청 ID·명시 귀속·완료 구간·누적값 차분·증가분·합계를 기존 검사기로 대조한다. measured가 아닌 파일을 0으로 합산하지 않는다. 미측정 파일은 수입하지 말고 해당 단계의 `coverage`를 `missing`으로 남긴다. 측정 파일 참조는 방식당 최대 1,000개이며 같은 요청에 귀속되어야 한다.

## 단계별 수집 범위와 품질

두 방식 모두 아래 여덟 단계에 대해 `included`, `not_applicable`, `missing` 중 하나를 명시한다.

| 단계 | 포함할 범위 |
| --- | --- |
| `routing` | 처리 방식 판단·추천 |
| `selection` | 사용자 선택의 확인·기록·후속 상태 처리 |
| `processing` | 본 설명·개발·조사 |
| `handoff` | 위임 준비·지침 전달 |
| `integration` | 결과 수신·통합 |
| `verification` | 출처·테스트·결과 확인 |
| `rework` | 오류 보완·재시도 |
| `reporting` | 최종 보고·마감 |

`included`는 그 단계의 실행이 제공한 측정 구간에 포함됐다는 호출자의 선언이며 단계별 토큰 분배가 아니다. 여러 단계가 한 턴에 들어 있으면 턴을 한 번만 합산한다. 실제로 없었던 단계만 `not_applicable`로 표시하고, 실행했으나 측정하지 못한 단계는 `missing`으로 둔다. 본작업은 not_applicable일 수 없고 라우팅 방식의 routing도 마찬가지다. 선택·위임을 하지 않았다면 해당 단계는 not_applicable일 수 있다.

품질에는 `status: pass|fail|unverified`, `reviewer: self|independent|user`, 근거 파일 참조가 필요하다. 도구는 파일의 존재·해시와 입력 형식만 확인한다. 자연어 평가 내용의 타당성·평가자의 독립성·수집 완전성을 자동 증명하지 않는다. 따라서 결과도 **선언된 수집 완전성**과 **선언된 품질**로 표시한다. 평가 근거에는 각 단계의 included/not_applicable 판단과 알려진 누락·조건 차이를 함께 설명한다.

## 계산과 판정

- 같은 방식의 정확히 같은 물리 측정 재참조는 한 번만 합산한다. 같은 키의 상충값, 두 방식 사이의 같은 턴, 동일 세션의 겹친 구간·다른 사용량을 가진 동일 dispatch는 거부한다.
- 입력+출력=합계다. 캐시 입력·추론 출력은 이미 포함된 세부값이며 다시 더하지 않는다. 알 수 없는 세부값은 null을 유지하고 안전한 정수 범위를 넘는 합산은 거부한다.
- 측정 파일이 없으면 합계를 0 대신 null로 둔다. 어느 방식이든 missing 단계가 있으면 전체 토큰 차이도 null로 둔다. 부분 합계는 `measured_tokens`로만 표시한다.
- 시간은 병렬 worker 시간을 합치거나 native 구간의 최소/최대 시각으로 요청 전체 시간을 추측하지 않는다. v1의 시간·금액 결과는 null이다. v2는 [별도 근거와 범위](routing-metrics.md)가 있을 때만 시간 차이·토큰 단가 추정을 반환한다. 모델별 가격·캐시 과금이 달라 토큰 감소를 금액 감소로 바꾸지 않는다.

| `decision` | 의미 |
| --- | --- |
| `quality_not_met` | 어느 방식이든 필수 품질 실패. 절감 성공으로 채택하지 않음 |
| `incomplete_measurement` | 측정 없음 또는 알려진 단계 누락. 전체 절감 판정 보류 |
| `needs_quality_review` | 품질 미확인 또는 자체 평가만 있음 |
| `no_token_saving` | 선언된 전체 토큰이 줄지 않음 |
| `candidate_for_repeated_evaluation` | 두 방식 품질 통과·자체 평가 외 검토·선언된 범위 수집과 토큰 감소. 반복 평가 후보일 뿐 자동화 허용이 아님 |

`routed_minus_direct_tokens`는 라우팅−직접 처리다. 모든 결과의 `automation_allowed`는 false다. 검증되지 않은 최적 모델·가격 절감·일반화 정확도·학습 효과를 보고하지 않는다. 이 도구의 출력만으로 설정·허용 범위를 바꾸지 않는다.

## 검증과 다음 단계

18개 검사에서 가상 측정값의 합산·중복 제거, 두 방식의 물리 구간 충돌, worker/조율자 형식, 누락·품질 실패/미확인·자체 검토의 판정, 해시 변경·요청 불일치·카운터 상충/overflow, 비공개 CLI 경계와 읽기 전용 동작을 확인했다. 수치는 코드 검사 전용이며 실제 성능 결과가 아니다.

후속 v2의 신규 지표 검사 25개도 확인했다. 실제 짝지은 기록 수집과 사용자/독립 품질 평가, 여러 사례·반복·조건 차이 분석, 요청 전체 시간·단가 적용의 실제 근거, 이득이 있는 유형에 대한 명시 제한 자동화가 남아 있다. 공식 입력/선택 UI와 현재 대화의 모델 전환 지원은 [통합 개발 순서](../learning/development.md)의 별도 연결 과제다.
