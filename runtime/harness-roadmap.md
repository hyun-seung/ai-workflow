# 하네스 개선 상태와 다음 작업

2026-11-11 기준. 연결 실험·화면 개발·권한 시험에서 반복된 문제를 범용 운영 규칙으로 정리했다. 실제 요청·경로·세션 ID·로그·사용량은 비공개 기록에 보관한다. 이 문서는 제품 기능의 구현 여부와 조율 지침을 구분하며, 목록 전체의 자동 실행을 지시하지 않는다.

## 이번에 반영한 규칙

| 경험에서 드러난 문제 | 적용한 규칙 | 현재 확인 범위 |
| --- | --- | --- |
| 부모와 자식의 승인 모드가 다름 | Orca + Codex 자동화 운영은 대신 승인 활성화·새 worker 실제 적용 확인을 필수 준비로 지정 | 제한된 새 worker에서 실제 설정·파일 작업·정식 검토 후 loopback·결과 반환 확인. 장기 승인 감소는 미검증 |
| 작은 업무도 무거운 기본 프로필로 실행됨 | native 기본값과 요청한 모델·effort를 구분하고 실제값 대조. 미지원 옵션·암묵적 대체 금지 | 기록·판단 지침 반영. 자동 프로필 선택·검사 도구는 없음 |
| 공통 지침·환경 실패를 여러 역할이 다시 조사함 | 준비 근거를 한 번 인계하고 각 worker는 자기 설정 차이·담당 자료만 확인 | 인계 양식·명시 파일 경로/해시 검사 도구 있음. 자동 맥락 선별 없음 |
| 독립 작업까지 한 담당자에게 몰거나 역할을 과하게 나눔 | 같은 수정은 묶고 공통 계약 뒤 독립 작업만 병렬 배정. 동시·누적 한도를 시작 전에 기록 | 수동 운영 규칙. 상한 예약·강제는 미구현 |
| 같은 승인 알림과 사소한 재작업이 반복됨 | 실제 대기 상태와 원본 요청을 확인하고 비차단 보완은 묶어서 전달 | 원본 ID가 확인된 입력의 중복 억제 도구 있음. native pending ID 연결은 미완료 |
| 요청 결과보다 부가 화면 작업이 오래 이어짐 | 원래 요청의 AC·최종 산출물부터 전달. 별도 개선은 후속 요청으로 분리 | 마감·검증 범위 지침 반영 |
| 프로젝트·서버가 남은 이유를 알기 어려움 | 생성 목적·소유권·보관·정리 범위를 처음 정하고 종료 상태 보고 | 수명 관리 지침 있음. 자동 보관·삭제 없음 |

이 규칙은 [운영 가이드](harness.md), [권한 정책](permission-policy.md), [Orca 연결](environments/orca.md), [작업 입력](../templates/task-input.md)에 연결되어 있다. 실제 파일·설정 변경, 에이전트 생성, 결과 수신은 환경의 공식 기능을 사용한다.

## 다음 구현 후보와 완료 기준

우선순위는 현재 반복 문제를 기준으로 한다. 하나를 완료·검증한 뒤 다음을 선택하며, 네이티브 기능을 대체하는 범용 실행기를 먼저 만들지 않는다.

| 순서 | 후보 | 최소 완료 기준 |
| --- | --- | --- |
| 1 | native 실행 메타데이터 확인·비공개 기록 연결 | 명시한 task/dispatch와 세션을 연결해 요청/실제 승인 모드·모델·effort·사용량 출처를 기록. 불일치·누락·자동 검토 세션 혼동·누적 중복을 가상 자료로 검사. 설정 변경·새 worker 생성 없이 기존 결과를 검증하고 다음 승인된 위임에서 확인 |
| 2 | 설정 가능한 위임 상한 연결 | [병렬 정책](parallelism.md)의 동시 worker·누적 배정 한도를 별도 설정으로 읽고 원자적 예약을 수행. 승인 대기·불명 상태·재시도·후속 배정·재시작을 포함해 검사. 관리 경로에서 상한 초과를 막고 직접 CLI까지 통제한다고 주장하지 않음 |
| 3 | 남은 승인 대기 알림 연결 | 설치 버전에서 안정적인 원본 요청 ID·변경 버전을 먼저 확보. 새 대기/동일 대기/해소·재시작·전송 실패를 구분. 수신처와 전송 범위 승인 후 최소 알림만 전송. ID 미확인은 자동 억제하지 않음 |
| 4 | 실행 결과와 조회 기록의 마감 연결 | 한 요청의 조율·구현·검증·후속 배정을 중복 없이 연결. 부분 snapshot·미측정·원본 출처와 마지막 수집 시각 보존. 조회 화면은 수집/실제 실행의 완료와 구분 |
| 5 | 작업 자원 정리 기록·보관 확인 | 생성한 정확한 자원·최종 산출물·정리 권한·종료를 연결. 보관 누락·새 변경·경로 중첩·부분 실패를 확인하고 삭제 권한 없는 자료는 유지. 자동 TTL로 사용자 프로젝트 삭제 금지 |

알림 수신과 휴대폰에서 실제 승인하는 기능은 별도다. 파일/SQLite 선택, 다른 DB 어댑터, 복수 저장소 통합, Paseo 적용은 별도 기능 요청으로 유지한다.

## 효과를 판단할 자료

같은 완료 기준에서 요청 접수부터 결과 전달까지의 경과 시간, 역할 배정 수, 실제 모델·effort, 환경 준비·승인 대기·검증·재작업을 비교한다. 병렬 작업 시간의 합과 전체 경과 시간을 구분한다.

사용량은 [실행 기록 규칙](execution-records.md)에 따라 출처·세션·범위를 남긴다. worker 자체 보고에 측정값이 없더라도 명시적으로 연결된 실행 도구 기록에 값이 있으면 별도 근거로 보완할 수 있다. 캐시 포함 입력을 고유 입력 크기·API 비용으로 바꾸거나 누적 이벤트를 합산하지 않는다. 측정되지 않은 사람 승인 횟수와 대기 시간은 `unavailable`로 둔다.

단순 업무에서 모델·effort를 낮추거나 역할 수를 바꾸는 효과는 비교 가설이다. 속도·토큰만 좋아지고 필수 검증·결과 품질이 낮아지면 개선으로 채택하지 않는다.
