# 하네스 개선 상태와 다음 작업

2026-11-18 기준. 연결 실험·화면 개발·권한 시험에서 반복된 문제와 튜터·요청 라우팅의 진행 범위를 정리했다. 실제 요청·경로·세션 ID·로그·사용량은 비공개 기록에 보관한다. 이 문서는 제품 기능의 구현 여부와 조율 지침을 구분하며, 목록 전체의 자동 실행을 지시하지 않는다.

## 기본 개발 흐름의 현재 상태

[개발 컨트롤러](development-workflow.md)는 프로젝트의 명시 선택과 한도 아래 현재 AI의 의미 판단 → 실행 전 예약 → 개발자 자체 검사 → 독립 검토 → 결과 마감을 연결한다. Orca에서 두 역할의 실제 실행·종료·Stop/SQLite 수입·재처리 불변성을 확인했다. 전체 Python 816개와 독립 코드 재검토를 통과했다. 실제 수정 루프와 전체 사용량 수집은 이번 읽기 전용 실증의 범위 밖이다.

다음은 [Paseo의 공식 생성·재조정 계약 확인](paseo-development-adapter.md)이다. 응답 유실 시 같은 실행을 찾는 근거와 정확한 provider 세션·종료 관측을 확보하기 전에는 adapter를 활성화하지 않는다. Codex·Paseo adapter와 앱 입력 자동 연결은 현재 미지원이며, 공통 지침 연결만으로 활성화되지 않는다.

## 다음 구현 후보와 완료 기준

### 요청 라우팅·사용자 제어의 별도 진행

학습 진입점과 역할·모델/effort 추천 요청을 단계적으로 연결한다. 기존 완료 수집·위임 관리 기능을 자동 라우터가 이미 구현됐다는 뜻으로 확대하지 않는다.

1. **사용자 제어 계약 정의:** [직접 처리·제안·자동 처리, 독립 제어와 범위](request-routing.md), [가상 점검 사례](../examples/request-routing.md)를 작성했다. 지침 검토 단계이며 자연어 분류·실행 검증은 아니다.
2. **추천 전용 로컬 도구 구현:** [request_router.py](request-router.md)는 확정 제어·기존 선택을 먼저 검사하고 필요한 의미 판단은 현재 AI에 맡긴다. 짧은 목록과 제안/추천 없음·충돌 판정을 반환하며 모델 호출·worker 생성·설정 저장은 하지 않는다. [짧은 진입 지침](routing-brief.md)을 연결했다. 앱 입력 연결·자연어 판단 품질·실제 토큰 절감은 미검증이다.
3. 선택·실행 연결 → 모델/effort 지원·실제값 연결 → 동일 완료 기준의 품질·시간·사용량 비교 순으로 확장한다. 각 단계의 완료 기준은 요청 라우팅 계약에 둔다.

이 목록은 기능의 진행 순서이며 모든 단계를 한 번에 구현하거나 앱·지속 선호 설정을 변경하라는 지시가 아니다.

튜터 개발과 남은 라우팅 작업은 [통합 개발 순서](../learning/development.md)를 기준으로 하나씩 진행한다. 역할별 문서 작성과 실제 추천·설명 품질 검증을 구분하며, 다음 단계의 연결 전에 앞 단계의 누락을 보완한다.

[현재 AI 호출형 공통 진입](routing-flow.md)을 추가해 추천·선택·첫 역할 지침·후속 재사용·명시 위임·취소/종료 조회를 연결했다. 신규 흐름 18개·중지 6개와 전체 Python 검사 444개 확인, 독립 코드 검토를 마쳤다. 다음은 [실제 품질·대화 운영, 현재 대화 프로필 지원, 실제 관측/비교, 제한 자동화](../learning/development.md#남은-작업)다. native hook은 공식 검토·승인 및 같은 런타임 조회 경로 확보 전까지 별도 보류하며 같은 시험을 반복하지 않는다.

후속으로 미실행 취소의 슬롯 반환·불명 응답 보존과 공통 `finish`의 명시 원본 수집·프로필 대조·고정한 담당자 DB 수입·비교용 파일 참조를 연결했다. 완료 연결의 신규 21개를 포함한 관련 216개 검사와 독립 재검토를 통과했다. 파일 소유·충돌 검사와 같은 수집의 재시작을 포함하며 실제 측정 쌍·전체 비용/품질 효과는 아직 없다.

피드백 전 준비로 [네 유형의 비교 입력·완료 기준·평가 절차](../experiments/routing-pilot/README.md), [빈 평가 기록](../templates/routing-evaluation.md), [짧은 운영 안내](routing-quickstart.md)를 추가했다. 기능 검사 자료는 정상 구현 1개·결함 구현 6개로 자체 확인했다. 실제 실행·독립 평가·시간/금액 비교·사용자 피드백은 별개로 남아 있으며 추가 실행이나 자동화가 허용된 것은 아니다.

[선택적인 시간·단가 추정 v2](routing-metrics.md)도 구현했다. 요청 접수→최종 응답의 명시 시각과 검증된 관측 모델/캐시 수치·유효 기간·단가 근거만 사용한다. 누락은 전체 차액을 보류하며 청구액을 인증하지 않는다. 신규 25개 포함 관련 102개 검사와 독립 재검토를 마쳤다. 실제 기록·공식 요금 근거·전체 비용/품질 이득은 아직 없다.

입력 연결은 Orca 1.4.257에서 현재 세션용 프로젝트 정의를 실제 시험했으나 수신·신뢰 경로가 확인되지 않아 정의를 제거했다. 전역 hook·OS 권한을 변경하거나 다른 환경으로 대체하지 않았다. 그와 별도로 현재 AI의 명시 호출형 연결을 구현했으며 공식 native 지원 근거가 확보되면 앱의 실제 입력 수신·선택 UI·지침 자동 주입을 검증한다.

기본 인입을 hook의 선행 조건으로 두지 않는다. 연결된 현재 AI가 짧게 판단·대화 선택을 받고 필요한 역할 지침을 읽는 경로로 운영한다. 위 native 연결은 상태 자동 전달·측정 수집의 선택적 고도화이며 현재 대화의 모델/effort 변경은 별도 지원 경로를 확인한다.

별도 opt-in 관리 실행 연결은 앱 자동 라우팅과 구분한다. 사용자가 선택한 Sol/medium으로 현재 worktree의 읽기 전용 worker 한 건을 실행해 역할 수신·요청/실행환경 적용값·같은 operation 재조회·정확한 종료와 관리 활성 0을 확인했다. 공급자 실제 프로필·토큰은 원본 경로와 hook 영수증 부재로 미확인이다. [실제 검증 보고서](routing-integration-check.md)에 근거와 제한을 둔다.

### 기존 실행 연결·기록 기능

첫 단계의 [명시 native 기록 검사](native-record.md), [단발성 완료 처리·임시 공간 정리](completion.md), [하네스 설정·위임 한도](delegation.md)를 구현했다. 조율자가 완료 알림 후 호출하면 정확한 종료 worker를 조회해 기록하고, Y이며 준비된 정리 계획이 있으면 보관본·종료·경로를 대조해 처리한다. 전역 이벤트 hook이나 원본 세션 경로 자동 탐색은 아니다.

한도·정책 검사 27개와 완료·정리 검사 25개가 통과했고, 독립 검토에서 발견한 경로·모순 응답·후속 배정 중복 결함 3건을 수정해 재검토를 통과했다. 실제 Orca에서는 동시 두 배정 뒤 세 번째 보류, 종료 후 두 후속 배정, 새 task/dispatch receipt 연결과 최종 활성 0을 확인했다. 시험에 사용한 숫자는 기본값이 아니며, 속도·사용량 절감 효과는 아직 측정하지 않았다. 다음 표는 그 이후의 연결·자동화와 화면 개선 범위다.

우선순위는 현재 반복 문제를 기준으로 한다. 승인 원본 ID 계약 확인이 필요한 항목은 보류한다. 결과 연결·요청 중심 화면·배정별 수집과 DB 연결, 명시한 여러 메시지·턴의 귀속과 관측 정정을 구현했다. 격리된 중단·복구, 임시 폴더 관리, 초기 단일/병렬 비교, 명시 요청의 일괄 마감과 입력 초안 생성을 확인했다. 다음은 실제 업무의 반복 비교와 수집 범위 확대다. 부분 측정과 요청 전체 수집은 구분한다. 하나를 완료·검증한 뒤 다음을 선택하며, 네이티브 기능을 대체하는 범용 실행기를 먼저 만들지 않는다.

알림 수신과 휴대폰에서 실제 승인하는 기능은 별도다. 파일/SQLite 선택, 다른 DB 어댑터, 복수 저장소 통합, Paseo 적용은 별도 기능 요청으로 유지한다.

승인 대기 연결의 첫 단계는 Orca 대화용 안내 준비까지 구현했다. 관련 21개 검사와 실제 종료 worker의 안내 미생성을 확인했다. 설치 Orca 1.4.256의 공개 CLI에서 안정적인 원본 승인 ID·변경 버전 규약을 확보하지 못했으므로 native pending 자동 중복 억제 완료 기준은 남아 있다. 같은 상태의 알림 메시지 ID를 승인 요청 ID로 사용하지 않으며, 이미 완료된 업무를 다시 실행해 인위적으로 승인을 만들지 않는다.

마감 연결은 명시 입력을 사용하는 CLI·SQLite·조회 화면에 구현했다. 기존 기록 보존·replay·충돌·후속 참조·변경 뒤 재확인을 검사하고, 경로 교체와 재수입 참조 결함을 수정해 독립 재검토를 통과했다. 자동 수집·완료 hook이나 현재 프로세스 종료 확인을 대신하지 않으며, 결과 파일은 수입 시점의 해시로 연결한다.

## 요청별 작업·사용량 대시보드 범위

요청 요약·원문 펼치기·조율자의 계획과 배정·전달 지시·실제 명령 펼치기를 기존 SQLite·조회 화면에 구현했다. 배정별 수집 JSON은 원래 actor 값을 덮어쓰지 않는 추가 관측으로 DB에 연결한다. 명시 수입과 완료 명령의 선택 DB 수입을 지원하며 관측이 없는 과거 담당자는 미측정으로 남는다.

공통 개발·학습 역할의 이름·색상을 고정하고 업무명과 역할을 분리했다. 학습 역할 ID는 사용량 수집·DB 검사·화면 표시에도 연결했다. 사용량 화면은 요청 전체 → 역할별 → 수입된 작업별 → 입력/캐시/출력/추론 세부값으로 펼친다. 파일 읽기·수정 등 개별 도구별 토큰은 현재 귀속 근거가 없어 미수집으로 표시한다. 세션 누적 참고값을 배정별 값으로 복제하지 않으며 검증된 dispatch_usage만 연결한다.

- 검색 없이 최신 요청부터 선택한다. 요청 요약을 먼저 보여 주고 원문은 펼쳐 읽는다. 원래 접수 시각이 없는 과거 기록은 미확인으로 구분하며 수입 시각을 접수 시각처럼 쓰지 않는다.
- 요청별 상단에는 상태, 참여 담당자, 측정된 입력·출력·합계 토큰과 측정 범위를 표시한다. 조율자·검증·재작업도 해당 요청에 귀속되는 경우 포함한다. 에이전트 수와 배정 횟수는 구분한다.
- 본문은 요청 → 조율자가 명시한 처리 계획·분할 이유 → 하위 작업·전달 지시 → 결과 흐름이다. 역할별 카드·색과 확인된 의존 관계를 사용한다. 동시 실행·실행 시간 막대는 실제 시각이 있는 경우에만 표시하고, 시각이 없으면 시간축이 아닌 단계별 흐름으로 표현한다. 전체 경과 시간과 작업별 소요 시간 합계를 혼동하지 않는다.
- 작업을 선택하거나 펼치면 역할·확인 모델, 입력/출력/합계 토큰, 전달 지시, 실제 명령·결과·원문 근거를 볼 수 있다. 긴 명령과 원문은 기본 화면에 모두 나열하지 않으며 모바일에서는 hover 없이도 접근할 수 있게 한다.
- native 기록의 기존 `usage`는 세션 누적 참고값이다. 새 `dispatch_usage`는 확인된 단일 배정 구간의 수치와 명시 요청/역할을 연결한다. 누적값 차감은 시작·종료·기준값과 각 증가분이 원본 호출 수치에 부합할 때만 인정한다. 하나의 native 턴에 여러 작업을 넣거나 식별 없는 후속 대화가 생기면 임의 비율로 나누지 않는다. DB 수입은 이 구간·중복 키를 보존해야 한다.
- 요청 합계에는 중복 없는 귀속 측정값만 포함한다. 일부만 있으면 `측정된 사용량`과 미측정 담당자·작업 범위를 함께 표시하고 전체 합계로 단정하지 않는다. 미측정을 0으로 채우지 않는다. `입력 + 출력 = 합계`이며 캐시 입력·추론 출력은 포함된 세부값으로 다시 더하지 않는다. 원천이 제공한 측정 범위와 수집 시각을 보존한다.

새 요청의 조율자 호출형 흐름은 위 범위에서 확인했다. 남은 기준은 누락된 역할·작업의 수집 완전성, 여러 native 턴의 한 배정 자동 수집, 원천 측정값의 대체·제외 정책과 타 공급자·원격 환경의 완료 연결이다. 다른 저장소 어댑터도 별도 범위다. 현재 단계 카드는 실행 시간·동시성 그래프가 아니다. 사용자 예시 이미지의 역할 수·수치·동시 실행은 테스트 결과나 필수 에이전트 구성으로 사용하지 않는다.

## 효과를 판단할 자료

같은 완료 기준에서 요청 접수부터 결과 전달까지의 경과 시간, 역할 배정 수, 실제 모델·effort, 환경 준비·승인 대기·검증·재작업을 비교한다. 병렬 작업 시간의 합과 전체 경과 시간을 구분한다.

사용량은 [실행 기록 규칙](execution-records.md)에 따라 출처·세션·범위를 남긴다. worker 자체 보고에 측정값이 없더라도 명시적으로 연결된 실행 도구 기록에 값이 있으면 별도 근거로 보완할 수 있다. 캐시 포함 입력을 고유 입력 크기·API 비용으로 바꾸거나 누적 이벤트를 합산하지 않는다. 측정되지 않은 사람 승인 횟수와 대기 시간은 `unavailable`로 둔다.

단순 업무에서 모델·effort를 낮추거나 역할 수를 바꾸는 효과는 비교 가설이다. 속도·토큰만 좋아지고 필수 검증·결과 품질이 낮아지면 개선으로 채택하지 않는다.

여러 메시지의 명시 동일 업무 연결(version 3)과 측정 구간 참조형 논리 작업 묶음, 표준 관측·묶음의 원본 보존 정정은 [구현된 규칙](trace-amendments.md)을 사용한다. 실제 프로필 상위 표시는 [별도 관측 연결](execution-profiles.md)을 사용한다. 명시 그룹과 실제 측정 구간은 [조회 화면](trace-viewer.md#논리-작업과-측정-시간-흐름)에서 확인한다. 자동 귀속·원천 토큰 수정은 별도 후속이다.

완료 시 수집은 [Orca·Codex Stop 연결](completion-hook.md)의 opt-in 경로를 구현하고 로컬 structured worker 한 건의 실제 자동 수입을 확인했다. 공식 plugin의 터미널 상태를 structured worker 완료로 간주하지 않으며, hook 정의 생성/검증과 프로젝트 활성화·신뢰·실제 이벤트 수입 검증을 구분한다. 전체 공급자나 모든 업무의 전역 hook은 아니다.
