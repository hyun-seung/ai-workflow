# 하네스 개선 상태와 다음 작업

2026-11-12 기준. 연결 실험·화면 개발·권한 시험에서 반복된 문제를 범용 운영 규칙으로 정리했다. 실제 요청·경로·세션 ID·로그·사용량은 비공개 기록에 보관한다. 이 문서는 제품 기능의 구현 여부와 조율 지침을 구분하며, 목록 전체의 자동 실행을 지시하지 않는다.

## 이번에 반영한 규칙

| 경험에서 드러난 문제 | 적용한 규칙 | 현재 확인 범위 |
| --- | --- | --- |
| 부모와 자식의 승인 모드가 다름 | Orca + Codex 자동화 운영은 대신 승인 활성화·새 worker 실제 적용 확인을 필수 준비로 지정 | 제한된 새 worker에서 실제 설정·파일 작업·정식 검토 후 loopback·결과 반환 확인. 장기 승인 감소는 미검증 |
| 작은 업무도 무거운 기본 프로필로 실행됨 | native 기본값과 요청한 모델·effort를 구분하고 실제값 대조. 미지원 옵션·암묵적 대체 금지 | 명시 snapshot의 검사·비공개 기록 도구 구현. 자동 프로필 선택·생성 전 제한은 없음 |
| 공통 지침·환경 실패를 여러 역할이 다시 조사함 | 준비 근거를 한 번 인계하고 각 worker는 자기 설정 차이·담당 자료만 확인 | 인계 양식·명시 파일 경로/해시 검사 도구 있음. 자동 맥락 선별 없음 |
| 독립 작업까지 한 담당자에게 몰거나 역할을 과하게 나눔 | 같은 수정은 묶고 공통 계약 뒤 독립 작업만 병렬 배정. 고정 숫자 기본값 없이 작업별 동시·누적 한도 지정 | 관리 경로의 원자적 예약·중복 방지·후속 배정·종료 해제 구현. 직접 CLI나 다른 조율자까지 차단하지 않음 |
| 같은 승인 알림과 사소한 재작업이 반복됨 | 실제 대기 상태와 원본 요청을 확인하고 비차단 보완은 묶어서 전달 | 원본 ID가 확인된 입력의 중복 억제와 Orca 대화용 안내 준비 도구 있음. native pending ID 규약 미확인으로 자동 연결은 보류 |
| 요청 결과보다 부가 화면 작업이 오래 이어짐 | 원래 요청의 AC·최종 산출물부터 전달. 별도 개선은 후속 요청으로 분리 | 마감·검증 범위 지침 반영 |
| 프로젝트·서버가 남은 이유를 알기 어려움 | 생성 목적·소유권·보관·정리 범위를 처음 정하고 종료 상태 보고. 정리 Y/N 선택, 기본 Y | 명시한 로컬 임시 폴더의 보관본 대조·등록 해제·삭제 연결 구현. N이면 정리 계획도 읽지 않음. 전역 탐색·자동 보관·프로세스 종료는 없음 |

이 규칙은 [운영 가이드](harness.md), [권한 정책](permission-policy.md), [Orca 연결](environments/orca.md), [작업 입력](../templates/task-input.md)에 연결되어 있다. 실제 파일·설정 변경, 에이전트 생성, 결과 수신은 환경의 공식 기능을 사용한다.

## 다음 구현 후보와 완료 기준

첫 단계의 [명시 native 기록 검사](native-record.md), [단발성 완료 처리·임시 공간 정리](completion.md), [하네스 설정·위임 한도](delegation.md)를 구현했다. 조율자가 완료 알림 후 호출하면 정확한 종료 worker를 조회해 기록하고, Y이며 준비된 정리 계획이 있으면 보관본·종료·경로를 대조해 처리한다. 전역 이벤트 hook이나 원본 세션 경로 자동 탐색은 아니다.

한도·정책 검사 27개와 완료·정리 검사 25개가 통과했고, 독립 검토에서 발견한 경로·모순 응답·후속 배정 중복 결함 3건을 수정해 재검토를 통과했다. 실제 Orca에서는 동시 두 배정 뒤 세 번째 보류, 종료 후 두 후속 배정, 새 task/dispatch receipt 연결과 최종 활성 0을 확인했다. 시험에 사용한 숫자는 기본값이 아니며, 속도·사용량 절감 효과는 아직 측정하지 않았다. 다음 표는 그 이후의 연결·자동화와 화면 개선 범위다.

우선순위는 현재 반복 문제를 기준으로 한다. 승인 원본 ID 계약 확인이 필요한 항목은 보류하고, 결과 연결·요청 중심 화면·배정별 토큰 수집·DB 연결 및 명시한 조율자 단일 턴의 수집을 구현했다. 새 작은 요청의 조율자 호출형 연결을 확인했으며, 다음은 여러 메시지·실행 턴의 귀속과 관측 정정 계약이다. 역할별 일부 측정이 가능해진 것과 요청 전체 수집이 끝난 것은 구분한다. 하나를 완료·검증한 뒤 다음을 선택하며, 네이티브 기능을 대체하는 범용 실행기를 먼저 만들지 않는다.

알림 수신과 휴대폰에서 실제 승인하는 기능은 별도다. 파일/SQLite 선택, 다른 DB 어댑터, 복수 저장소 통합, Paseo 적용은 별도 기능 요청으로 유지한다.

승인 대기 연결의 첫 단계는 Orca 대화용 안내 준비까지 구현했다. 관련 21개 검사와 실제 종료 worker의 안내 미생성을 확인했다. 설치 Orca 1.4.256의 공개 CLI에서 안정적인 원본 승인 ID·변경 버전 규약을 확보하지 못했으므로 native pending 자동 중복 억제 완료 기준은 남아 있다. 같은 상태의 알림 메시지 ID를 승인 요청 ID로 사용하지 않으며, 이미 완료된 업무를 다시 실행해 인위적으로 승인을 만들지 않는다.

마감 연결은 명시 입력을 사용하는 CLI·SQLite·조회 화면에 구현했다. 기존 기록 보존·replay·충돌·후속 참조·변경 뒤 재확인을 검사하고, 경로 교체와 재수입 참조 결함을 수정해 독립 재검토를 통과했다. 자동 수집·완료 hook이나 현재 프로세스 종료 확인을 대신하지 않으며, 결과 파일은 수입 시점의 해시로 연결한다.

## 요청별 작업·사용량 대시보드 범위

요청 요약·원문 펼치기·조율자의 계획과 배정·전달 지시·실제 명령 펼치기를 기존 SQLite·조회 화면에 구현했다. 배정별 수집 JSON은 원래 actor 값을 덮어쓰지 않는 추가 관측으로 DB에 연결한다. 명시 수입과 완료 명령의 선택 DB 수입을 지원하며 관측이 없는 과거 담당자는 미측정으로 남는다.

공통 6개 역할의 이름·색상을 고정하고 업무명과 역할을 분리했다. 사용량 화면은 요청 전체 → 역할별 → 수입된 작업별 → 입력/캐시/출력/추론 세부값으로 펼친다. 파일 읽기·수정 등 개별 도구별 토큰은 현재 귀속 근거가 없어 미수집으로 표시한다. 세션 누적 참고값을 배정별 값으로 복제하지 않으며 검증된 dispatch_usage만 연결한다.

- 검색 없이 최신 요청부터 선택한다. 요청 요약을 먼저 보여 주고 원문은 펼쳐 읽는다. 원래 접수 시각이 없는 과거 기록은 미확인으로 구분하며 수입 시각을 접수 시각처럼 쓰지 않는다.
- 요청별 상단에는 상태, 참여 담당자, 측정된 입력·출력·합계 토큰과 측정 범위를 표시한다. 조율자·검증·재작업도 해당 요청에 귀속되는 경우 포함한다. 에이전트 수와 배정 횟수는 구분한다.
- 본문은 요청 → 조율자가 명시한 처리 계획·분할 이유 → 하위 작업·전달 지시 → 결과 흐름이다. 역할별 카드·색과 확인된 의존 관계를 사용한다. 동시 실행·실행 시간 막대는 실제 시각이 있는 경우에만 표시하고, 시각이 없으면 시간축이 아닌 단계별 흐름으로 표현한다. 전체 경과 시간과 작업별 소요 시간 합계를 혼동하지 않는다.
- 작업을 선택하거나 펼치면 역할·확인 모델, 입력/출력/합계 토큰, 전달 지시, 실제 명령·결과·원문 근거를 볼 수 있다. 긴 명령과 원문은 기본 화면에 모두 나열하지 않으며 모바일에서는 hover 없이도 접근할 수 있게 한다.
- native 기록의 기존 `usage`는 세션 누적 참고값이다. 새 `dispatch_usage`는 확인된 단일 배정 구간의 수치와 명시 요청/역할을 연결한다. 누적값 차감은 시작·종료·기준값과 각 증가분이 원본 호출 수치에 부합할 때만 인정한다. 하나의 native 턴에 여러 작업을 넣거나 식별 없는 후속 대화가 생기면 임의 비율로 나누지 않는다. DB 수입은 이 구간·중복 키를 보존해야 한다.
- 요청 합계에는 중복 없는 귀속 측정값만 포함한다. 일부만 있으면 `측정된 사용량`과 미측정 담당자·작업 범위를 함께 표시하고 전체 합계로 단정하지 않는다. 미측정을 0으로 채우지 않는다. `입력 + 출력 = 합계`이며 캐시 입력·추론 출력은 포함된 세부값으로 다시 더하지 않는다. 원천이 제공한 측정 범위와 수집 시각을 보존한다.

새 요청의 조율자 호출형 흐름은 위 범위에서 확인했다. 남은 기준은 누락된 역할·작업의 수집 완전성, 여러 native 턴의 한 배정 자동 수집, 원천 측정값의 대체·제외 정책과 자동 완료 연결이다. 다른 저장소 어댑터도 별도 범위다. 현재 단계 카드는 실행 시간·동시성 그래프가 아니다. 사용자 예시 이미지의 역할 수·수치·동시 실행은 테스트 결과나 필수 에이전트 구성으로 사용하지 않는다.

## 효과를 판단할 자료

같은 완료 기준에서 요청 접수부터 결과 전달까지의 경과 시간, 역할 배정 수, 실제 모델·effort, 환경 준비·승인 대기·검증·재작업을 비교한다. 병렬 작업 시간의 합과 전체 경과 시간을 구분한다.

사용량은 [실행 기록 규칙](execution-records.md)에 따라 출처·세션·범위를 남긴다. worker 자체 보고에 측정값이 없더라도 명시적으로 연결된 실행 도구 기록에 값이 있으면 별도 근거로 보완할 수 있다. 캐시 포함 입력을 고유 입력 크기·API 비용으로 바꾸거나 누적 이벤트를 합산하지 않는다. 측정되지 않은 사람 승인 횟수와 대기 시간은 `unavailable`로 둔다.

단순 업무에서 모델·effort를 낮추거나 역할 수를 바꾸는 효과는 비교 가설이다. 속도·토큰만 좋아지고 필수 검증·결과 품질이 낮아지면 개선으로 채택하지 않는다.

여러 메시지의 명시 동일 업무 연결(version 3)과 측정 구간 참조형 논리 작업 묶음, 표준 관측·묶음의 원본 보존 정정은 [구현된 규칙](trace-amendments.md)을 사용한다. 자동 귀속·그룹 전용 화면·실제 프로필 상위 표시·원천 토큰 수정은 별도 후속이다.
