# 여러 프로젝트에서 공통으로 사용하기

개인 Codex 지침에 짧은 연결문을 두면, 서로 다른 프로젝트에서도 ai-workflow 문서를 읽도록 안내할 수 있다. 공통 저장소는 실행 host에 한 번 받아 두고, 프로젝트마다 전체 문서를 복사하지 않는다. 이 설정은 해당 개인 실행 환경의 기본 지침이므로 적용할 범위를 먼저 선택한다.

## 어떤 파일에 넣나요?

| 사용 환경 | 연결 위치 | 적용 범위 |
| --- | --- | --- |
| 기본 Codex | `~/.codex/AGENTS.md` | 기본 Codex home을 사용하는 새 실행 |
| `CODEX_HOME`을 따로 쓰는 Codex | 실제 `CODEX_HOME` 안의 `AGENTS.md` | 해당 home을 사용하는 새 실행 |
| Paseo에서 Codex 사용 | 선택한 host·공급자·계정의 실제 Codex home 안의 `AGENTS.md` | 그 설정으로 실행되는 Codex 세션 |

[공식 Codex 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md.md)는 기본 home을 `~/.codex`로 설명하며 `CODEX_HOME`으로 바뀔 수 있다고 명시한다. 같은 위치에 `AGENTS.override.md`가 있으면 그 파일이 먼저 선택되므로, `AGENTS.md`만 추가해도 적용되지 않을 수 있다. 기존 override를 삭제하거나 덮어써 해결하지 않는다.

[Paseo는 설치된 agent CLI를 실행](https://paseo.sh/docs/providers.md)한다. 계정 전환 도구나 공급자 설정이 별도 Codex home을 지정할 수 있다. 일부 로컬 계정 전환 구성에서는 다음과 같은 경로를 사용한다.

```text
~/.paseo/account-switcher/accounts/<account-id>/codex/AGENTS.md
```

이 경로는 **계정 전환 구성의 예시**이며 모든 Paseo 설치의 공통 경로가 아니다. 다른 사람의 계정 ID를 복사하거나 모든 계정 폴더를 수정하지 않는다. 새 계정·다른 PC·원격 host에서는 실제 경로를 다시 확인한다. 계정 경로가 확인되지 않으면 기본 home과 같다고 추측하지 않는다.

## AI에게 설정 맡기기

공통 저장소를 받은 뒤 아래 경로를 실제 위치로 바꿔 사용 중인 AI에게 보낸다. 설정할 범위를 기본 Codex, 현재 Paseo 계정 또는 둘 다 중에서 명시한다.

```text
내 여러 프로젝트에서 ai-workflow 공통 지침을 사용하고 싶어.
공통 저장소 위치: /absolute/path/to/ai-workflow
적용 범위: 기본 Codex와 현재 Paseo의 Codex 계정

먼저 읽기 전용으로 실제 실행 host와 Codex home을 확인해줘.
환경을 확인할 때는 CODEX_HOME 등 필요한 경로 항목만 확인하고,
인증 파일이나 전체 환경변수·계정 로그는 출력하지 마.
현재 Paseo 계정의 home을 확인할 수 없으면 그 부분은 미확인으로 남겨줘.

공통 저장소의 templates/global-AGENTS.md를 읽고
공통 저장소 경로를 내 실제 경로로 바꾼 최소 연결문을 준비해줘.
해당 home의 기존 AGENTS.md와 AGENTS.override.md를 확인하고,
기존 지침을 보존한 추가안·적용 범위·비공개 백업 위치를 먼저 보여줘.
내 검토 후 선택한 파일에만 적용하고, 새 파일은 소유자 전용 권한으로 만들어줘.
기존 파일의 권한이나 다른 계정·프로젝트는 임의로 변경하지 마.

모델·권한 모드·hook·자동 수집 설정은 이번 지침 연결에 포함하지 마.
적용 뒤에는 실제 파일 내용·권한과 새 대화에서 확인할 방법을 알려줘.
```

확인되지 않은 경로에 계정 폴더를 새로 만들지 않는다. 두 환경이 같은 home을 쓰면 파일을 한 번만 수정한다. 기존 내용과 같은 연결이 이미 있으면 중복 추가하지 않는다. 백업에도 개인 경로가 들어가므로 비공개로 보관한다.

## 직접 연결문을 넣는 경우

[11줄 연결문 양식](../templates/global-AGENTS.md)을 사용한다. `/absolute/path/to/ai-workflow`를 **그 host에서 읽을 수 있는 실제 절대 경로**로 바꾸고, 선택한 home의 `AGENTS.md`에 기존 내용을 보존하여 추가한다. 전체 역할 문서나 기능 설명을 전역 파일에 복제하지 않는다.

새 파일은 macOS/Linux에서 소유자 전용 읽기·쓰기 권한 `0600`을 권장한다. Windows에서는 계정별 파일 접근 권한으로 확인한다. 파일 내용 일치와 권한 검사는 저장 상태를 확인하는 것이며, 실제 실행이 그 파일을 로드했다는 증거는 아니다. 공통 저장소를 이동하면 연결 경로도 갱신해야 한다.

전역 연결문·실제 계정 ID·개인 경로·백업은 공개 GitHub에 올리지 않는다. 공개할 것은 범용 양식과 설정 절차다.

## 새 프로젝트에서 확인하기

선택한 환경에서 **다른 기존 프로젝트의 새 대화**를 열어 다음을 요청한다. 기존 작업 대화를 초기화하거나 앱·daemon을 재시작할 필요는 없다. 지침이 시작 시 로드되는 방식과 현재 앱의 실제 동작은 [공식 지침 검색 규칙](https://learn.chatgpt.com/docs/agent-configuration/agents-md.md)을 참고한다.

```text
파일을 바꾸지 말고 공통 workflow 연결을 확인해줘.
현재 작업 폴더와 대상 프로젝트 지침을 확인하고,
전역 연결문이 제공됐는지와 공통 AGENTS.md·projects/README.md를
실제로 읽었는지 구분해서 알려줘.
이 프로젝트에 적용할 공통 원칙 세 가지를 설명하고,
공통 저장소 자체의 테스트 명령을 이 프로젝트에 그대로 적용하지 마.
읽을 수 없는 문서가 있으면 미확인으로 남겨줘.
```

확인할 것은 현재 프로젝트 유지, 전역 연결문 수신, 공통 두 문서의 실제 읽기, 프로젝트 고유 규칙과 검증 명령의 구분이다. 다른 프로젝트 시험 전에는 “여러 프로젝트 적용 검증 완료”라고 하지 않는다. 계정 전환이나 host 변경 뒤에도 이 확인을 반복한다.

## 전체 기능 연결과의 관계

전역 연결은 AI가 공통 문서를 찾는 진입점이다. 공통 `AGENTS.md`의 요청 판단·필요한 역할과 검증 기준을 사용할 수 있게 한다. 프로젝트별 지침과 상위 정책은 계속 적용된다. 전체 역할을 매 입력마다 읽거나 새 에이전트를 자동 생성하는 설정이 아니다.

실제 위임 한도·실행 권한·비공개 DB·hook 신뢰·사용량 수집·결과 교환은 [프로젝트 전체 연결 절차](project-onboarding.md)에서 기능별로 준비하고 검증한다. 지침 파일 두 개를 만들었다는 이유로 모든 기능의 설치가 끝났다고 표시하지 않는다.

변경을 해제할 때는 백업과 현재 내용을 대조해 자신이 추가한 연결문만 제거한다. 기존 지침·계정 home·인증 파일·프로젝트는 삭제하지 않는다.
