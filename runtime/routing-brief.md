# 요청 판단 요약

작은 요청·변경 이점이 불분명한 요청은 현재 AI·설정으로 답한다. 라우팅 전용 AI를 추가 호출하지 않는다. 역할 적용·모델·effort·위임은 별개이며 명시 제어를 우선한다. 같은 작업의 후속 질문은 유효한 선택을 재사용한다. 직접 처리에는 라우팅 안내를 붙이지 않는다.

단순 개념 질문은 [짧은 튜터 지침](../learning/tutor-brief.md)으로 바로 설명할 수 있다. 이 경우 실행 변경을 추천하려고 `role=tutor` 후보를 의무적으로 만들지 않는다. `recommendation=null`은 실행 변경 제안이 없다는 뜻이며 쉬운 설명이나 출처 확인을 생략하라는 뜻이 아니다. 사용자가 직접 처리·역할 고정을 지정한 경우 그 선택을 우선한다.

새 복합 요청의 추천이 필요할 때만 `python3 scripts/request_router.py catalog`로 짧은 목록을 확인한다. 설정값은 추천의 시작점이며 현재 실행값·최적값·사용 가능 보장이 아니다. 모든 역할 문서를 미리 읽지 않는다. 현재 AI가 범위·이점·입력 부족을 판단하고, 변경 이유가 있을 때만 하나의 짧은 제안을 만든다. 쉬운 작업은 가벼운 설정 후보, 복잡한 추론은 상향 후보지만 절감·품질을 보장하지 않는다. 역할 기본 프로필을 자동 적용하지 않는다.

구조화된 제어·분석 결과는 `scripts/request_router.py route`로 검사할 수 있다. 의미 분석·제어의 자연어 해석은 현재 AI가 맡으며 도구가 원문을 자동 분류하지 않는다. 도구의 제안·기존 선택 재사용은 실행이나 승인이 아니다. 자동 위임·모델 변경·영구 저장은 하지 않는다. 모호한 동의는 실행 근거로 쓰지 않는다. 상세한 범위·충돌·취소를 판단해야 할 때만 [제어 계약](request-routing.md)과 [입출력](request-router.md)을 확인한다.
