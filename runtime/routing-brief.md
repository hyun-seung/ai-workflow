# 요청 판단 요약

작은 요청·변경 이점이 불분명한 요청은 현재 AI·설정으로 답한다. 라우팅 전용 AI를 추가 호출하지 않는다. 역할 적용·모델·effort·위임은 별개이며 명시 제어를 우선한다. 같은 작업의 후속 질문은 유효한 선택을 재사용한다. 직접 처리에는 라우팅 추천 안내를 붙이지 않으며, 답변 끝의 짧은 [적용 상태 표시](workflow-status.md)는 공통 지침을 따른다.

독립 구현·검토가 필요한 개발 요청은 현재 AI가 판단한 뒤 [개발 진입](development-workflow.md#명시적-개발-진입과-보고)의 `development_workflow.py entry`를 호출한다. 정책 존재와 명시 수용 기록은 별개이며 미수용은 opt_in_required로 최초 프로젝트 범위·한도를 선택한다. 수용된 동일 범위는 재사용한다. native 미확인은 native_check_required로 공식 도구를 확인하고, 확인된 부재만 unavailable로 남긴다. 유효한 요청/선택은 재시작·후속 질문에서도 재사용하고 변경된 범위는 명시적으로 재설정한다. 지원된 Orca 경로는 entry → begin/next → reserve → 공식 guard 실행 → attach/complete → 독립 검토 → report로 연결한다. 직접 처리·위임 금지가 우선하며 원래 독립 검토 기준과 충돌하면 보고에 남긴다. 대화와 작은 수정은 상태·모든 역할 로딩이 필요 없다. 현재 AI의 명시 호출이며 앱 입력 자동 연결은 미구현이다.

단순 개념 질문은 [짧은 튜터 지침](../learning/tutor-brief.md)으로 바로 설명할 수 있다. 같은 목표의 꼬리 질문에도 설명·필요한 시각화 기준을 유지하며 direct/reuse를 튜터 중단으로 해석하지 않는다. 이 경우 실행 변경을 추천하려고 `role=tutor` 후보를 의무적으로 만들지 않는다. `recommendation=null`은 실행 변경 제안이 없다는 뜻이며 쉬운 설명이나 출처 확인을 생략하라는 뜻이 아니다. 사용자가 직접 처리·역할 고정을 지정한 경우 그 선택을 우선한다.

새 복합 요청의 추천이 필요할 때만 `python3 scripts/request_router.py catalog`로 짧은 목록을 확인한다. 설정값은 추천의 시작점이며 현재 실행값·최적값·사용 가능 보장이 아니다. 모든 역할 문서를 미리 읽지 않는다. 현재 AI가 범위·이점·입력 부족을 판단한다. 필수 자료가 없으면 그 자료부터 확인하고 역할 승인·모델 상향으로 대신하지 않는다. 변경 이유가 있을 때만 하나의 짧은 제안을 만든다. 쉬운 작업은 가벼운 설정 후보, 복잡한 추론은 상향 후보지만 절감·품질을 보장하지 않는다. 역할 기본 프로필을 자동 적용하지 않는다.

구조화된 제어·분석 결과는 `scripts/request_router.py route`로 검사할 수 있다. 의미 분석·제어의 자연어 해석은 현재 AI가 맡으며 도구가 원문을 자동 분류하지 않는다. 도구의 제안·기존 선택 재사용은 실행이나 승인이 아니다. 자동 위임·모델 변경·영구 저장은 하지 않는다. 모호한 동의는 실행 근거로 쓰지 않는다. 상세한 범위·충돌·취소를 판단해야 할 때만 [제어 계약](request-routing.md)과 [입출력](request-router.md)을 확인한다.

추천·명시 선택·취소를 실제로 기록하고 연결할 때는 [공통 진입 흐름](routing-flow.md)을 사용한다. 현재 AI가 자연어를 해석해 `scripts/routing_flow.py`에 전달하며 첫 수용에만 선택한 역할 지침을 받는다. 일반 입력마다 도구나 이 상세 가이드를 읽지 않는다.

프론트/백엔드/혼합 개발의 새 명시 계획은 [v3 계획 계약](development-workflow.md#명시-역할-계획-선택적-v3)을 사용한다. AI가 구현 순서·fresh/reuse/none 시안·사람 선택 필요·화면 검토를 명시해 Entry에 전달하며 유효한 선택을 재사용한다. 사람 선택 gate는 시안 결과 뒤, 구현 예약 앞이다. 역할 관점·재사용 산출물·실제 별도 실행을 구별하고 화면 검토는 독립 기능 검토를 대체하지 않는다. 기존 v2는 수정하지 않는다.
