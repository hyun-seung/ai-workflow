# 실행 사용량과 로컬 기록

실행기는 한 역할의 `codex exec --json --ephemeral` 출력을 읽고 종료 시 측정 가능한 토큰 수를 stderr에 표시한다. 최종 에이전트 메시지는 stdout으로 출력한다. 원시 이벤트와 도구 출력은 파일에 보관하지 않는다. 추가 Python 패키지나 DB는 필요하지 않다.

## 저장과 업무 연결

저장은 기본적으로 꺼져 있다. 사용자가 선택한 비공개 위치를 `--records-dir`로 명시하면 실행마다 UUID 이름의 JSON 파일을 남긴다. 공통·프로젝트 설정 파일에서 저장을 자동 활성화하지 않는다.

아래 경로와 시간 제한은 예시다. 실제 보관 위치와 실행 제한을 정한 뒤 바꿔 사용한다. ai-workflow 디렉터리에서 실행하고 작업 요청은 표준 입력으로 전달한다. 실제 모델 호출에는 계정 사용량이 발생한다.

```sh
python3 scripts/workflow.py run \
  --project /path/to/project \
  --role backend \
  --task-id TASK-001 \
  --parent-task-id WORK-001 \
  --task-type development \
  --records-dir /path/to/private/ai-workflow-runs \
  --result-ref reports/TASK-001.md \
  --timeout-seconds 300 \
  --task -
```

먼저 `--dry-run`을 추가하면 모델 호출이나 폴더·기록 생성 없이 설정을 확인할 수 있다.

| 값 | 의미 |
| --- | --- |
| `--task-id` | 동일 업무의 재시도에서 유지할 비민감 식별자. 생략하면 실행 UUID 사용 |
| `run_id` | 시도마다 새로 생성. 이전 시도의 기록을 덮어쓰지 않음 |
| `--parent-task-id` | 기존 입력 양식의 상위 업무 ID. 여러 담당 작업을 연결하는 선택 항목 |
| `--task-type` | `development`, `research`, `design-review`, `writing` 중 선택 |
| `--result-ref` | 별도로 관리하는 결과 보고서·산출물 참조. 여러 번 지정 가능 |
| `--timeout-seconds` | 양수인 실행 경과 시간 제한. 생략하면 시간 제한 없음 |

입력 Markdown의 `task_id`, `parent_task_id`, `task_type`과 같은 값을 전달한다. 실행기가 Markdown 내용을 자동 추출하거나 일치 여부를 확인하지 않는다. ID에는 이름·고객번호·회사명을 넣지 않는다. 자기 자신을 부모로 지정하는 것은 거부하지만 전체 업무 관계의 존재·순환 여부까지 검증하지는 않는다.

`--result-ref`는 저장을 활성화했을 때만 사용할 수 있다. 실행기가 참조 파일을 읽거나 만들거나 존재 여부를 검증하지 않는다. 상대 참조의 기준은 사용자 보고 규칙에서 정한다. 결정·검증 내용은 [작업 결과 양식](../templates/task-result.md)에 작성하고 이 참조로 연결한다.

기록 형식은 [JSON Schema](../schema/run-record.schema.json), 공개 가능한 예시는 [가상 기록](../examples/run-record.json)을 따른다. 저장 형식의 스키마가 업무 결과의 자동 검증을 뜻하지는 않는다.

## 보관 범위와 개인정보

작업·상위 업무·실행 ID, 작업 유형, 역할, 요청한 모델·effort·sandbox, 확인 가능한 CLI 버전, 시간 제한, 시작·종료 시각, 소요 시간, 실행 상태, 사용량과 명시한 결과 참조를 남긴다. 실제 모델·effort는 현재 이벤트에서 확인하지 못하므로 `observed`에 `null`을 기록한다.

요청 원문, 지침 본문, 코드, 모델 응답 본문, 도구 로그, 오류 원문, 프로젝트 절대 경로, 인증 정보는 자동 저장하지 않는다. 결정·검증 보고서도 자동 생성하지 않는다. ID·참조 자체에 민감한 내용을 넣지 않도록 한다.

- 저장 위치는 템플릿·대상 프로젝트 밖이어야 하며, 상위 경로에 `.git`이 있는 Git 작업 트리도 거부한다. 심볼릭 링크는 실제 경로로 검사한다.
- POSIX에서는 새 폴더를 `0700`, 기록 파일을 `0600`으로 만든다. 기존 저장 폴더는 현재 사용자 소유이고 다른 사용자에게 권한이 없어야 한다. 기존 폴더 권한을 임의로 바꾸지 않는다.
- 이 검사는 공개 실수를 줄이는 방어다. 암호화, 백업, ACL, 동기화 서비스나 같은 사용자로 실행하는 다른 도구의 접근까지 보장하지 않는다. Windows에서는 ACL을 별도로 설정한다.
- 보존 기간·삭제·다른 PC로의 이동은 자동 처리하지 않는다. 사용자가 보관 정책을 정한다.
- CLI stderr에는 민감한 오류가 있을 수 있다. 터미널·CI 로그, 도구와 외부 서비스의 기록은 이 실행기의 저장 정책 범위 밖이다.

## 실행 상태와 중단

| `execution_status` | 의미 |
| --- | --- |
| `running` | 모델 실행 전의 초기 기록. 비정상 종료 후 남아 있을 수도 있음 |
| `succeeded` | 자식 프로세스 종료 코드 0과 `turn.completed`를 확인함 |
| `failed` | 호출·입출력·프로세스 실패 또는 성공 이벤트 누락 |
| `interrupted` | Ctrl+C 또는 SIGTERM 종료 요청을 처리함 |
| `timed_out` | 지정한 실행 경과 시간 제한에 도달함 |

`task_verification`은 항상 `not_evaluated`다. 실행 성공은 업무 완료 기준 통과를 뜻하지 않는다.

기록을 활성화하면 실행 전에 초기 파일을 쓰고 종료 시 같은 파일을 원자적으로 교체한다. 초기 저장 실패 시 모델을 호출하지 않는다. 최종 저장 실패 시 오류와 종료 코드 2를 반환한다. 이미 작업했을 수 있으므로 자동 재실행하지 않는다. SIGKILL·전원 차단·최종 저장 실패 시 `running` 기록이 남을 수 있다. 작업 재개나 자동 복구는 아직 없다.

macOS/Linux에서는 별도 프로세스 그룹으로 실행한다. Ctrl+C·SIGTERM·시간 초과 시 해당 그룹에 종료 신호를 보내고, 유예 시간 이후 남은 프로세스를 강제 종료한다. 다른 세션으로 분리된 프로세스나 원격 서버에서 이미 처리 중인 요청까지 종료를 보장하지 않는다. Windows는 직접 자식 종료만 구현되어 있으며 하위 프로세스 전체 정리까지 검증하지 않았다.

시간 제한에는 실행 준비 시간이 포함되며 CLI 버전 확인·종료 정리로 지정 시간을 초과할 수 있다. **시간 제한은 토큰 상한이 아니며, 이미 사용한 토큰을 취소하지 않는다.** 사용량 이벤트를 받지 못한 종료는 미측정으로 남긴다.

| 실행기의 반환 코드 | 의미 |
| --- | --- |
| 0 | 실행 성공 및 요청한 기록 저장 성공 |
| 2 | 설정·수집기·저장 오류 또는 성공 이벤트 누락 |
| 124 | 실행 시간 초과 |
| 130 | Ctrl+C / SIGINT |
| 143 | SIGTERM |
| 기타 | Codex의 비정상 종료값. 신호 종료는 `128 + 신호 번호`로 변환 |

JSON의 `exit_code`는 자식 프로세스의 종료값으로, 실행기의 반환 코드와 다를 수 있다. POSIX 신호 종료는 음수다. 설정·경로·CLI 설치 검사에서 거부된 요청은 실행 기록을 생성하지 않는다.

## 사용량 해석

Codex의 `turn.completed.usage`에서 수치를 읽는다. **`total_tokens = input_tokens + output_tokens`**다. 캐시 입력과 추론 출력은 각각 입력·출력의 세부값이므로 다시 더하지 않는다. 제공하지 않는 값은 `null`로 남긴다.

| `usage.status` | 의미 |
| --- | --- |
| `measured` | 성공한 단일 실행의 입력·출력 수치를 확인함. 선택 세부값은 없을 수 있음 |
| `partial` | 일부 수치만 확인했거나 실패·중단·잘못된 이벤트·복수 턴 등 범위 제한이 있음 |
| `unavailable` | 유효한 사용량 수치를 받지 못함. 0 사용과 다름 |

같은 종료 이벤트를 다시 받아도 합산하지 않는다. 여러 턴이나 서로 다른 종료 수치가 나오면 마지막 보고 스냅샷만 보관하고 `partial` / `last_reported_turn`으로 표시한다. 이를 전체 실행 합계로 사용하지 않는다. 실패 중 미보고 사용량이나 별도 에이전트·실행기 밖의 조율·검증·보고 비용도 자동 포함하지 않는다.

잘못된 JSON과 8 MiB 초과 이벤트는 본문을 보관하지 않고 건너뛴다. 유효한 수치가 있더라도 `partial`로 표시한다. 큰 에이전트 메시지가 건너뛰어지면 최종 메시지도 누락될 수 있으므로 결과를 별도로 확인한다.

입력 토큰 합계는 고유한 파일 내용의 분량이 아니다. 도구 사용을 거치는 동안 지침·대화·결과가 모델 입력에 반복 포함될 수 있다. 캐시 입력도 입력 합계의 일부다. 이 종료 이벤트만으로 파일별 사용량이나 모델 호출별 내역을 역산할 수는 없다.

토큰 수는 API 청구 금액·구독 한도 소비율과 같지 않다. 가격 환산, 누락된 사용량의 자동 수집, 토큰 예산 강제, 자동 재시도, DB는 후속 범위다. `--ephemeral`은 Codex 세션 기록에 관한 옵션이며 모든 도구·서비스의 보관을 차단하지는 않는다.

## Orca 등 native 세션의 별도 근거

명시한 로컬 Orca/Codex 세션과 선택 worker snapshot의 대조는 [native 기록 도구](native-record.md)로 수행할 수 있다. 실제 시작 요청, 검사 기대값, 적용값을 구분하고 비공개 JSON으로 저장한다. live 조회·새 에이전트 생성·자동 DB 수입은 하지 않는다.

위 단독 실행기의 기록과 native 세션 자료는 수집 경로가 다르다. worker의 자체 보고가 `unavailable`이어도 명시적으로 연결된 실행 도구의 기록에 측정값이 있다면 조율자가 출처를 붙여 보완할 수 있다. 기존 자체 보고는 덮어쓰지 않고 측정한 범위와 시점을 별도로 남긴다. 현재 `workflow.py`나 조회 화면이 이 자료를 자동 수집하지는 않는다.

로컬 Codex 원본 기록에서 확인할 경우 해당 task/dispatch에 대응하는 세션을 먼저 특정한다. `session_meta`의 식별자·출처, `turn_context`의 설정, `event_msg` 중 `token_count`의 수치처럼 필요한 메타데이터만 사용한다. 이 구조는 확인한 CLI 버전의 보조 근거이며 모든 공급자의 공통 계약이 아니다. 누락·형식 변경·출처 불일치는 미확인으로 남기고 전체 대화·내부 추론을 복사하지 않는다.

`total_token_usage`가 세션 누적값이면 마지막 유효 snapshot을 한 번 기록한다. 중간 누적 이벤트를 더하거나 같은 세션을 공유한 여러 배정에 총량을 복제해 합산하지 않는다. 캐시 입력·추론 출력의 포함 관계와 수집 종료 시점을 표시한다. 별도 자동 승인 검토 세션은 역할 worker와 구분하며, 조율자·검토자의 측정을 확보하지 못하면 전체 요청 합계라고 보고하지 않는다.

[native 기록 검사기](native-record.md#배정-구간의-사용량)는 기존 누적 참고값과 별도로 닫힌 단일 native 턴의 `dispatch_usage`를 기록한다. 누적 기준값과 원본 `last_token_usage`를 대조하고, 조율자가 명시한 요청 ID·역할과 연결된 경우에만 요청별 귀속을 인정한다. 동일 물리 구간의 측정 키는 파일·요청 이름을 바꿔도 유지하며, DB 수입과 여러 역할 합산은 별도다. 파일 읽기·수정 등의 도구별 사용량으로 해석하지 않는다.

## 필요한 자료를 함께 전달하기

작업 범위가 좁고 필요한 자료가 정해져 있다면 `--context-file`을 반복해 파일이나 줄 범위를 전달한다. 대상 프로젝트 안의 UTF-8 텍스트만 허용한다. 줄 번호는 1부터 시작하며 끝 번호를 포함한다.

```sh
python3 scripts/workflow.py run \
  --project /path/to/project --role verifier \
  --context-file src/example.py:10:40 \
  --context-file tests/test_example.py \
  --task - --dry-run
```

이 예시는 표준 입력으로 작업 요청을 받는다. `--dry-run`은 본문을 출력하거나 모델을 호출하지 않고 전달할 문자 수 등을 확인한다. 실제 실행에는 이를 제거한다.

- 경로만 알려주는 방식과 달리 지정한 내용을 실행 전에 읽어 프롬프트에 포함한다. 충분한 자료가 있으면 다시 읽지 않도록 지시하고, 불충분하거나 변경된 내용은 필요한 부분을 확인하도록 한다.
- 공통·프로젝트·역할 지침은 유지한다. 전달한 코드는 작업 자료이며 상위 지침을 대체하지 않는다. 비공개 파일을 지정하는 경우 해당 모델에 전달해도 되는 자료인지 먼저 확인한다.
- 최대 8개 지정, 파일 하나당 64 KiB, 선택한 원문 합계 64 KiB까지다. 큰 파일의 일부를 지정해도 원본 파일 제한은 적용된다. 동일 파일·동일 줄 범위는 한 번만 전달한다. 겹치는 서로 다른 범위는 자동 병합하지 않는다.
- 자동 자료 선택이나 저장소 전체 인덱싱은 하지 않는다. 초기 입력이 커질 수 있으므로 관련 없는 파일을 넣지 않는다. 줄 번호는 현재 작업 사본 기준이며 수정 후 다시 확인한다.
- 같은 코드·지침·모델·effort·완료 기준에서 참조만 전달한 실행과 내용을 함께 전달한 실행을 비교한다. 캐시 상태와 모델 동작은 달라질 수 있으므로 한 번의 차이를 보장된 절감률로 해석하지 않는다. 품질·미검증·재작업도 함께 확인한다.

## 본문 없는 진단 정보

새 기록의 `diagnostics`는 프롬프트 문자 수와 이벤트 건수만 보관한다. 기존 기록에 이 필드가 없어도 집계할 수 있으며, 과거 값은 추정해 채우지 않는다.

| 항목 | 의미와 한계 |
| --- | --- |
| `prompt.prompt_characters` | 실행기가 표준 입력으로 전달한 전체 문자 수. Codex의 시스템·도구 정의·자동 지침이나 이후 대화는 포함하지 않음 |
| `instruction_files`, `instruction_characters`, `task_characters` | 직접 전달한 지침 파일 수·지침 문자 수·요청 문자 수. 포맷 문자 때문에 부분 합계가 전체와 같지 않을 수 있음 |
| `inline_context_sources`, `inline_context_characters` | 명시한 자료 범위 수와 원문 문자 수. 줄 번호·제목 등 추가 포맷은 원문 문자 수에 포함하지 않음 |
| `events.completed_items` | `item.completed` 유형별 건수. 같은 ID는 한 번만 집계하고 알 수 없는 유형은 `other`로 처리 |
| `events.completed_tool_items` | 명령 실행·MCP·웹 검색의 완료 이벤트 합계. 파일 읽기 횟수나 명령 안의 하위 작업 수가 아님 |
| `events.model_calls` | 현재 확인할 수 없으므로 항상 `null` |

문자 수를 토큰 수로 바꿔 실측으로 보고하지 않는다. 이벤트 상태는 실행 전 `not_started`, 성공·스트림 종료·이상 없음이면 `observed`, 중단·누락·ID 없음 등은 `partial`이다. 완료되지 않은 도구 작업은 포함되지 않는다. 실제 명령·파일 경로·본문·이벤트 ID는 저장하지 않는다.

## 로컬 기록 집계

```sh
python3 scripts/workflow.py summary \
  --records-dir /path/to/private/ai-workflow-runs \
  --parent-task-id WORK-001 \
  --execution-status succeeded
```

모델 호출이나 파일 생성·수정 없이 지정 폴더 바로 아래의 JSON 기록을 읽는다. `--task-id`, `--parent-task-id`, `--role`, `--execution-status`는 선택 필터이며 함께 사용하면 모두 충족하는 기록을 고른다(AND 결합). `--execution-status`는 `running`, `succeeded`, `failed`, `interrupted`, `timed_out` 중 단일 값을 허용하며 잘못된 값은 종료 코드 2로 거부한다. 생략하면 모든 실행 상태를 포함한다. 상위 ID 필터는 직접 연결만 선택하고 자손 작업이나 부모 본체의 기록까지 자동 포함하지 않는다. `--json`으로 같은 선택 집계 결과를 JSON으로 출력할 수 있다. 필터와 관계없이 폴더 전체를 먼저 검사하고 중복·충돌을 판정하며, 같은 `run_id`의 일부 기록만 필터에 일치해도 충돌한 실행 전체를 제외한다.

- 역할·**요청한** 모델·effort별 실행 수, 실행 상태·사용량 상태, 측정 완료 토큰, 확인된 누적 시간을 표시한다. 실제 모델 확인이나 업무 완료 판정은 하지 않는다.
- `measured` 사용량만 토큰 합계에 넣고 `partial`·`unavailable` 건수를 별도로 표시한다. 완전 측정이 하나도 없으면 합계는 `null`이다. 이것을 전체 비용이 0이라고 해석하지 않는다.
- 캐시 비율은 캐시 상세가 있는 `measured` 실행의 입력만 분모로 사용한다. 캐시 미제공을 0으로 간주하지 않는다. 시간 합계는 각 실행 시간의 합이며 병렬 업무 전체 경과 시간과 다르다.
- 같은 `run_id`와 같은 내용의 복사본은 한 번만 센다. 같은 ID의 내용이 충돌하면 해당 실행 전체를 제외한다. 같은 `task_id`라도 별도 `run_id`인 재시도는 모두 포함한다.
- 잘못된 JSON·중복 키·1 MiB 초과 파일·지원하지 않는 스키마·심볼릭 링크·충돌은 건수로 알리고 종료 코드 2를 반환한다. 파일명이나 오류 원문은 출력하지 않는다. 전체 JSON Schema를 검증하는 기능은 아니며 집계에 필요한 필드와 수치 일관성을 확인한다.
- 기록이 누락된 실행, 실행기 밖에서 수행한 조율·검증·보고, 다른 폴더의 데이터는 포함하지 않는다. 오래된 기록의 진단 정보는 미측정으로 표시한다.

Python에서 `run_summary.summarize(directory, ..., execution_status=...)`를 직접 호출할 때도 `None` 또는 위 다섯 상태 문자열만 허용한다. 잘못된 문자열이나 비문자열 값은 디렉터리 검사·파일 접근·집계 전에 `ValueError`로 거부한다.

## 검증과 첫 실제 업무

모의 Codex 프로세스로 정상·실패·신호 종료·시간 초과·이벤트 누락·중복·잘못된 수치·저장 오류·민감한 본문 제외를 검증한다. 라이브 모델과 실제 업무 품질은 별도 실험에서 확인한다.

첫 실험은 비공개 보관 위치를 정한 후 작고 명확한 업무 하나로 진행한다. 사용 CLI 버전, 기준 코드·지침 버전과 미커밋 변경, 업무 완료 기준을 결과 보고서에 기록한다. 완료 시 실행 기록의 `run_id`와 `usage`, 결과물, 검증 근거를 함께 확인한다. 전체 역할을 한꺼번에 호출할 필요는 없다.

참고: [OpenAI 공식 비대화형 실행 문서](https://learn.chatgpt.com/docs/non-interactive-mode)의 JSONL 이벤트·사용량 예시와 `--ephemeral`, [공식 사용량 설명](https://developers.openai.com/api/docs/guides/agents-api/observability)의 캐시·추론 세부값 해석. 실제 파서는 Codex CLI 이벤트 필드만 사용한다.
