# ai-workflow

개발, 기술 조사, 설계 검토와 글쓰기에서 재사용할 AI 작업 원칙을 정리합니다. 특정 프로젝트나 도구에 종속되지 않는 공통 기준부터 시작하고, 실제 작업 경험에 따라 가이드를 확장합니다.

## 현재 구성

| 경로 | 용도 |
| --- | --- |
| [AGENTS.md](AGENTS.md) | 공통 작업 원칙과 AI 에이전트 지침 |
| [principles/privacy.md](principles/privacy.md) | 공개·비공개 정보, 저장 위치와 외부 전달 기준 |
| [.gitignore](.gitignore) | 이 저장소에서 로컬 파일의 실수 커밋을 줄이는 보조 설정 |

## 시작하기

1. 이 저장소를 원하는 작업 위치에 복제하거나 문서를 열어 공통 원칙과 개인정보 관리 기준을 읽습니다.
2. 해당 프로젝트에서만 쓰는 기술 스택, 테스트 방법과 서비스 정책은 그 프로젝트의 지침으로 관리합니다.
3. 사용할 AI 도구에 공통 가이드와 프로젝트 지침을 읽도록 명시적으로 연결하거나 요청에 필요한 문서를 지정합니다. 연결 방법과 자동 로딩 범위는 도구마다 다릅니다.
4. 작은 실제 작업에 적용하고, 반복적으로 도움이 되는 절차만 추가합니다.

### 요청 예시

> 이 프로젝트의 기존 지침과 ai-workflow의 AGENTS.md 및 개인정보 관리 지침을 참고해 작업해 줘. 필요한 문서가 접근 가능한지 먼저 확인하고, 변경 사항에 맞는 검증 결과를 알려줘.

도구에 이 저장소가 접근 가능하도록 제공해야 합니다. 다른 프로젝트에 이 저장소의 가이드가 자동으로 적용되는 것은 아닙니다. 개인정보나 인증 정보를 예시 요청에 넣지 마세요.

## 공개와 개인 정보

- 이 저장소는 공개되어 있으므로 공개 가능한 범용 문서와 가상 예시만 저장합니다.
- 개인 자료는 사용자가 정한 별도 위치에 보관하며, 가능하면 이 저장소의 바깥을 선택합니다. 위치가 정해지지 않았거나 공개 여부가 모호하면 먼저 확인합니다.
- 비밀번호, 토큰, API 키 등은 문서에 기록하지 않고 승인된 자격 증명 저장소를 사용합니다.
- .gitignore는 보안 경계가 아닙니다. 이미 추적된 파일을 숨기지 않으며, AI의 접근을 차단하거나 데이터를 암호화하지 않습니다.
- 조직의 비공개 자료에는 해당 조직의 정책이 우선합니다. 자세한 내용은 [개인정보 관리 기준](principles/privacy.md)을 참고하세요.

## 앞으로 확장하기

개발, 기술 조사, 설계 검토, 블로그 작성 가이드는 실제 사용 경험을 바탕으로 필요한 순서대로 추가합니다. 여러 에이전트의 역할이나 도구 연결도 실제 필요가 확인되면 구체화합니다.
