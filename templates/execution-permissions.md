# 실행 권한 인계

필요한 항목만 작성해 비공개 작업 입력에 첨부한다. 이 양식은 권한 설정 파일이 아니며 실행기가 자동 적용하지 않는다. [공통 정책](../runtime/permission-policy.md)을 따른다.

- 작업/허용 근거: <요청·결정 참조. 이미 승인된 범위를 반복 질문하지 않음>
- 실행 위치: <환경 / host / workspace / 세션 또는 프로필 / 버전>
- 승인 모드: <요청값 / 실제 확인값 또는 unknown / 확인 출처>
- 운영 방식: <Orca + Codex 자동화는 대신 승인 실제 적용 확인 필수 / 명시적으로 선택한 수동 승인 운영. 명칭만으로 판정하지 않음>
- 승인 정책·경계: <reviewer / approval policy / sandbox·network 실제값 또는 unknown. 각각 별개로 확인>
- 읽기 입력: <프로젝트·외부 입력의 필요한 경로>
- 쓰기 출력: <프로젝트의 수정 범위 / 자기 scratch / 작업별 비공개 기록 폴더>
- 실행: <빌드·테스트 명령 / 스크립트 버전 / 시간 제한>
- 의존성: <기존 준비 근거 또는 필요한 공식 출처·버전·캐시>
- 네트워크: <필요한 목적지. 불필요하면 없음>
- 로컬 서버: <loopback 주소·포트·수명·정리 담당. 불필요하면 없음>
- 조율: <현재 run/dispatch와 질문·보고 경로. 위임하지 않으면 없음>
- 제외/별도 승인: <게시·다른 경로·프로젝트 삭제·운영 변경 등>

## 적용과 확인

| 대상 | 필요한 범위 | 현재 확인값과 근거 | 남은 차이 / 담당 |
| --- | --- | --- | --- |
| 조율자 | <...> | <... 또는 unknown> | <... 또는 없음> |
| worker | <위임할 때만> | <자기 설정 확인. 부모 성공만으로 pass 금지> | <...> |

- 지속적 설정 변경: <정확한 항목 / 전후 값 / 이번 실행·프로젝트·호스트 기본값 중 적용 범위 / 승인 근거 / 복원 방법>
- 준비 검사: <필요한 동작만, 명령·시각·결과·세션>
- 재사용할 준비 근거: <같은 버전·프로필·경로·명령의 기존 결과 참조 / 이번 worker의 차이만 확인. 별도 시험 worker를 매번 만들지 않음>
- 상태: <계획 / 승인 대기 / 설정 저장 / 실제 적용 확인 / 효과 미검증>
- 승인·검토·대기 측정: <각 출처와 수치, 없으면 unavailable>
- 만료·재확인 조건: <host·세션·버전·경로·명령·네트워크 범위 변경>

실제 파일 경로·질문 본문·세션 ID는 공개 예제로 옮기지 않는다. 비밀 값이나 인증 설정 원문은 이 양식에 넣지 않는다.
