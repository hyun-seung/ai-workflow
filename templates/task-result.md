# 작업 결과

작업을 마친 뒤 아래 형식으로 응답한다. `<...>`를 결과로 바꾸고 선택 항목은 필요한 것만 남긴다. 실행하지 않은 검사나 확인할 수 없는 사용량을 만들어 적지 않는다. 이 양식 자체는 파일 저장이나 외부 게시를 지시하지 않는다.

## 필수

- task_id: <입력과 동일한 작업 ID>
- status: <completed / partial / blocked>
- summary: <무엇이 달라졌고 어디까지 확인했는지>
- artifacts: <변경 파일·문서·결과물의 참조와 필요한 버전, 없으면 없음>

### checks

| 완료 기준 ID | 상태: pass / fail / unverified | 수행한 확인과 증거·대상 버전 | 판정 주체: 자체 / 별도 검증 |
| --- | --- | --- | --- |
| AC-01 | <상태> | <실제 명령·출처·결과 위치, 미검증이면 이유> | <주체> |

완료 기준마다 한 행을 작성한다. 실패 항목에는 기대 결과·실제 결과·재현 또는 확인 방법을 추가한다. 기준 밖의 개선 제안은 실패와 구분한다. 산출물 변경 이후에도 증거가 유효한지 확인한다.

### remaining

- <미완료·실패·미검증 항목과 다음 조치, 없으면 없음>
- <blocked이면 진행을 막는 조건, 해소 방법과 필요한 담당자>

### usage

- 상태: unavailable
- 사유: <실행 도구의 측정 자료가 없거나 아직 확인되지 않음>

측정 자료가 있을 때만 위 상태를 `measured` 또는 `partial`로 바꾸고, 출처·작업/시도/세션 식별자·측정 범위·실제 수치·집계 기준을 기록한다. 부분 측정이면 누락 범위를 적는다. 같은 세션 기록을 다른 작업과 공유하면 중복 합산하지 않도록 표시한다.

## 선택

### decisions

| 결정 | 대안별 장단점 | 선택과 근거 | 남은 위험·재검토 조건 |
| --- | --- | --- | --- |
| <중요한 결정> | <검토한 대안만 간결하게> | <선택과 확인 가능한 근거> | <해당하는 경우> |

### handoff

- 다음 담당 역할·작업: <필요한 경우>
- 전달할 참조·확정된 계약: <다음 작업에 필요한 자료만>
- 남은 질문·의존성: <다음 담당자가 알아야 하는 제약>

### improvement

- 관찰한 반복 문제·근거: <실패·재작업·측정된 비용 등>
- 개선 가설·비교 방법: <작은 변경과 동일한 품질 기준>

개선 제안은 별도 작업의 후보이며, 현재 업무를 벗어난 수정이나 추가 모델 호출을 자동으로 승인하지 않는다.
