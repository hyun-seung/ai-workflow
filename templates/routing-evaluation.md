# 요청 라우팅·튜터 품질 평가 기록

빈 양식이다. 실제 사용 시 Git/대상 프로젝트 밖의 비공개 위치에 복사한다. 초기 판정은 미검증이며 작성 후 해당 파일 자체의 SHA-256을 비교 manifest의 `quality.evidence`에 연결한다. 준비된 양식을 평가 완료 근거로 쓰지 않는다.

## 평가 연결

- 사례 ID / 요청 ID: 미기록
- 평가용 라벨(A 또는 B): 미기록
- 평가 종류(self / independent / user): 미기록
- 평가자·작성 참여 여부·블라인드 한계: 미기록
- 고정한 기준 파일 절대 경로 / SHA-256: 미기록
- 실제 입력·제어·응답/코드의 비공개 참조 / SHA-256: 미기록
- 필요한 선행 맥락·자료 제공 여부 / 누락된 맥락: 미기록. 사례 나열 순서를 대화 순서로 가정하지 않음
- 사용한 지침·설정 버전 참조: 미기록
- 수행한 코드 검사와 로그 참조 / 종료 코드: 미기록

평가자는 비용·모델·D/R 대응을 공개받기 전에 아래 품질을 판정한다. 실제 모델/effort·실행 순서·캐시·네트워크 등 비교 조건은 별도 비공개 운영 기록에 보존한다. 확인하지 못한 실행값은 추측하지 않는다.

## 완료 기준별 판정

사례의 모든 필수 AC를 ID 그대로 옮긴다. 행을 빠뜨리거나 필수 기준을 선택 의견으로 바꾸지 않는다.

| AC ID | pass / fail / unverified | 답변 위치·실행 결과·공식 자료의 해당 절 | 문제와 보완 또는 미검증 이유 |
| --- | --- | --- | --- |
| AC-01 | unverified | 미기록 | 미평가 |
| 나머지 필수 AC 전부 추가 | unverified | 미기록 | 미평가 |

## 주장과 출처 대조

| 핵심 주장 / 연관 답변 | 공식 문서명·관련 절·링크 | 확인한 버전·범위 | 일치 / 불일치 / 미확인 |
| --- | --- | --- | --- |
| 미기록 | 미기록 | 미기록 | 미확인 |

출처를 확인하지 않았다면 링크 존재만으로 일치라 하지 않는다. 직접 만든 예시·비유·추론을 구분하고, 공식 자료 대신 다른 자료를 사용했다면 이유·자료 성격을 적는다.

- 특정 절/앵커의 확인 근거 또는 확인한 페이지·절 제목으로 대체한 이유: 미기록
- 수치의 대상·버전·조건 / 소스 도출·직접 관측·가상의 구분과 관측 범위: 미기록

## 추천·제어와 범위

- 실제로 나온 추천(없으면 없음): 미기록
- 역할 / 모델 / effort / 위임의 변경 범위: 미기록
- 사용자에게 실제로 제시한 내용·받은 선택의 근거: 미기록
- 같은 후속에서 추천·지침·승인을 반복했는지: 미검증
- 직접 처리·고정·위임 금지·취소·인용문 처리가 맞았는지: 미검증
- 실제 사용자 이해도·만족도: 미측정

## 튜터 설명·후속·시각화 (해당 시)

- 실제 질문한 대상과 첫 답의 대상이 일치했는지 / 다른 메서드·단계의 횟수로 대신하지 않았는지: 미검증
- 같은 목표의 후속에서도 설명 기준을 유지했는지, 새로 막힌 연결과 이미 답한 내용을 구분했는지: 미검증
- 표현 선택(짧은 답 / 표 / 도식)과 이유, 반복 혼란에 예시·표현을 바꿨는지: 미검증
- 같은 질문 재제기에서 직전 답의 대상 불일치를 먼저 확인했는지 / 같은 조건·예시의 막힌 단계를 갱신했는지: 미검증
- 관계·흐름·분기·권한 경계에 필요한 도식을 제공했는지와 화살표 의미: 미검증
- 실제 표시 수단·가독성 확인 범위 / 지원 불가·텍스트 대체 사유: 미검증
- 설계 질문의 관련 자원·권한·네트워크·장애·비용·운영 누락과 가정: 미검증
- 지침 참조·응답 품질·앱 자동 연결의 확인 수준을 구분했는지: 미검증
- 근거·도식·실험의 재사용과 새 확인의 필요성 / 실제 사용량 측정 여부: 미검증

선택 의견을 새 필수 AC로 소급하지 않는다. 도식 판단이 필요 없는 약어·한 문장 요청에는 이유와 함께 not_applicable로 기록한다. 새 기준은 다음 평가부터 적용하며 실제 이해도·자동 연결 성공·비용 절감으로 확대하지 않는다.

## 수집 범위 근거

아래는 실제 완료 후 작성한다. 각 단계에 included / not_applicable / missing을 붙이고 근거를 적는다. 미수집을 not_applicable로 바꾸지 않는다. 비교 manifest에도 같은 선언을 사용한다.

| 단계 | 선언 | 측정 파일/구간 참조 또는 없었던/누락된 이유 |
| --- | --- | --- |
| routing | 미기록 | 미기록 |
| selection | 미기록 | 미기록 |
| processing | 미기록 | 미기록 |
| handoff | 미기록 | 미기록 |
| integration | 미기록 | 미기록 |
| verification | 미기록 | 미기록 |
| rework | 미기록 | 미기록 |
| reporting | 미기록 | 미기록 |

- 평가·재작업 자체의 모델 호출/사용량을 포함한 범위와 제외 근거: 미기록
- 공동 실험 준비/합산 보고 등 별도 운영비 참조: 미기록
- 알려진 조건 차이·누락·시간/요금 근거의 한계: 미기록

## 최종 판정

- quality.status: unverified
- 필수 AC 중 fail / unverified / pass의 근거: 미평가
- 선택적 개선 의견: 미기록
- 초안/수정본·재평가 연결(해당 시): 미기록
- 판정 시각·근거 파일 해시 고정 시점: 미기록

필수 fail이 있으면 fail, fail 없이 필수 미검증이 있으면 unverified, 전부 통과한 경우만 pass다. 품질 pass와 전체 토큰 절감·자동화 허용은 별개다.
