# 작업 보고 양식

공개 가능한 빈 양식이다. 실제 내용은 비공개 자료를 포함할 수 있으므로 사용자가 지정한 보관 위치 또는 승인된 프로젝트 환경에 작성한다. 이 공개 저장소에 실행 로그를 자동 저장하지 않는다. 작은 작업은 필요한 항목만 짧게 남긴다.

이 양식은 여러 작업을 종합하는 보고서다. 개별 업무 배정은 [작업 입력](task-input.md), 담당자의 반환은 [작업 결과](task-result.md)를 사용한다. 기존 입력·결과를 참조하여 연결하고 동일한 내용을 다시 길게 작성하지 않는다. 상태·측정 기준은 [입출력 계약](README.md)을 따른다.

## 목표와 완료 기준

- 작업 ID / 목표 / 포함·제외 범위:
- 요구사항별 완료 기준과 검증 방법:
- 제약·미해결 질문 / 전체 허용 예산과 단위:

## 중요한 결정

| 결정 | 검토한 대안과 장단점 | 선택과 근거 | 남은 위험·재검토 조건 |
| --- | --- | --- | --- |

간결한 결정 요약을 기록한다. 전체 대화나 내부 추론의 나열은 필요하지 않다.

## 검증 결과

| 완료 기준 | 수행한 검증·근거 위치 | 상태: 통과/실패/미검증 | 담당자·후속 조치 |
| --- | --- | --- | --- |

작성자의 자체 검증과 별도 검증을 구분한다. 실패는 기대 결과·실제 결과·재현 조건을, 미검증은 이유를 적는다. 새로운 개선 제안을 기존 완료 기준의 실패와 혼동하지 않는다.

## 실제 사용량

| 작업·시도·세션 식별자 | 역할 | 실제 모델·effort | 입력 | 출력 | 캐시·추론 세부값 | 측정 출처·완전성 |
| --- | --- | --- | --- | --- | --- | --- |

- 세부값이 입력·출력에 이미 포함되는지 확인하고 중복 합산하지 않는다. 공급자별 집계 기준을 남긴다.
- 역할별 측정이 불가능하면 세션 전체로 보고한다. 누락은 0이 아닌 미측정/부분 측정으로 적는다.
- 재시도·조율·검증·보고·개선을 포함한 전체 사용량과 시간, 예상 대비 차이·이유를 정리한다.
- 보고 작성 자체의 사용량이 실행 종료 후에만 확인된다면 현재 집계 범위를 명시한다.

## 인계와 개선

- 결과물과 변경 위치 / 남은 제한·실패·미검증 / 다음 담당자·조치:
- 반복 문제와 개선 가설 / 비교할 대표 작업과 동일한 품질 기준 / 개선에 허용할 예산:
- 비교 기준: 동일한 목표·완료 기준·검증 방법 / 기준 변경본·실행 환경 / 다른 조건과 확인하지 못한 조건:
- 변경 내용과 근거: 지침·전달 자료·모델·effort 등의 변경과 이유:

필요한 경우 개선 전후의 확인 가능한 항목만 채운다. 사용량이 없으면 미측정으로 적고, 조율·재시도·검증·보고·개선 작업의 포함 범위와 중복 여부를 표시한다. 캐시 상태 등 비교 조건이 다르거나 확인되지 않으면 함께 밝힌다.

| --- | --- | --- | --- | --- |
| 개선 전 |  |  |  |  |
| 개선 후 |  |  |  |  |

완료 기준과 검증 수준을 낮추어 토큰만 줄인 경우에는 개선 성공으로 판단하지 않는다. 민감한 실행 내용의 보관·공개는 [개인정보 관리 기준](../principles/privacy.md)을 따른다.
