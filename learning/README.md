# 학습 대화 진입점

**학습 튜터(`tutor`)**는 “이게 무슨 개념이야?”에서 시작하는 대화 역할이다. 기존 개발 역할의 하위 단계가 아니라 별도 인입점이며, 같은 세션의 에이전트가 튜터 책임을 맡을 수 있다. 이름을 새 에이전트 생성 명령으로 해석하지 않는다.

## 연결과 사용

이 저장소의 [AGENTS.md](../AGENTS.md)는 이해·학습 요청을 [짧은 튜터 지침](tutor-brief.md)으로 연결한다. 다른 프로젝트나 새 대화에서는 사용하는 도구의 지침 기능 또는 시작 요청에 공통 원칙과 튜터 문서를 명시적으로 연결해야 한다. 앱 전체에 새 메뉴·슬래시 명령·자동 라우터를 설치하는 변경은 아니다.

일반 설명은 [짧은 튜터 지침](tutor-brief.md)을 사용하고 심화 방식에만 상세 역할 문서를 읽는다. 튜터 개발과 추천 평가·Orca 연결·선택 반영·위임/모델 전환·비용 비교의 순서는 [통합 개발 계획](development.md)에 모았다. [참고 답변](reference-response.md)과 [통합 점검 입력](../examples/tutor-routing-cases.json)은 1차 기준 자료이며 독립 품질 평가 결과가 아니다.

[심화 평가 기록](evaluation.md)에는 세 주제의 [생성 응답 16개](evaluation-responses.md), 공식 근거 대조, [시각 예시](visual-samples.html)의 실제 배치 확인과 보완을 남겼다. 작성 AI의 자체 검토이며 독립 정확도·학습 효과·비용 절감의 측정 결과로 일반화하지 않는다.

시작 요청 예시:

> 이 대화에서는 공통 AGENTS.md와 roles/tutor.md를 적용해 학습 튜터로 대화해 줘. 처음 듣는 주제는 쉬운 설명과 핵심부터 시작하고, 내 요청에 따라 그림·원리·한 장 정리로 바꿔 줘. 이어서 궁금할 만한 질문과 답변도 써 줘. 근거는 공식 문서를 우선 확인하고, 각 설명을 어디서 확인할 수 있는지 링크로 연결해 줘.

연결한 뒤에는 “캐시가 무슨 개념이야?”, “제1원리로 설명해 줘”, “메모 그림으로 보여줘”, “내가 설명해 볼게”, “관련해서 궁금할 만한 것도 알려줘”처럼 요청한다. 방식을 매번 고르거나 모두 실행할 필요가 없다. 방식·분량·난이도는 현재 대화에서 자동 선택·전환한다. 기존 9·10번의 퀴즈·소크라테스 문답은 연관 질문과 답변으로 대체했다. 사용자에게 답을 요구하지 않고 질문과 해설을 함께 제공한다. 실제 선택·출처 규칙은 튜터 문서에 둔다.

## 설명과 출처의 기본 형식

1. 쉬운 정의와 핵심, 예시·작동 이유를 설명하고 핵심 주장에 근거 링크를 연결한다.
2. 연관 질문 2~4개와 각각의 답변·근거 링크를 덧붙인다. 이유·비교·적용·예외 중 도움이 될 내용을 고르며, 짧게 요청하면 개수·분량을 줄이거나 생략한다.
3. 공식 문서 내용을 쉬운 말로 재구성했는지, 짧게 직접 인용했는지, 비유·예시는 직접 만들었는지 구분한다. 출처에 없는 추론은 그 지점에서 밝힌다.

근거는 **공식 문서 우선 → 다른 권위 있는 1차 자료 → 신뢰할 수 있는 전문 해설로 보완**한다. 관련 페이지·절을 실제로 읽고 문서명·절 제목을 붙여 링크한다. 홈페이지나 검색 결과만 제시하지 않는다. 공식 자료를 찾지 못했거나 접근하지 못하면 미확인 범위와 사용한 대체 자료의 성격을 알린다. 자세한 기준은 [튜터의 출처와 정확성](../roles/tutor.md#출처와-정확성)을 공통으로 적용한다.

### 기존 단독 실행기의 사용 범위

`workflow.json`에 튜터와 준비 역할의 실행값을 등록한다. 아래는 **한 번의 설명 응답**을 준비하는 명령이며, 실행할 모델의 지원 여부는 별도 확인한다.

```sh
python3 scripts/workflow.py run --project . --role tutor --task "캐시가 무슨 개념인지 쉽게 설명해 줘" --dry-run
```

`--dry-run`은 모델을 호출하지 않는다. 제거하면 한 번 실행하며, 이 실행기는 재위임을 제한한다. 지속 대화·문답 상태 저장·병렬 worker 자동 생성은 이 명령에 구현하지 않았다. 문답은 지침을 연결한 대화 세션에서 이어 간다. Orca/Paseo에서 실제 위임할 때는 [시작 가이드](../runtime/environments/README.md), 선택한 환경 가이드와 [권한 정책](../runtime/permission-policy.md)을 먼저 적용한다. 단독 CLI를 연결 실패의 대체 경로로 쓰지 않는다.

## 병렬 준비와 순차 대화

역할은 학습 기법마다 하나씩 만들지 않고, 독립적으로 준비할 수 있는 결과물 기준으로 나눈다. 튜터가 공통 입력을 확정한 뒤 필요한 역할만 실행한다. 단순 질문에는 worker 없이 답한다. 병렬화가 항상 더 빠르다고 가정하지 않으며, 짧은 결과에 생성·통합 비용이 더 크면 직접 준비한다.

| 담당 | 준비 범위 | 병렬 가능 조건 |
| --- | --- | --- |
| [개념 해설 담당](../roles/learning-concepts.md) (`learning-concepts`) | ELI5·80/20·제1원리의 핵심 사실, 예시·비유·한계 | 주제·범위·정의·출처가 확정되어 시각/Q&A 자료와 독립적으로 조사 가능 |
| [학습 시각화 담당](../roles/learning-visuals.md) (`learning-visuals`) | 스티커 메모·마인드맵·관계/흐름 도식, 한 장 시트의 구성 초안 | 공통 개념 목록·관계가 확정된 뒤 연관 Q&A 준비와 병렬 가능 |
| [연관 질문 해설 담당](../roles/learning-connections.md) (`learning-connections`) | 이어서 궁금할 질문·답변·공식 근거, 요청 시 파인만 설명 범위 보조 | 학습 목표·개념·예상 오해가 확정된 뒤 시각 자료와 병렬 가능; 사용자 답을 기다릴 필요 없음 |
| 튜터 (`tutor`) | 수준·범위 결정, 모드 선택, 개념·출처 검증, 본문과 연관 Q&A 통합·전달 | 본문 확정 후 Q&A의 중복·충돌 확인; 요청한 파인만 대화의 사용자 답 → 피드백은 순차 |

기본 의존성:

```text
사용자 요청 → 튜터: 주제·목표·범위·정의 확정
                 ↓ (근거가 부족하면 먼저 개념 해설로 보완)
              공통 개념·관계·오해 확정
                 ├→ 설명 예시 보완 ──┐
                 ├→ 시각 자료 준비 ──┼→ 튜터 대조·통합 → 설명/학습 시트
                 └→ 연관 Q&A·근거 ──┘        + 연관 질문과 답변·출처 링크

파인만 요청 시에만: 설명 요청 하나 → 사용자 재설명 → 튜터 피드백
```

미확정 개념을 전제로 그림·문제를 먼저 완성하지 않는다. 독립 출처 탐색이나 레이아웃 틀은 앞서 준비할 수 있지만, 개념이 달라지면 관련 결과를 다시 확인한다. 첫 핵심 설명과 선택 자료를 단계적으로 전달할 수 있으며, 배경 실행·추후 전달은 환경에서 실제 지원할 때만 약속한다.

### 하위 역할 입출력 계약

- 입력: 주제, 사용자 목적·알려진 수준, 선택한 방식·분량, 공통 정의·개념·관계·출처, 맡길 범위, 제외 범위, 의존 결과의 버전, 완료 기준을 전달한다. 사용자 답 전체나 개인정보는 필요 없이 공유하지 않는다.
- 출력: 담당 범위의 자료, 주장별 근거 링크·문서명·관련 절, 자료의 공식 여부·버전/날짜(해당 시), 가정, 쉬운 표현과 정확한 용어의 대응, 비유의 한계, 남은 의문을 튜터에게 돌려준다. 연관 질문에는 답과 근거를 함께 포함한다.
- 튜터만 사용자에게 답한다. 합성 전에 용어·관계·본문과 Q&A의 중복·출처가 실제 주장을 뒷받침하는지 대조하며, 일부 역할이 실패해도 검증된 범위의 설명은 전달하고 빠진 요청 자료를 알린다. 필수 자료가 빠졌으면 전체 요청 완료로 표시하지 않는다.
- 실제 위임은 환경의 생성·완료 수신·사용량 수집과 [위임 한도](../runtime/delegation.md)를 따른다. 새 역할 추가가 동시 실행 한도를 늘리거나 자식 권한을 부여하지 않는다. 요청값과 실제 모델·effort, 미측정과 0을 구분한다.

아래는 가상 시나리오의 수용 기준이며 실제 모델 품질 측정 결과가 아니다. 단독 실행기의 설정·dry-run 검증으로 대화 품질이나 병렬 속도 개선을 보장하지 않는다.

| 요청/상황 | 기대 동작 |
| --- | --- |
| “캐시가 뭐야?” | 쉬운 정의·핵심·예시·한계와 공식 근거 링크, 연관 Q&A 추가; 불필요한 사전 설문·위임 없음 |
| “캐시 스티커 메모/마인드맵/도식” | 각각 주제별 메모/분류 가지/작동 관계로 표현, 용어 일치 |
| “왜 빨라지는지 원리부터” | 접근 비용·재사용의 이유에서 도출하고 갱신·일관성 조건 설명 |
| “한 장으로 핵심과 읽는 순서·지표까지” | 한 화면 분량, 적중률·지연시간의 의미와 단위·해석 조건 포함 |
| “내가 설명해 볼게” | 설명 요청 하나 후 기다림; 실제 답에서 빠진 연결에만 피드백 |
| “관련해서 궁금할 만한 것도” | 예: “캐시를 많이 쓰면 항상 빠른가?”, “데이터가 바뀌면?”처럼 본문 다음 단계의 질문과 답·근거를 함께 제공 |
| “한 줄로 핵심만” | 분량을 우선하며 Q&A를 강제로 붙이지 않음 |
| 공식 문서 접근 불가·공식 자료 없음 | 확인 범위·제약·대체 출처 성격 표시, 링크·내용을 확인한 척하지 않음 |
| 공식 문서 요약에 직접 만든 비유 포함 | 재구성·비유임을 구분하고 실제 문서의 해당 절로 연결 |
| “이게 뭐야?”의 참조 없음 | 대상 확인 질문 하나, 임의 주제 설명 없음 |
| 설명 중 “그만, 이제 구현해 줘” | 학습 흐름을 멈추고 명시한 구현 요청으로 전환 |
| 자료 간 정의 충돌 또는 worker 실패 | 충돌 해소 후 통합, 필수 미완료와 선택 자료 누락 구분 |

## 이름과 설계 근거

`설명자(explainer)`는 설명 전달에, `학습 튜터(tutor)`는 설명·연관 개념 확장과 요청 시 재설명 피드백을 함께 맡는 이번 책임에 더 잘 맞는다는 명명 판단이다. Open University는 튜터의 학습 촉진과 열린 질문을 소개한다. CMU의 학습 원칙은 사전 지식, 지식의 조직, 목표에 맞는 연습과 피드백을 강조한다. 이 자료를 모든 방식을 수행하거나 특정 비율의 학습 효과를 보장하는 근거로 해석하지 않는다. 현재 기본 출력은 사용자 선호에 따라 퀴즈 대신 연관 Q&A를 제공한다.
