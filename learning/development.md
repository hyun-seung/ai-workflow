# 튜터·요청 라우팅 통합 개발 순서

튜터와 역할·모델/effort 추천을 같은 진입 흐름에서 개발한다. 매 요청의 추가 토큰 최소화, 직접 처리 선택, 공식 근거와 필수 품질을 공통 기준으로 둔다. 역할 문서나 로컬 도구의 존재를 앱 연동 완료로 간주하지 않는다.

기본 인입은 지침이 연결된 현재 AI의 요청 판단·대화 선택이다. 필요한 역할 지침도 현재 AI가 읽어 적용한다. native hook과 별도 선택 UI는 상태 자동 전달·측정 수집을 위한 선택적 고도화이며 기본 기능의 선행 조건으로 두지 않는다. 현재 대화의 모델/effort 전환에는 별도 공식 적용 경로가 필요하다.

## 우선순위

| 순서 | 통합 작업 | 완료 기준과 현재 범위 |
| --- | --- | --- |
| 1 | 튜터 기본 응답·추천 생략 기준 정리와 대표 사례 점검 | 짧은 튜터 진입 지침, 공식 근거에 기반한 참고 답변, 튜터/일반 요청의 점검 입력을 작성. 로컬 라우터의 정책 경로와 코드 예시는 확인하되 자연어 추천 품질·사용자 학습 효과의 통계 평가와 구분 |
| 2 | 튜터 심화 방식·추천의 실제 품질 평가 | 원리·스티커 메모·마인드맵·도식·한 장 시트·파인만·연관 Q&A를 대표 주제에 적용. 자료 없는 질문·실제 개발 요청·설정 고정까지 포함해 불필요한 추천·오분류·출처 오류·분량 초과를 기록. 현재 AI의 자체 판단과 사용자/독립 평가를 구분 |
| 3 | 기본 인입과 선택적 Orca 상태 연결 | 현재 AI가 연결 지침과 대화 입력으로 판단하는 경로를 기본으로 둠. [선택적 native 연결](../runtime/orca-routing-input.md)은 어댑터 13개·probe 8개 검사와 실제 시험 후 영수증/검토 경로 미확인으로 시험 정의 제거 |
| 4 | 사용자 선택과 같은 AI의 역할 적용 | [로컬 선택 기록·26개 검사](../runtime/routing-choices.md) 구현. 대화 해석은 현재 AI가 담당하며 선택한 역할 지침을 읽는 기본 경로 사용. 앱의 자연어 상태 추출·선택 UI·자동 지침 주입·snapshot 동기화는 남음 |
| 5 | 명시한 병렬 위임·모델/effort 전환 | [명시 실행 연결](../runtime/routing-dispatch.md) 19개 가상 응답 검사·독립 검토. [실제 Sol/medium 한 건](../runtime/routing-integration-check.md)의 역할 전달·요청/실행환경 적용값·replay·정확한 종료 확인. 공급자 관측·토큰·현재 대화 전환·병렬 효과는 미확인 |
| 6 | 직접 처리 대비 비용·품질 비교와 제한 자동화 | [기존 측정 파일의 비교 도구](../runtime/routing-comparison.md)와 18개 가상 자료 검사 구현. 수집 단계·품질·물리 중복을 검사하며 실제 비교 쌍·시간/금액·일반화 효과는 미측정. 모든 출력의 자동화 허용은 false |

각 단계에서 튜터의 발견된 문제를 고친다. 튜터 전체를 별도 완성한 뒤 라우터를 다시 붙이거나, 모든 단계를 한꺼번에 구현하지 않는다. 현재 순서는 의존성에 따른 개발 계획이며 모델/worker 실행·지속 설정 변경의 포괄 승인이 아니다.

## 1차 산출물과 확인 범위

- [짧은 튜터 진입 지침](tutor-brief.md): 단순 설명에 맞춘 필수 행동. 심화 요청에만 상세 역할 문서 확인.
- [공식 문서 기반 참고 답변](reference-response.md): 가상 Python 질문을 재구성한 답변·짧은 응답·파인만 요청 예시. 실제 코드를 확인하되 다른 주제의 품질까지 일반화하지 않음.
- [통합 점검 입력](../examples/tutor-routing-cases.json): 작성 AI가 정리한 요청 해석과 라우터 입력·기대 정책 결과. 기대값을 알고 작성한 자체 점검 자료이며 독립 자연어 분류 시험이 아님.

1차 로컬 확인: 작성한 점검 입력 12개의 정책 결과가 기대값과 일치했고, 참고 답변의 Python 코드 3개의 출력이 설명과 일치했다. 공식 튜토리얼의 대입·리스트 복사 절을 원문 확인했다. 이는 정책 연결과 한 주제 예시의 자체 확인이며 실사용 오분류율·학습 효과·토큰 절감의 측정이 아니다.

2단계의 [대표 응답 16개](evaluation-responses.md)에 대해 세 기술 주제의 공식 근거·분량·전환·추천 필요성을 자체 검토하고 [평가 결과](evaluation.md)를 남겼다. 시각 예시 네 방식의 두 화면 폭 확인, 모바일 시트·마인드맵·키보드 전환과 지침 보완을 수행했다. 독립 추천 정확도·사용자 학습 효과·토큰 절감은 미검증이다.

## 연결 범위와 검증 근거

- **입력 어댑터:** 빈 상태는 추가 문맥을 출력하지 않고 명시 snapshot만 최대 512문자 힌트로 전달한다. 원문·transcript 저장/탐색·별도 모델 호출은 없다. Orca 1.4.257에서 현재 native 세션용 probe와 등록 worker용 Stop을 시험했으나 실제 수신·공식 검토 경로가 확인되지 않아 시험 정의를 제거했다. [지원 경계와 검사](../runtime/orca-routing-input.md).
- **공식 지원 재확인:** 웹 문서에는 일반 프로젝트 hook 지원이 명시되어 있고 현재 관리 상태 hook도 활성·Codex 설치 상태다. 현재 native 사용자 프로젝트의 신뢰/이벤트 실행까지 검증된 것은 아니므로 [지원 범위](../runtime/orca-routing-input.md#2026-11-14-공식-웹-문서-재확인)를 구분하며 기본 진입 운영은 계속한다.
- **선택 기록·후속 재사용:** 요청 원문·추천 이유를 저장하지 않고 요청/추천 버전과 수용·거절·취소를 기록한다. 같은 요청임이 명시되고 문맥이 일치할 때만 역할 본문 재로딩 없이 선택을 재사용한다. [보관·처리 계약과 26개 검사](../runtime/routing-choices.md).
- **명시 위임 연결:** 수용한 worker 선택과 모델/effort를 한 ledger·operation·계획에 고정하고 공통 지침 참조·선택 역할만 전달한다. [실제 한 건](../runtime/routing-integration-check.md)의 요청/실행환경 적용값·역할 전달·중복 재조회·종료는 확인했다. 공급자 실제 모델/effort 두 필드는 unverified이며 토큰도 미측정이다. 현재 대화 전환 성공을 뜻하지 않는다.
- **회귀 확인:** 이 세 연결과 기존 관리 실행·완료 수집을 포함한 Python 검사 394개 통과. 독립 검토의 공통 지침·역할 원본 경로 전달 누락을 보완했다. 단위 검사·가상 응답을 실제 통합이나 토큰 절감 근거로 확대하지 않는다.
- **측정 비교 준비:** 기존 worker/조율자 수집 파일과 동일 완료 기준·품질 근거를 비공개 manifest로 연결하는 읽기 전용 비교 도구를 추가했다. 단계 누락·같은 물리 턴 재사용·품질 미확인에는 절감 성공을 판정하지 않는다. 선언된 범위와 품질의 진위는 자동 증명하지 않는다. 실제 비교 쌍과 효과는 아직 없다.
- **기본 경로 후속 점검:** [비개발 개념·제어 경계 응답 여섯 개](basic-flow-check.md)를 공식 교재와 자체 대조하고 작성된 정책 입력 16개·가상 취소→직접 처리 경로를 확인했다. 관련 회귀 106개 통과. 추가 모델/worker·매 입력용 지침 확대는 없으며 독립 품질 평가는 아니다.
- **공통 진입 연결:** [현재 AI 호출형 진입점](../runtime/routing-flow.md)을 구현했다. 추천→선택→첫 역할 지침 준비·후속 재사용과 명시 위임→취소/종료 조회를 기존 저장 형식·실행기에 연결한다. 거절 반복·중복 지침/실행을 억제하고 미연결 모델 변경은 수동 설정으로 구분한다. 이 단계의 신규 흐름 18개·중지 6개와 전체 Python 검사 444개, 독립 코드 검토를 확인했다. 최초 실행의 localhost bind 제한 한 건은 해당 검사만 정식 권한 경로로 재실행해 통과했다. 실제 중지·앱 자동 연결 검증은 아니다.
- **취소·복구 후속 보완:** 시작 전 권한 거부로 미실행이 증명된 예약은 native 호출 없이 취소·슬롯 반환한다. 누적 한도·원래 영수증은 보존하고 같은 operation 재실행을 막는다. 비정상 신원/종료 응답은 중지·해제 근거로 쓰지 않는다. 현재 흐름 19개·중지 10개를 포함한 관련 회귀 102개와 독립 검토가 통과했다. 실제 native 중지 검증과 비용 측정은 남아 있다.
- **완료·측정 연결:** 공통 진입점에 `finish`와 시작 시 선택 `collection`을 추가했다. 명시 원본→기존 완료 수집→선택한 프로필 대조→배정별 토큰→고정한 DB 담당자/업무명→비교용 파일 참조를 연결한다. 원본 누락은 보류, 실제값 누락은 미확인, 배정 측정은 전체 요청 비용과 구분한다. 새 검사 21개와 독립 재검토를 통과했다. 기존 파일 덮어쓰기 방지와 중단된 수집의 동일 소유 복구를 포함한다. 실제 측정 쌍·품질 근거·절감 효과는 아직 없다.

기본 경로는 연결된 현재 AI의 짧은 판단·대화 선택·필요한 지침 읽기이며 로컬 도구도 필요한 사건에만 호출한다. native 입력 지원 근거가 확보되면 상태 자동 전달·문맥 주입을 추가 검증한다. 앱 연동이 확인됐다고 전역 자동화 허용으로 확대하지 않는다.

## 피드백 이전 준비 완료

실제 실행 전에 독립적으로 준비할 수 있던 세 항목을 정리했다. 별도 모델/worker·독립 평가·실제 측정은 실행하지 않았다. 이 자료를 일반 입력마다 주입하지 않는다.

| 준비 | 산출물 | 확인 범위 |
| --- | --- | --- |
| 비교 실험 | [네 유형의 입력·고정 완료 기준과 실행 준비](../experiments/routing-pilot/README.md) | 짧은 설명·두 턴 후속·작은 코드 수정·복합 설계 검토. 한 유형의 한 쌍부터 계획, 모델 고정·위임 금지, 전체 단계 누락 보존 |

| 시간·금액 계산 연결 | [비교 v2](../runtime/routing-metrics.md), 시간·단가표 양식 | 선언된 요청 전체 시간과 관측 모델의 단가 추정. 신규 25개를 포함한 관련 102개 검사·독립 재검토 통과. 실제 요금·시간/금액 절감·청구 검증은 미수행 |

RP-03 기능 검사기는 정상 예시 1개 통과와 의도적으로 잘못 만든 구현 6개 거절을 로컬에서 확인했다. 사례의 Python 코드 블록 2개도 구문 확인했다. 이것은 검사 자료의 자체 확인이며 실제 AI 결과의 품질이나 성능 측정이 아니다. 공개한 사례는 작성자가 알고 있으므로 미공개 평가 세트라고 부르지 않는다.

2026-11-15 공개 전 통합 확인에서 Python 검사 495개를 확인했다. 최초 실행의 localhost bind 제한 한 건은 해당 HTTP 검사만 정식 권한 경로로 재실행해 통과했다. 공개 후보에는 범용 코드·문서·가상 입력만 포함하며 실제 원본·세션 식별자·개인 경로·수집 결과는 포함하지 않는다. 이 회귀 검증은 실제 비용 절감이나 native 자동 연결의 성공 근거가 아니다.

| 2 | 후속·취소·목표 변경의 실제 운영 검증 | 사용자 만족도 피드백 없이 검증 가능. 추가 worker가 필요하면 새 실행 선택·한도를 먼저 확정하고 기존 1회 허용을 재사용하지 않음 |
| 3 | 실제 튜터·추천 품질과 개인 사용성 | 독립 정확성 평가는 실행 선택 후 가능. 사용자가 이해하기 쉬운 정도·선호 분량·추천 빈도는 실제 피드백 필요 |
| 4 | 시간·금액의 실제 근거 확인 | v2 입력·계산 연결은 구현됨. 실제 요청 시각·기간별 공식 단가/적용 조건·조율자 등의 관측 모델을 확보해야 전체 비교 가능. 추정치를 실제 청구액으로 보고하지 않음 |
| 5 | 현재 대화 모델/effort 전환·복귀 | 공식 적용 경로·선택·범위·실제값 대조가 필요. 현재 수동 설정 안내이며 역할 적용을 worker로 바꾸지 않음 |
| 6 | hook·자동 상태 전달·선택 UI | 공식 로딩·신뢰·같은 런타임 조회/이벤트 근거 확보 후 재개. 같은 실패 시험은 반복하지 않음 |
| 7 | 이득이 확인된 유형만 제한 자동화 | 반복 비교의 품질·전체 비용 이득과 사용자 허용 유형·한도·중단 조건이 모두 필요 |

**보류:** native hook·자동 상태 전달·별도 선택 UI는 정확한 정의의 공식 검토·승인 경로가 확보되면 재개한다. 일반 hook 지원과 프로젝트 신뢰는 확인했지만 우리 프로젝트 hook의 개별 승인 기록과 같은 런타임 조회 경로는 미확인이다. 동일 probe·worker 시험이나 UI 탐색을 반복하지 않는다.

**이미 확인:** 단일 Sol/medium worker의 역할 수신·요청/실행환경 적용·replay·정확한 종료. 공급자 실제 관측·토큰은 미확인이며 기존 한도 1을 초기화해 추가 시험하지 않는다. 기본 설명·선택은 현재 AI의 지침/대화 기반 경로로 운영하며 새 모델·worker 실행의 사용자 선택과 실제 권한 준비는 생략하지 않는다.

자연어의 제어·의도·후속 여부는 현재 AI가 해석하고 공통 진입점에 전달한다. 앱의 자동 상태 추출·자연어 파서는 아직 없다. 로컬 도구는 전달받은 해석의 정책 준수와 상태 연결을 검사하므로, 입력과 기대값이 맞아도 추천 의미 판단의 정확도나 토큰 절감률을 얻은 것은 아니다. 실제 품질 평가에서는 원래 요청, 사용한 지침 버전, 실제 판단/응답, 출처와 판정 근거를 연결하고 측정하지 않은 모델·effort·사용량을 추정하지 않는다. 실제 대화 기록은 지정된 비공개 위치에 보관한다.
