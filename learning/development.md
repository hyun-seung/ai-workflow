# 튜터·요청 라우팅 통합 개발 순서

튜터와 역할·모델/effort 추천을 같은 진입 흐름에서 개발한다. 매 요청의 추가 토큰 최소화, 직접 처리 선택, 공식 근거와 필수 품질을 공통 기준으로 둔다. 역할 문서나 로컬 도구의 존재를 앱 연동 완료로 간주하지 않는다.

## 우선순위

| 순서 | 통합 작업 | 완료 기준과 현재 범위 |
| --- | --- | --- |
| 1 | 튜터 기본 응답·추천 생략 기준 정리와 대표 사례 점검 | 짧은 튜터 진입 지침, 공식 근거에 기반한 참고 답변, 튜터/일반 요청의 점검 입력을 작성. 로컬 라우터의 정책 경로와 코드 예시는 확인하되 자연어 추천 품질·사용자 학습 효과의 통계 평가와 구분 |
| 2 | 튜터 심화 방식·추천의 실제 품질 평가 | 원리·스티커 메모·마인드맵·도식·한 장 시트·파인만·연관 Q&A를 대표 주제에 적용. 자료 없는 질문·실제 개발 요청·설정 고정까지 포함해 불필요한 추천·오분류·출처 오류·분량 초과를 기록. 현재 AI의 자체 판단과 사용자/독립 평가를 구분 |
| 3 | Orca 입력·대화 상태 연결 | [입력 어댑터](../runtime/orca-routing-input.md)와 13개 검사 구현. Orca 플러그인은 직접 사용자 입력을 hook하지 않아 Codex 공급자 이벤트 대상으로 준비. 정확한 native 식별자·경로·hook 신뢰·실제 이벤트 검증은 남아 있음 |
| 4 | 사용자 선택과 같은 AI의 역할 적용 | [로컬 선택 기록·26개 검사](../runtime/routing-choices.md) 구현. 요청·제안 버전별 수용/거절/취소·만료·중복, 선택한 역할 지침 준비와 명시한 후속 대화의 선택 재사용 확인. 자연어 동의·선택 UI·동일 AI에 실제 적용·입력 snapshot 동기화는 남아 있음 |
| 5 | 명시한 병렬 위임·모델/effort 전환 | [수용한 worker 선택의 관리 실행·완료 대조](../runtime/routing-dispatch.md)와 19개 가상 응답 검사·독립 검토 완료. 같은 동의의 복수 실행·프로필 대체 방지. 이 경로의 실제 배정 검증·현재 대화의 프로필 전환·병렬 준비 효과는 남음 |
| 6 | 직접 처리 대비 비용·품질 비교와 제한 자동화 | 같은 완료 기준에서 추천·선택·출처 탐색·인계·통합·재작업까지 비교. 토큰·시간·품질의 근거가 있는 유형만 자동화 허용. 미측정은 절감으로 보고하지 않음 |

각 단계에서 튜터의 발견된 문제를 고친다. 튜터 전체를 별도 완성한 뒤 라우터를 다시 붙이거나, 모든 단계를 한꺼번에 구현하지 않는다. 현재 순서는 의존성에 따른 개발 계획이며 모델/worker 실행·지속 설정 변경의 포괄 승인이 아니다.

## 1차 산출물과 확인 범위

- [짧은 튜터 진입 지침](tutor-brief.md): 단순 설명에 맞춘 필수 행동. 심화 요청에만 상세 역할 문서 확인.
- [공식 문서 기반 참고 답변](reference-response.md): 가상 Python 질문을 재구성한 답변·짧은 응답·파인만 요청 예시. 실제 코드를 확인하되 다른 주제의 품질까지 일반화하지 않음.
- [통합 점검 입력](../examples/tutor-routing-cases.json): 작성 AI가 정리한 요청 해석과 라우터 입력·기대 정책 결과. 기대값을 알고 작성한 자체 점검 자료이며 독립 자연어 분류 시험이 아님.

1차 로컬 확인: 작성한 점검 입력 12개의 정책 결과가 기대값과 일치했고, 참고 답변의 Python 코드 3개의 출력이 설명과 일치했다. 공식 튜토리얼의 대입·리스트 복사 절을 원문 확인했다. 이는 정책 연결과 한 주제 예시의 자체 확인이며 실사용 오분류율·학습 효과·토큰 절감의 측정이 아니다.

2단계의 [대표 응답 16개](evaluation-responses.md)에 대해 세 기술 주제의 공식 근거·분량·전환·추천 필요성을 자체 검토하고 [평가 결과](evaluation.md)를 남겼다. 시각 예시 네 방식의 두 화면 폭 확인, 모바일 시트·마인드맵·키보드 전환과 지침 보완을 수행했다. 독립 추천 정확도·사용자 학습 효과·토큰 절감은 미검증이다.

## 연결 범위와 검증 근거

- **입력 어댑터:** 빈 상태는 추가 문맥을 출력하지 않고 명시 snapshot만 최대 512문자 힌트로 전달한다. 원문·transcript 저장/탐색·별도 모델 호출은 없다. Orca 1.4.257에서 정확한 native 바인딩·공식 hook 신뢰 경로를 확보하지 못해 설치·활성화하지 않았다. [지원 경계와 13개 검사](../runtime/orca-routing-input.md).
- **선택 기록·후속 재사용:** 요청 원문·추천 이유를 저장하지 않고 요청/추천 버전과 수용·거절·취소를 기록한다. 같은 요청임이 명시되고 문맥이 일치할 때만 역할 본문 재로딩 없이 선택을 재사용한다. [보관·처리 계약과 26개 검사](../runtime/routing-choices.md).
- **명시 위임 연결:** 수용한 worker 선택과 모델/effort를 한 ledger·operation·계획에 고정하고 공통 지침 참조·선택 역할만 전달한다. 완료 시 요청·실행환경 적용·실제 관측을 대조한다. [가상 응답 19개 검사·독립 검토와 미검증 범위](../runtime/routing-dispatch.md). 실제 native 실행·현재 대화의 프로필 전환 성공을 확인한 것은 아니다.
- **회귀 확인:** 이 세 연결과 기존 관리 실행·완료 수집을 포함한 Python 검사 394개 통과. 독립 검토의 공통 지침·역할 원본 경로 전달 누락을 보완했다. 단위 검사·가상 응답을 실제 통합이나 토큰 절감 근거로 확대하지 않는다.

실제 입력 지원 근거가 확보되면 입력 수신→선택 UI·문맥 적용을 검증한다. 앱 연동이 확인되기 전 전역 자동화로 확대하지 않는다. 현재 구현은 필요할 때 명시 호출하는 로컬 경로이며 모든 입력의 필수 절차가 아니다.

## 남은 작업

1. **공식 입력 연결·선택 UI:** 정확한 native 바인딩·hook 신뢰 경로 확보 후 실제 사용자 입력 한 건과 선택/취소·snapshot 동기화 검증. 지원 근거 변화 없이 UI 탐색을 반복하지 않음.
2. **같은 AI의 역할·설정 적용:** 필요한 지침의 실제 전달·재주입/문맥 소실과 취소 처리. 현재 대화의 모델/effort 전환은 공식 지원 경로·실제값을 확보한 뒤 연결.
3. **선택→위임→완료의 실제 한 건:** 사용자가 구체적 모델·effort·위임·한도를 선택한 범위에서 새 opt-in 경로를 실행하고 실제 인자·receipt·세 단계 프로필·중복 재조회 확인. 필요한 native 세션 원본 경로는 공식 근거로만 확보.
4. **실사용 품질·전체 비용 비교:** 튜터 설명/연관 Q&A·불필요한 추천·오분류를 사용자 또는 독립 평가와 연결. 같은 완료 기준의 직접 처리와 추천/선택/인계/검증/재작업까지 측정. 현재 자체 예시 점검을 실사용 정확도로 확대하지 않음.
5. **이득이 확인된 유형만 제한 자동화:** 사용자가 허용한 범위·한도·중단 조건 안에서 확대. 측정되지 않은 토큰을 절감으로 보고하지 않음.

1·2의 앱 지원 경로가 남아 있어도 명시 선택을 받은 3번의 제한 검증이나 기존 기록을 이용한 4번 비교 준비는 독립적으로 진행할 수 있다. 새 모델·worker 실행 자체의 사용자 선택과 실제 권한 준비는 생략하지 않는다.

자연어에서 제어·의도·후속 여부를 추출하는 연결은 아직 없다. 로컬 도구는 전달받은 해석의 정책 준수만 검사하므로, 입력과 기대값이 맞아도 추천 의미 판단의 정확도나 토큰 절감률을 얻은 것은 아니다. 실제 품질 평가에서는 원래 요청, 사용한 지침 버전, 실제 판단/응답, 출처와 판정 근거를 연결하고 측정하지 않은 모델·effort·사용량을 추정하지 않는다. 실제 대화 기록은 지정된 비공개 위치에 보관한다.
