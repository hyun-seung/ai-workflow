# 튜터 심화·추천 품질 1차 자체 평가

상태: 2026-11-13 대표 응답의 자체 검토와 로컬/화면 확인 완료. 독립 평가·블라인드 시험·사용자 학습 효과·실사용 오분류율·토큰 절감은 미검증이다. [통합 개발 순서](development.md)의 2단계에서 확인한 범위와 제한을 기록한다.

위 상태와 아래 사례별 표는 당시 자체 평가다. 2026-11-16 별도 검토자가 다섯 응답을 확인해 발견한 문제와 후속 수정은 [독립 콘텐츠 검토](#2026-11-16-독립-콘텐츠-검토와-수정)에 추가했다. 과거 자체 판정을 독립 판정으로 바꾸거나 수정본에 이전 판정을 자동 적용하지 않는다.

최신 지침 보완은 [2026-11-17 후속 설명·시각화 점검](#2026-11-17-후속-설명시각화-보완)이다. 한 주제의 설명 형식 피드백을 다른 주제의 품질·사용자 학습 효과·비용 이득까지 일반화하지 않고 다음 주제에서 재확인한다.

## 방법과 완료 기준

Python 객체 복사, HTTP 캐시, PostgreSQL 트랜잭션 세 주제에 대해 [가상 요청과 생성 응답 16개](evaluation-responses.md)를 작성하고, 같은 작성 AI가 다음 기준으로 검토했다. 실사용 대화나 비공개 프로젝트 내용은 사용하지 않았으며 분류·평가 전용 AI를 추가 호출하지 않았다. 현재 작성 AI의 실제 모델·effort·전체 토큰을 별도 수집하지 않았으므로 값을 추정하지 않는다.

1. 요청한 방식과 분량에 맞는가? 쉬운 말·원리·관계·예외가 일치하는가?
2. 사실을 공식 문서의 해당 절이 실제로 뒷받침하는가? 재구성·비유·직접 만든 수치가 구분되는가?
3. 모르는 자료·불명확한 대상·잘못된 전제에 대해 지어내거나 상향 추천하지 않는가?
4. 질문을 기다리는 파인만 방식과 질문·답을 함께 주는 Q&A를 구분하는가?
5. 작은 설명·후속 요청에서 불필요한 역할 승인·모델 전환·별도 worker가 없는가?
6. 그림의 분류·흐름·단위·분기가 정확하고 실제 화면에서 읽을 수 있는가?

판정은 아래의 확인 범위에 한정한다. 응답 작성자가 기대 결과와 기준을 알고 있으므로 모든 항목이 적합해도 일반화 정확도를 계산하지 않는다. 반복·독립 평가에서 재현되는지와 사용자가 이해하기 쉬운지는 별도다.

## 실행·화면 확인

- [통합 입력 12개](../examples/tutor-routing-cases.json)의 작성된 해석을 로컬 라우터에 넣어 기대 정책 경로와 대조했다. 이는 입력된 해석의 정책 검사이며 자연어 의도를 자동으로 맞힌 12회가 아니다.
- TE-15의 모델/effort 고정·위임 금지에서 역할만 제안하는 경로를 별도로 확인했다. `executable=false`이며 실행·설정 변경은 없다.
- TE-14의 Python 코드 1개를 실행해 assertion을 확인했다. PostgreSQL 서버·HTTP 서버 통합 시험은 수행하지 않았으며 해당 개념은 공식 원문으로 확인했다.
- [시각 예시 HTML](visual-samples.html)의 네 탭을 Orca 브라우저에서 1000px·390px 폭으로 확인했다. 네 방식 모두 가로 넘침 없이 선택한 패널 하나만 표시됐다. 마인드맵·도식·메모·학습 시트의 스크린샷을 직접 확인했다.
- 한 장 시트의 좁은 화면 초안은 본문 높이 약 890px로 길었다. 수정 후 390×844 화면에서 가로 넘침이 없고 하단 안내까지 포함한 끝 위치가 약 720px였다. 이는 해당 예시의 배치 결과이며 모든 시트를 같은 화면에 넣는 보장은 아니다.
- 탭의 Home·ArrowRight 전환으로 마인드맵 선택을 확인했다. 스크린리더 전수 검사·모든 브라우저·모든 테마·초소형 화면 검증은 수행하지 않았다.

시각 확인용 탭은 작업 종료 때 닫으며, 소스 HTML과 채팅용 미리보기만 유지한다. 원시 연결 상태·스크린샷 경로·개인 세션 정보는 공개 문서에 넣지 않는다.

## 반영한 보완

- 그림·시트가 주된 요청일 때 같은 내용을 긴 본문·Q&A로 반복하지 않도록 튜터 지침 보완.
- 마인드맵 연결선, 모바일 학습 시트 배치, 키보드 탭 선택 보완.

- ELI5 기본 응답의 연관 Q&A 누락 보완. 짧은 요청에는 여전히 Q&A를 강제로 붙이지 않음.

## 다음 단계와 미검증

현재 범위의 자체 검토에서는 진행을 막는 설명·정책·배치 문제를 보완했다. 이 1차 평가 이후의 진행은 [통합 개발 순서](development.md)를 따른다. 이 결과만으로 자동 위임·모델 선택을 켜거나 추천 품질이 보장됐다고 간주하지 않는다.

독립 평가·블라인드 입력·비기술 주제·반복 실행·사용자 이해도·실제 추천 빈도·전체 시간과 토큰 비교는 남아 있다. 향후 연결된 실제 결과도 같은 기준으로 점검하며, 설명 오류나 불필요한 추천이 나타나면 해당 단계의 규칙·판단을 수정한다. 이 문서를 일반 요청마다 모델에 주입하지 않는다.

## 2026-11-14 후속 자체 점검

[기본 인입·튜터 점검](basic-flow-check.md)에 비개발 개념인 필요조건/충분조건과 후속·인용·취소·자료 부족 응답 여섯 개를 추가했다. OpenStax 원문 두 절을 확인하고 관계의 방향·반례·근거 대응·한 문장 제한·Q&A 반복 생략을 자체 검토했다.

작성된 [정책 입력](../examples/tutor-routing-cases.json)은 12개에서 16개로 늘렸고 모든 기대 action을 로컬에서 대조했다. 가상 취소 상태의 선택 null·cancelled·후속 direct도 확인했다. 관련 회귀 검사 106개가 통과했으며 새 모델/worker는 호출하지 않았다. 이것은 독립 자연어 분류 정확도나 실사용 만족도·토큰 절감의 측정이 아니다. 아래 해시는 기존 1차 평가의 범위이며 후속 응답의 버전은 해당 문서로 구분한다.

## 2026-11-16 독립 콘텐츠 검토와 수정

사용자가 선택한 Sol/medium 읽기 전용 검증자 한 건이 기존 응답 다섯 개를 검토했다. 동시 1·누적 1·자동 재시도 없음, 공식 문서 최대 네 페이지 범위다. 작성자의 자체 판정을 제외한 입력과 짧은 튜터/라우팅 지침을 전달했다. 검토자는 공식 페이지 네 개를 확인하고 파일 변경·코드 실행 없이 결과를 반환했다. 정확한 worker 종료와 관리 슬롯 해제를 확인했다.

기준은 사실·출처·형식·제어·근거의 한계 다섯 항목이다. 원래 입력의 SHA-256은 `fdf9e25bd9ac88c4141dd712dc3f4e2bc67705857e8700a1e252d59eae3f62b6`이며 원래 응답·판정은 비공개 기록에 보존했다. 다음 표는 **수정 전 응답**에 대한 독립 판정이다.

| 검토 ID / 원래 사례 | 독립 종합 판정 | 발견 사항 |
| --- | --- | --- |
| Q1 / TE-01 | pass | 대입·얕은 복사·비유·Q&A와 공식 근거가 부합 |
| Q2 / TE-08 | unverified | 사실과 RFC 근거는 부합하지만 평가 입력에 HTTP 선행 맥락이 없어 후속의 관련성·대상 근거를 확인하지 못함 |
| Q3 / TE-15 | fail | 자료 요청이나 검토 없이 근거 불충분한 역할 승인 선택지를 제시. 필요한 자료 부족도 드러내지 않음 |
| Q4 / TE-16 | fail | PostgreSQL 반례·출처는 정확하지만 기본 설명의 연관 Q&A가 빠진 형식 문제 |
| Q5 / BF-04 | pass | 인용문을 실제 모델 변경 지시로 채택하지 않고 직접 설명 |

반영한 내용은 다음과 같다.

- **TE-08 / 평가 입력:** 가상 HTTP 선행 맥락을 명시했다. 원래 입력의 누락을 응답의 사실 오류나 다른 사례의 후속이라고 단정하지 않는다. 평가 절차·양식에도 필요한 맥락과 자료 제공 여부를 포함하도록 보완했다.
- **TE-15 / 응답·진입 지침:** 자료가 제공되지 않은 조건을 명시하고, 모델·effort를 유지한 채 자료부터 요청하도록 수정했다. 역할 승인을 정보 부족의 해결책으로 삼지 않는다. 이미 자료가 있는 경우 다시 요구하라는 규칙은 아니다.
- **TE-16 / 응답:** 관련 질문·답 두 개를 추가하고 PostgreSQL의 [일반 SELECT와 연속 조회 설명](https://www.postgresql.org/docs/current/transaction-iso.html#XACT-READ-COMMITTED)을 작성자가 직접 대조했다. 사실 오류와 형식 누락을 구분하며 한 줄 요청·짧은 후속에도 Q&A를 강제하는 규칙은 추가하지 않았다.

수정본은 작성 AI가 출처·문장·제어를 자체 확인했다. **수정본의 독립 재평가와 실제 사용자 만족도는 미수행**이며 이전 fail/unverified를 pass로 바꾸지 않는다. 공개된 작성 사례의 소규모 콘텐츠 검토를 실사용 추천 정확도·블라인드 성능·학습 효과·비용 절감률로 일반화하지 않는다.

후속 구현에서는 현재 AI가 필수 자료 부족을 표시한 경우 [로컬 검사기](../runtime/request-router.md)가 후보·이전 선택을 재사용하지 않고 `needs_input`을 반환하도록 연결했다. 새 상태/제안 미생성·기존 선택 불변·카탈로그 미호출·직접 제어·엄격한 boolean을 포함한 관련 검사 113개와 작성 정책 입력 17개를 확인했다. 이 단위/연결 검증은 수정본 설명의 독립 재평가나 자연어 자료 부족 판단의 정확도 측정이 아니다.

요청·실행환경 적용 모델/effort와 공급자 관측을 구분한다. 공급자 실제 모델·effort·사용량은 원본이 없어 미확인/미측정이며, 평가·재작업 비용을 0으로 기록하지 않는다. 실사용 이해도·분량·추천 빈도는 사용자 피드백으로 확인해야 한다.

## 2026-11-17 후속 설명·시각화 보완

실사용 피드백을 기준으로 지침과 응답을 자체 검토했다. 후속에서도 설명을 유지한다는 규칙은 있었지만, 짧은 지침에 관계·흐름의 시각화 선택 기준이 없고 텍스트 대체가 실제 표시 확인 없이 사용될 수 있었다. 긴 본문 반복·설계의 권한/네트워크 누락·지침 적용을 전체 정상 동작으로 확대하는 보고도 보완 대상으로 구분했다. 텍스트 도식이 전혀 없었다거나 꼬리 질문에서 튜터가 비활성화됐다고 단정하지 않는다.
