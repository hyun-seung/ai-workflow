# 공개 및 비공개 정보 관리

이 저장소는 공개를 전제로 하며, 공통 원칙과 공개 가능한 가상 예시만 포함한다. 공개 범위를 판단하기 어렵다면 게시를 보류하고 사용자에게 확인한다.

## 정보와 저장 위치

| 정보 | 기본 위치와 처리 |
| --- | --- |
| 범용 지침과 가상 예시 | 공개 ai-workflow 저장소 |
| 프로젝트 공개 규칙 | 공개 가능 여부를 확인한 해당 프로젝트 저장소 |
| 개인 설정과 비공개 프로젝트 자료 | 사용자가 지정한 개인 보관 위치 또는 조직이 승인한 환경 |
| 비밀번호, 토큰, API 키, 개인 키 | 문서에 기록하지 않고 승인된 자격 증명 저장소 또는 비밀 관리 도구 사용 |
| 공개 여부가 불명확한 정보 | 공개하지 않고 내용과 용도를 최소한으로 설명해 사용자에게 확인 |

- 작업 디렉터리는 사용자가 정하거나 현재 작업에서 명시한 프로젝트를 사용한다. 비공개 자료의 위치가 정해지지 않았다면 저장 전에 확인한다.
- 개인 보관 폴더는 공개 저장소 바깥에 두는 것을 권장한다. 구체적인 경로와 이름은 각 사용자가 선택한다.
- 회사·고객 정보는 개인 PC나 외부 AI로 옮기기 전에 조직의 보안 정책과 허용 범위를 확인한다.
- 로컬 보관은 암호화·접근 제어·백업을 보장하지 않는다. 별도로 필요한 보호 및 백업 방법을 선택한다.

## 접근과 외부 전달

- 작업에 필요한 파일만 읽는다. 개인 폴더는 존재한다는 이유만으로 탐색하지 않는다. 사용자가 필요한 파일이나 범위를 지정했다면 그 범위에서 작업한다.
- 민감한 자료를 외부 서비스 또는 다른 에이전트에 전달하기 전에는 전달할 정보, 대상과 목적을 확인한다. 비밀 값은 프롬프트, 예제, 로그나 메시지에 넣지 않는다.
- 파일이 로컬에 있거나 Git에서 무시되더라도 도구에 접근 권한이 있다면 읽힐 수 있다. 실제 접근·전송과 보관 정책은 사용하는 도구와 설정을 확인한다.
- 예제와 테스트에는 가상의 값과 가공된 데이터를 사용한다. 로그, 스크린샷, 파일 이름과 경로에도 민감한 내용이 있는지 살핀다.

## 공개 전 확인

1. 변경 대상 파일과 커밋할 내용을 확인한다.
2. 개인·고객 정보, 조직 내부 자료, 실제 주소와 인증 정보가 포함됐는지 살핀다.
3. 공개 가능 여부가 불명확하면 게시하지 않고 확인한다.
4. 지원되는 비밀 탐지 도구와 GitHub push protection을 보조 수단으로 활용한다. 탐지 도구가 모든 민감 정보를 찾지는 못한다.

저장소의 .gitignore는 추적되지 않은 특정 경로의 실수 커밋을 줄일 뿐이다. 이미 추적 중인 파일에는 소급 적용되지 않고, 접근 제어·암호화 또는 비밀 탐지를 대신하지 않는다. .env.example에는 반드시 가상 값만 넣는다.

## 실수로 공개했다면

추가 노출을 중단하고 사용자와 조직의 대응 절차에 알린다. 인증 정보는 가능한 한 즉시 폐기·교체하고, Git 이력과 복제본에 남을 수 있으므로 서비스 제공자의 민감 정보 제거 안내에 따라 처리한다. 단순히 파일을 삭제하는 것만으로 완전한 제거를 보장할 수 없다.
