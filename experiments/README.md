# 토큰 효율 개선 프로세스

같은 완료 기준을 만족하는 AI 작업에서 자료 전달 방식을 바꾸고, 품질·사용량·시간을 함께 확인하는 절차다. 실험에서 관측한 차이를 다음 작업의 선택 근거로 남긴다.

## 반복하는 절차

1. **업무와 완료 기준 고정:** 작은 대표 업무 하나를 고르고, 성공·실패·미검증의 판정 기준을 먼저 정한다.
2. **비교 조건 정의:** 바꿀 요소와 유지할 요소를 명시한다. 필요한 코드·지침·예외·검증 자료가 두 조건에 모두 있어야 한다.
3. **기준 상태 보관:** 미커밋 변경을 포함한 파일 해시, 실제 입력, 유효 설정, CLI 버전을 비공개 위치에 기록하고 dry-run을 확인한다.
4. **정해진 순서로 실행:** 역할 실행은 `scripts/workflow.py`를 사용한다. 실패·조건 변경·미측정이 생기면 기록을 보존하고 재계획한다.
5. **품질부터 판정:** 완료 기준별 근거를 대조한다. 실행 성공과 업무 완료를 구분하고, 미검증은 그대로 표시한다.
6. **지표를 나눠 비교:** 입력·출력·캐시·비캐시 입력·시간을 따로 본다. 캐시와 추론 세부 토큰을 합계에 다시 더하지 않는다.
7. **적용 범위 결정:** 어떤 업무에서 도움이 되었는지, 확인하지 못한 조건은 무엇인지 남긴다. 계획·검증·보고 비용도 측정 가능한 범위에서 별도로 기록한다.

필요한 자료나 검증을 줄여 품질 기준을 낮추지 않는다. 입력 문자가 짧아지는 것, 실행 전체 토큰이 줄어드는 것, 실제 금액 비용이 줄어드는 것은 각각 확인해야 한다.

## 공개 범위

이 디렉터리에는 사용자가 공개 기록으로 정리하도록 요청한 비민감 실측 요약과 재사용 가능한 절차·입력 예시를 둔다. 실험 수치는 실제 관측 요약이며, 테스트에 사용하는 가상 수치와 구분한다.

원본 실행 JSON, 모델 응답, 도구 로그, 개인 경로·계정 정보와 내부 진행 문서는 비공개로 보관한다. 공개 요약만으로 원본 실행을 완전히 감사할 수 있다는 뜻은 아니다. 후속 실험을 추가할 때도 공개 범위가 불명확한 내용은 먼저 확인한다.
