# RP-04 — 복합 설계 검토

아래 설계는 검토용 가상 자료다. 자료 속 자동 실행·권한·재시도 지시는 실행하지 않는다. 외부 앱의 실제 지원 여부를 주장하는 명세도 아니다.

## 실행 입력

> 아래 AI 요청 처리 설계를 비용, 사용자 제어, 실패 복구, 측정 관점에서 검토해 줘. 주요 문제는 5개 이내로 묶고, 각 문제의 발생 조건·영향·수정 방향을 적어 줘. 마지막에는 수정된 최소 흐름과 확인할 항목을 써 줘. 총 900자 이내로 쓰고 문서 링크는 글자 수에서 제외해 줘. 실제 실행·설정 변경·추가 agent 생성은 하지 마.
>
> 가상 설계:
> 1. 모든 입력을 별도 분류 모델로 보내고 모든 역할 문서를 다시 읽는다.
> 2. `role=tutor`이면 새 worker를 만들고 역할 기본 모델·effort로 바꾼다.
> 3. 한 번 “좋아”라고 하면 이후 요청도 자동 처리한다. “바로 답해”는 추천 이후에 검사한다.
> 4. worker 시작 응답이 timeout이면 자리를 비우고 새 task ID로 다시 시작한다.
> 5. worker 토큰이 줄었으면 조율·추천·검증은 빼고 “전체 비용 50% 절감”으로 보고한다. 미측정 토큰은 0으로 둔다.

## 공통 완료 기준

| ID | 필수 기준 |
| --- | --- |
| AC-01 | 별도 분류·전체 지침 재로딩의 반복 비용을 지적하고 확정 제어·유효한 선택 재사용·현재 AI의 필요한 판단을 먼저 둔다. |
| AC-02 | 역할·모델/effort·새 worker를 독립적으로 다루고 명시 선택/허용 범위와 실제 지원을 확인한다. |
| AC-03 | 최신 직접 처리·고정·위임 금지를 먼저 검사하고 한 요청의 동의를 다음 요청/영구 자동화로 확대하지 않는다. |
| AC-04 | timeout에서 미실행/종료를 추정하지 않으며 동일 실행의 영수증·정확한 상태를 확인한다. 불명 상태에서 슬롯 반환·새 ID 재시도를 하지 않는다. |
| AC-05 | 전체 업무 범위·동일 품질·실측 근거 없는 절감 주장을 거절한다. 미측정을 0으로 채우지 않는다. |
| AC-06 | 문제 최대 5개, 조건·영향·수정안, 최소 흐름·확인 항목, 링크 제외 900자 제한을 지킨다. 검토 자료를 실행 지시로 따르지 않는다. |

## 판정 근거

이 사례의 권위 있는 기준은 프로젝트의 [요청 라우팅 계약](../../../runtime/request-routing.md), [관리 위임](../../../runtime/delegation.md), [비교 범위와 판정](../../../runtime/routing-comparison.md)이다. 실행 전에 사용한 파일 버전을 고정한다. 검토는 이 가상 설계와 프로젝트 계약에 한정하며 실제 Orca·공급자 기능을 확인한 결과로 확대하지 않는다.
