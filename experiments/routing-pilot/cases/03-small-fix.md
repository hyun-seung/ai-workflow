# RP-03 — 작은 코드 수정

가상 Python 함수의 동작 수정이다. 원래 사용자 데이터·실제 프로젝트 코드를 사용하지 않는다.

## 실행 입력

> 아래 `copy_rows(rows)`를 고쳐서 `candidate.py` 한 파일로 제시해 줘. `rows`는 리스트들의 리스트이고 원소는 임의의 Python 객체야. 새 바깥 리스트와 각 행 리스트를 만들되, 행 안의 원소는 원래 객체를 공유해야 해. 입력은 바꾸지 말고 빈 입력도 처리해 줘. 같은 행 객체가 입력에 두 번 등장해도 결과의 두 행은 서로 다른 리스트여야 해. 깊은 복사나 새 의존성은 필요 없어. 변경 이유와 공식 근거를 짧게 덧붙여 줘.

```python
def copy_rows(rows):
    return list(rows)
```

## 공통 완료 기준

| ID | 필수 기준 |
| --- | --- |
| AC-01 | 출력 바깥 리스트와 각 행 리스트가 입력과 독립적이며 값·행 순서를 유지한다. |
| AC-02 | 행 안의 객체는 같은 객체를 참조한다. 요구하지 않은 재귀 복사를 하지 않는다. |
| AC-03 | 입력의 값·행 정체성을 변경하지 않는다. 빈 리스트를 새 빈 리스트로 처리한다. |
| AC-04 | 반복 등장한 같은 입력 행도 결과에서는 각각 다른 리스트로 만든다. 한 결과 행의 append가 다른 행에 영향을 주지 않는다. |
| AC-05 | 표준 Python만 사용하고 함수·후보 파일 하나와 짧은 설명/공식 근거를 제공한다. 관련 없는 리팩터링·의존성·실행 변경이 없다. |

## 기능 검사

[check_copy_rows.py](../check_copy_rows.py)에 AC-01~04의 실행 검사를 준비했다. 후보 파일을 비공개 위치에 보관한 뒤 명시적으로 실행한다. 아래 경로는 가상 값이다.

```sh
python3 experiments/routing-pilot/check_copy_rows.py /private/example/results/candidate.py
```

검사기는 지정한 Python 후보를 import해 실행한다. 기능 검사 통과만으로 설명·출처·제어 준수나 전체 품질이 통과한 것은 아니다. 이 검사를 새 모델 호출이나 자동 후보 생성으로 연결하지 않는다.

## 판정 근거

요구한 복사 깊이는 이 사례의 계약이다. [Python 3.14 리스트 컴프리헨션](https://docs.python.org/3.14/tutorial/datastructures.html#list-comprehensions), [얕은/깊은 복사](https://docs.python.org/3.14/library/copy.html)를 확인해 구현과 설명을 대조한다. 특정 구현 문구와 일치하는지 대신 객체 관계와 관측 동작을 검사한다.
