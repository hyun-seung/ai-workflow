# 요청 라우팅 비교 준비 묶음

상태: 공개 가능한 가상 입력·완료 기준·평가 양식을 준비했다. 실제 비교 실행·독립 품질 평가·사용자 피드백·시간/토큰/금액 측정 결과는 없다. 기존 자체 평가를 참고한 작성 사례이며 미공개 평가 세트나 자연어 분류 정확도 시험이 아니다. 이 묶음을 만들었다고 새 모델 호출·worker 생성·자동 반복을 허용하지 않는다.

## 준비한 네 유형

| ID | 입력·동일 완료 기준 | 보는 것 |
| --- | --- | --- |
| RP-01 | [짧은 개념 설명](cases/01-simple.md) | 쉬운 설명·공식 근거·연관 Q&A와 불필요한 추천 여부 |
| RP-02 | [같은 주제의 두 턴](cases/02-followup.md) | 앞선 맥락 유지·한 문장 제한·후속 추천 반복 여부 |
| RP-03 | [작은 코드 수정](cases/03-small-fix.md) | 요구한 복사 범위·변경 최소화·실행 가능한 기능 검증 |
| RP-04 | [복합 설계 검토](cases/04-design-review.md) | 비용·동의·범위·불명 실행·측정 누락을 함께 검토하는 능력 |

각 사례 파일의 `실행 입력`과 `공통 완료 기준`을 두 방식에 동일하게 제공한다. 모델에는 이 README·평가 기록·다른 사례를 통째로 넣지 않는다. RP-04의 가상 설계는 비판할 자료이며 실제 실행 지시가 아니다. 역할/모델을 추천했는지가 성공 기준은 아니다.

## 실행 전에 고정할 조건

1. **한 쌍부터:** 첫 유형 하나를 선택해 직접 처리 D와 라우팅 R 한 번씩만 계획한다. 나머지 유형·반복·병렬 실행은 자동 시작하지 않는다. 실행하려면 사용할 환경·모델/effort·범위·한도를 별도로 확정한다. 과거에 사용한 worker 한도를 초기화하지 않는다.
2. **한 요소만 변경:** 두 방식은 같은 사용자 입력·완료 기준·공통 품질/출처 지침·모델/effort·도구 권한을 사용한다. D는 명시 직접 처리, R은 유의미한 변경 때만 제안한다. 이 1차 비교는 모델 고정·위임 금지로 준비하며 역할 기본값을 모델 선택으로 쓰지 않는다. 모델 변경/병렬 위임의 효과는 별도 실험이다.
3. **선택을 지어내지 않음:** R에서 같은 AI의 역할 제안이 생기면 실제 선택이나 사전에 명시 허용된 역할 적용 범위를 기록한다. 합의되지 않은 수용 메시지를 사용자 대신 쓰지 않는다. 선택 확인·지침 준비 비용도 해당 방식에 포함한다.
4. **독립 문맥:** D/R은 별도 논리 요청·상태·native 측정 구간을 사용한다. 다른 방식의 답을 인계하지 않는다. RP-02는 각 방식 안에서만 첫 답 뒤에 두 번째 입력을 전달하고 두 턴 전체를 평가한다. 같은 AI가 이전 답을 봤다면 비공개 실행 기록에 그 노출을 밝힌다.
5. **버전 고정:** 사례 파일을 비공개 기준 사본으로 복사해 SHA-256을 고정한다. 상대 링크의 기준은 원래 사례 파일의 디렉터리임을 함께 전달하거나 필요한 자료를 같은 구조로 보관한다. AGENTS·짧은 라우팅/튜터 지침·실제 사용한 역할/검사 코드·설정·참조한 프로젝트 계약도 미커밋 변경을 포함한 파일 해시로 기록한다. 이후 바뀐 파일에 이전 판정을 적용하지 않는다.
6. **순서·조건 기록:** 첫 실행 전에 D→R 또는 R→D를 정하고 이유를 남긴다. 같은 시각의 공식 자료 사본/확인 기록을 사용할 수 있으면 양쪽에 동일하게 제공한다. 캐시·검색·네트워크·권한·환경 차이를 감추지 않는다. 한 쌍에서 차이가 보여도 반복 이득으로 일반화하지 않는다.

현재 AI의 동작·정책 경로가 같아 R에서도 바로 답할 수 있다. 그때 역할이나 worker를 억지로 만들어 차이를 키우지 않는다. 작은 요청에서는 추가 절차가 없는 결과 자체도 중요한 관측이다.

## 수집과 평가

- 각 방식의 본작업·추천·선택·인계·통합·검증·재작업·최종 보고를 [여덟 단계](../../runtime/routing-comparison.md#단계별-수집-범위와-품질)에 연결한다. 한 native 턴에 여러 단계가 있으면 한 번만 합산하며 임의 비율로 나누지 않는다.
- 실제로 없던 단계만 `not_applicable`, 실행했지만 수집 못 한 단계는 `missing`이다. 준비 시점의 예상 범위를 측정 완료인 `included`로 쓰지 않는다. 공식 원본을 못 받으면 미측정으로 멈추며 다른 실행/세션을 탐색해 채우지 않는다.
- 실행 기록에는 실제 입력/제어·결과·제안/선택·요청/적용/관측 프로필·수집 파일 참조·누락·실행 순서·시작/종료 시각이 제공됐다면 그 근거를 남긴다. 이 준비 묶음 자체는 실제 시간이나 요금을 만들지 않는다. 근거가 확보되면 [선택적인 시간·단가 추정 v2](../../runtime/routing-metrics.md)를 사용하고, 없으면 null/부분 측정을 유지한다.
- [평가 절차](evaluation.md)와 [기록 양식](../../templates/routing-evaluation.md)으로 먼저 품질을 판정한다. 독립 평가를 위해 새 모델을 실행할 경우에도 실행값·한도를 확정하고 해당 비용을 기록한다. 두 방식을 한 평가 턴에서 읽고 비용을 임의로 반으로 나누지 않는다.
- 사례 준비·공통 평가 설계·두 결과의 합산 보고는 실험 운영비로 별도 기록한다. 각 방식의 요청을 완성하는 데 든 검증·재작업 비용은 해당 방식에 포함한다. 어떤 비용을 제외했는지 평가 근거에 공개하며, 누락된 업무 단계를 전체 수집으로 주장하지 않는다.
- 품질 판정과 실제 수집이 끝나면 [기존 비교 양식](../../templates/routing-comparison.json)을 채운다. `criteria`는 고정한 해당 사례 사본, `quality.evidence`는 각 방식의 완성된 평가 기록, `measurements`는 실제 수집 파일의 `{path, sha256}`이다. 빈 양식·가짜 해시·기능 테스트 숫자를 실측으로 넣지 않는다.

공개 저장소에는 이 가상 자료와 빈 양식만 둔다. 실제 응답·운영 기록·블라인드 라벨 대응표·기준 사본·해시 목록·평가·manifest·stdout은 Git/대상 프로젝트 밖의 비공개 폴더 0700·파일 0600에 보관한다. 현재 AI가 경로와 구조화 입력을 준비하며 사용자에게 JSON 작성을 요구하지 않는다.

## 실행 전 준비 완료와 실제 평가 완료의 구분

준비 완료는 사례·기준·양식·운영 안내와 RP-03 검사 코드가 확인됐다는 뜻이다. 독립 평가·공정한 실행 조건·모든 단계의 실제 수집·사용자 이해도를 증명하지 않는다. 준비한 사례는 현재 작성 AI가 이미 알고 있으므로 이후 실행을 블라인드 미공개 시험이라고 부르지 않는다.

비교 결과는 [단일 쌍 비교 도구](../../runtime/routing-comparison.md)의 판정을 따른다. 품질 실패나 누락이 있으면 절감 성공으로 채택하지 않는다. 반복 비교 후보가 되어도 자동화 허용은 false이며, 실제 이득과 사용자 허용 범위가 확인된 유형만 다음 단계로 검토한다.

- [짧은 운영 안내](../../runtime/routing-quickstart.md)
- [현재 개발 상태와 남은 일](../../learning/development.md)
