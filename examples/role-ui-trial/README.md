# 역할 스킬의 브라우저 시험

실제 제품을 수정하기 전에 역할별 점검·수정·재검증 방법을 확인하는 가상 업무 화면이다. Web 브라우저와 loopback HTTP API를 사용하며 Dooit·React Native·운영 API 검증이 아니다. 외부 패키지·분석 서비스·실제 사용자 데이터는 사용하지 않는다.

```sh
python3 scripts/role_ui_trial.py --port 0 --ready-file local/role-skills/browser-trial-server.json
```

ready 파일의 URL을 해당 환경의 공식 브라우저로 연다. 이 파일은 로컬 경로·포트를 포함할 수 있어 Git에 넣지 않는다. 서버는 `127.0.0.1`에만 바인딩하고 아래 정적 파일과 시험 API만 제공한다. 서버 종료는 시작한 터미널의 Ctrl+C를 사용한다.

기존 ready 파일은 덮어쓰지 않으므로 실행별로 새 경로를 지정한다. API 회귀 검사는 `python3 -m unittest discover -s tests -p 'test_role_ui_trial.py' -v`이며, 브라우저 화면 검사를 대신하지 않는다.

## 기준과 비교

화면의 역할·문구·팔레트·데이터는 그대로 유지한다. `revision=baseline`은 의도한 회귀가 있는 기준본이고 `revision=fixed`는 관련 부분을 고친 비교본이다. 이미 알고 만든 결함의 재현 시험이며 미지의 제품 결함 발견률이나 스킬의 인과적 품질 향상 측정은 아니다. 같은 URL의 revision만 바꾸어 데이터·환경을 맞춘다.

- `data=demo|worst|empty|one|huge`: 같은 데이터 계약을 사용하는 fixture. huge는 1,000개 중 최대 20개씩 더 표시한다.
- `theme=light|dark`, `dir=ltr|rtl`, `text=normal|large`: 지원하는 화면 조건. large는 루트 글자 크기를 200%로 높이며 브라우저 자체 확대와 구분한다.
- `revision=baseline|fixed`: 수정 전후. 기본은 fixed다.

시험 도구 영역은 이 전용 화면 안에만 존재한다. 입력·fixture 이름은 모두 가상 값이다. 제목은 HTML maxlength와 같은 UTF-16 기준 1~120단위, 이름은 최대 80자, 이메일은 최대 254자, 역할은 선택 값이다. 서버와 클라이언트의 제목 제한을 맞추며, 빠진 역할은 생략한다. 목록 데이터에 HTML처럼 보이는 문자열도 텍스트로 표시한다.

## 먼저 고정할 완료 기준

| ID | 관찰 가능한 기준 |
| --- | --- |
| UI-01 | 320·390·1280 CSS px에서 긴 제목·이메일을 읽을 수 있고 가로 넘침 없이 행 동작에 접근 가능 |
| UI-02 | API 실패 뒤 입력을 유지하고 안내·재시도로 저장 가능. 오류는 색 외의 문구로 제공 |
| UI-03 | 저장 중 연속 활성화해도 한 요청만 전송. API의 요청/저장 개수를 실제 응답으로 확인 |
| UI-04 | 목록 더 보기/접기 후 같은 버튼에 키보드 초점 유지. Enter·Tab으로 핵심 흐름 조작 가능 |
| UI-05 | empty/one/worst/huge, RTL·dark·200% 루트 글자 조건을 실제 렌더링하고 URL 상태가 reload 후 유지 |
| UI-06 | 저장된 결과가 조회 API와 재조회 후 일치. 서버 재시작 뒤 영구 보존은 요구하지 않음 |

baseline은 UI-01의 flex 최소 폭, UI-02의 입력 보존, UI-03의 중복 전송, UI-04의 사라지는 초점 대상 문제를 의도적으로 포함한다. 고정된 대비 조건에서 먼저 재현하고 fixed를 같은 조건으로 다시 확인한다. baseline 결함을 제품의 결함이라고 보고하지 않는다.

## 역할·스킬과 증거

디자이너 관점에서는 위 기준과 기존 화면을 유지한다. 프론트엔드는 Web 지침·break-ui·Impeccable harden의 관련 부분으로 구현을 확인하고, 검증자는 원래 기준에 실제 화면·상호작용·HTTP 응답을 대응시킨다. 한 에이전트가 모두 수행했다면 독립 검토라고 쓰지 않는다.

브라우저는 [환경 가이드](../../runtime/environments/README.md)를 따른다. DOM 측정은 읽기 전용이며 입력·클릭·키보드는 실제 브라우저 동작으로 수행한다. 소스의 문자열 존재나 만들어낸 좌표를 화면 통과 증거로 사용하지 않는다. 캡처·명령·측정·source hash·AC별 판정은 `local/role-skills/trials/<run>/`에 보관한다. 정기 출처 점검의 `runs/`와 분리해 비교 기준선을 섞지 않는다. 가상 화면이라도 실행 환경의 개인 경로·ID를 공개 기록에 섞지 않는다.

실제 시험에서 전체 가로 폭이 정상이더라도 200% 글자의 텍스트 칸이 0px이 될 수 있었다. fixed는 큰 글자에서 행을 세로로 배치한다. 저장 버튼 잠금으로 자동 이탈한 초점은, 사용자가 다른 컨트롤로 옮기지 않은 경우 원래 버튼으로 돌린다. 이 추가 발견은 처음 정한 회귀 네 개와 구분해 기록한다.

Orca의 페이지 이동·reload 뒤에는 viewport를 다시 설정하고 실제 `documentElement.clientWidth`를 기대값과 대조한다. 캡처 파일명이나 설정 명령의 성공만으로 같은 화면 크기라고 판단하지 않는다. 문서 폭 검사도 텍스트 가독성·글리프 겹침의 통과를 대신하지 않으므로 목록 아래까지 실제 화면을 확인한다.

이 시험만으로 스킬 전체를 active로 승격하지 않는다. Web 엔진 하나의 결과를 native·다른 브라우저·실기기·스크린리더·모든 스킬 규칙 통과로 확대하지 않는다.
