# 독자에게 제공할 가상 작업

사용 자료: 이 파일, [시험 README](README.md), README가 연결한 최종 절차·양식. 작성자의 시험 결과나 구현·테스트 소스는 제공하지 않는다. 이는 독립 검토자가 나중에 수행할 입력이며, 작성자가 독립 시험을 했다는 기록은 아니다.

독자는 Python과 shell 명령을 읽을 수 있고 저장소 checkout이 있다. 네트워크·설치·실행은 권한이 있을 때만 직접 수행하고, 수행하지 않았다면 명령 계획과 미수행을 구분한다. 실제 서비스·계정·정책 변경을 하지 않는다.

목표: 가상 문서 세 파일을 안전하게 제안·검토·검사·반영하고, 실패와 근거 변경 후 다음 행동을 문서만으로 결정한다.

1. 필요한 dependency를 프로젝트 밖에 설치하고 trial을 실행하려면 어떤 명령과 경로가 필요한가?
2. 기존 파일 변경 제안에서 독립 검토자가 받아야 할 정확한 자료와 review 필드는 무엇인가?
3. 현재 코드가 삭제 204, 설계가 200이면 ADR에 무엇을 확정할 수 있는가?
4. 소스 hash가 바뀌었을 때 재검토할 문서와 기존 제안·검토를 어떻게 처리하는가?
5. complete=false, applied에 파일 하나, backups에 두 파일, incomplete_backups에 별도 경로가 있다면 무엇을 확인하고 어떻게 복구를 준비하는가?
6. 오탈자만 수정하는 경우 독자 시험과 권한 확인은 어떻게 처리하는가?

[독자 시험 양식](../../templates/document-reader-review.md)에 실제 답·수행 결과·빠진 단계·추가 자료 사용을 기록한다. 정답이나 작성자 결론을 먼저 요청하지 않는다.
